## 1. 设计边界与统一页面框架

采用 Vue 3、TypeScript、Vue Router、Pinia、Element Plus；具体文件目录由 06 确定。路由是浏览器页面地址，与 /api/v1 接口路径分别管理，不能直接把数据库表映射成页面。

PC 页面采用顶部账户区、左侧业务导航、主内容区、必要的详情抽屉或确认对话框。顶部显示站点名称、通知入口、当前昵称及账户菜单；运行中的任务显示持久专注条。所有位置统一使用服务端返回的状态和统计。

左侧导航为：今日、目标、任务、周计划、日计划、待处理、习惯、历史、通知。账户菜单提供个人资料、修改密码、退出。管理员增加“账户管理”，超级管理员额外提供“系统配置”。普通用户不出现交流、社区、私信、AI 助手、会员、积分、质量评分或数据导出入口。

### 1.3 所有数据区域适用的状态矩阵

| 状态编号 | 触发 | 页面表现 | 允许动作 |
|---|---|---|---|
| UI-STATE-01 加载 | 首次或切换筛选查询未返回 | 骨架或加载文本；新筛选下不把旧结果冒充新结果 | 取消无副作用查询；不提交依赖未知版本的写入 |
| UI-STATE-02 空 | 成功返回空页或空视图 | 说明当前范围无数据，并提供合法创建/规划入口 | 仅提供当前状态允许的动作 |
| UI-STATE-03 加载失败 | 请求明确失败 | 显示失败和重试，不能显示“无任务”或统计值 0 | 重试同一读取；已有可靠快照明确标注未刷新 |
| UI-STATE-04 提交中 | 写请求尚未确定 | 锁定本次提交控件，显示处理中；其他不相关查看可继续 | 不生成第二个意图双击提交 |
| UI-STATE-05 已保存 | 服务端提交成功 | 更新权威对象/版本，再刷新受影响清单和概览 | 后续操作使用新版本 |
| UI-STATE-06 版本或状态冲突 | VERSION_CONFLICT / STATE_CONFLICT 等 | 显示当前状态及原因，保留未提交输入供比较 | 刷新后由用户决定新操作，不自动覆盖 |
| UI-STATE-07 结果待核实 | RESULT_UNKNOWN 或提交后响应丢失 | 明确“结果待确认”；不能显示确定失败或重复添加条目 | 查当前对象或原键核实；不换键盲重发 |
| UI-STATE-08 会话失效 | AUTH_REQUIRED 或当前账户被撤销 | 立即遮蔽受保护数据，清理控制许可与敏感缓存 | 重新登录；不依赖失效凭据自动执行 |
| UI-STATE-09 无权或不可见 | FORBIDDEN / NOT_FOUND | 友好拒绝或对象不可用，不显示他人信息 | 返回本人列表；不提供绕过入口 |
| UI-STATE-10 历史只读 | 过去计划、固定完成或删除保留身份 | 文本说明只读原因；保留查看历史能力 | 不展示过去编辑、补打卡或撤销任务完成 |
| UI-STATE-11 被执行阻塞 | UNFINISHED_EXECUTION | 列出全部 RUNNING/PAUSED 记录 | 逐个复用 FOCUS 结束；或取消原操作 |
| UI-STATE-12 请求受限 | RATE_LIMITED、请求过大、服务恢复中 | 显示等待/范围调整/维护提示，保留当前合法输入 | 按服务端时限重试；不绕过限制 |

空状态和加载失败独立；无任务不能遮住当天仍应完成的习惯。成功后的概览刷新失败显示“操作已保存，展示尚未更新”，不撤销已确认事实。

## 2. PAGE-001 登录

**布局文字原型：** 中央登录卡片；顶部为站点名，下方用户名、密码、滑动验证、登录按钮，底部公开注册入口及锁定等待提示。

| 控件 | 字段与校验 | 提交或展示要求 |
|---|---|---|
| 用户名 | username；1–30 字符，英文字母、汉字或数字 | 展示保留输入，登录匹配按大小写口径；不询问邮箱 |
| 密码 | password；登录校验非空且不超过 50 码点；新密码 8–50 规则用于注册/改密 | 非空但错误的短密码仍由服务端凭据校验，不借前端误用新密码规则改变失败计数；不 trim、不缓存到页面外 |
| 滑动验证 | 本次挑战与验证结果 | 用途为 LOGIN；失败只拒绝本次，不自行增加凭据失败次数 |
| 登录 | 提交一个稳定意图 | 成功后同步当前资料、时区及执行状态，再进入今日 |
| 锁定提示 | 服务端剩余等待 | 本地显示倒数只作提示，到期仍由服务端决定是否解锁 |
| 注册入口 | 公开设置是否允许注册 | 关闭时显示已关闭；不能仅靠隐藏按钮阻止提交 |

**接口关联：** PUB-001 公开站点、AUTH-001 CSRF、AUTH-002/003 挑战与验证、AUTH-005 登录、AUTH-006 当前身份。登录 Body 为 username、password、captchaChallengeId、captchaVerificationToken；不提交 zoneId 或 confirmPassword。成功使用 SelfSession.csrf 和 account 新快照。

拼图控件按 AUTH-002 返回的原图尺寸显示背景和透明拼图，纵向用 pieceTop；缩放后将拖动水平位移换算成原图 offsetX 提交 AUTH-003。验证成功后将 challengeId/verificationToken 留内存；到期或失败清除并重新取图，不能靠“拖到末尾”本地判通过。取图、验证、登录是三个独立意图，各自重试保持各自键。

**状态与失败：** 用户不存在或密码错误一律“用户名或密码错误”；锁定与限流分别展示；滑动失败保留非秘密字段并更换合法挑战。登录成功前不预加载个人正文。登录响应不确定使用原意图核实，不持续重放密码。

登录响应丢失先 AUTH-006 确认浏览器是否已有有效会话；已登录则按权威快照继续，不能重建第二登录。没有可用会话时按 03 核实原意图，确需重新认证则新取挑战并由用户重新提交，不从长期去重结果恢复旧 Cookie 或登录秘密。

## 3. PAGE-002 注册

**布局文字原型：** 注册卡片包含用户名、昵称、密码、确认密码、滑动验证及注册按钮。旁边用短文本说明用户名用于登录且唯一，昵称可重复。

| 控件 | 字段与校验 | 特殊规则 |
|---|---|---|
| 用户名 | username 必填，规则与登录一致 | 服务端最终判断唯一；不做冷静期提示 |
| 昵称 | nickname 可选 | 未填由服务端取注册时用户名，后续独立修改 |
| 密码与确认 | password、confirmPassword；8–50 码点且一致 | 强度显示弱/低/高/强；合规弱密码也允许提交 |
| 时区 | zoneId；自动识别的合法 IANA 名称；失败时显示选择器 | 不采集地理定位、语言或服务器时区代替 |
| 滑动验证 | REGISTER 用途 | 与 LOGIN 的挑战不可混用 |
| 注册 | 创建普通用户 | 无角色选择、手机号、邮箱、头像或社区信息 |

**接口关联：** PUB-001 公开设置、PUB-002 合法时区集合、AUTH-001 CSRF、AUTH-002/003 注册挑战与验证、AUTH-004 注册。提交 username、password、confirmPassword、zoneId、captchaChallengeId、captchaVerificationToken；未填昵称时省略 nickname，不提交 null。成功以 loginRequired=true 提示并转登录，不假定自动登录。

**状态与失败：** 用户名重复定位该字段；注册已关闭及时提示；即使页面早已打开，服务端关闭注册后仍不得创建账户。注册提交失败保留用户名/昵称，密码和挑战只在当前受控内存中按失败类型处理。

## 4. PAGE-003 今日看板

**布局文字原型：** 顶部为今天日期、时区与目标概览；主区第一块是唯一运行任务及暂停队列；下方分列“今日指定日期任务”“本周未指定日期任务”；右侧/下方是今日习惯、待处理入口和完成确认通知。

| 区域 | 显示字段 | 动作 |
|---|---|---|
| 目标概览 | 已开始未结束未归档目标、当前 C/N、真实投入 | 进入 PAGE-005；未来目标不混入此区 |
| 唯一计时任务 | 任务名、本次确认值/实时估计、累计、执行状态 | 打开 PAGE-012；控制页可暂停/结束，观察页不替它保活 |
| 暂停队列 | 任务名、暂停原因、本次已有投入 | 在资格合法时显式继续或先改期，不自动逐个恢复 |
| 今日任务 | name、priority、status、completionCriteria、estimatedSeconds、确认投入 | 查看、开始/继续、完成、改期；使用服务端 availability |
| 本周无日期任务 | 同任务卡片，显示“本周内完成” | 可以本周直接执行，不强制添加今日 |
| 今日习惯 | 名称、条件、类别、完成勾选 | 只勾选今天应执行项，不提供昨天补记 |
| 待处理与通知 | 唯一任务待处理条目、目标确认轮次提示 | PAGE-011 或目标确认，不能自动迁到今天 |

**接口关联：** API-DASH-001 概览；API-DASH-002 的 TODAY_TASKS/WEEK_FLEXIBLE/PENDING/GOALS 四种 view 各自分页；API-DASH-003 今日习惯；FOCUS-001 当前执行、FOCUS-011 暂停与未结束清单；任务信息和改期调用 API-TASK-003/007，完成调用 API-TASK-005，习惯勾选 HABIT-010，目标确认调用 API-GOAL-007。

**空与异常：** 任务为空展示“暂无任务，可先规划”，习惯区继续独立显示；某区加载失败显示重试，不能让其他成功区一起变为 0。恢复可见/重连先认证同步，再开放状态动作。

**提交后同步：** 任务迁移刷新旧日、新日、周清单及运行区；完成任务成功后从待执行区移除，保留已完成入口；达到 100% 显示等待用户确认，目标不会自动消失。

## 5. PAGE-004 目标列表

**布局文字原型：** 顶部“新建目标”；范围标签为进行中、待开始、已完成、归档；下方名称搜索、分页目标卡片。

每卡片显示 name、startDate、expectedEndDate、state、归档标记、progress、confirmedFocusMicroseconds。无任务显示“暂无任务，可先规划”，不能显示 100%。待开始卡片显示“将于某日显示”；已完成与已归档可以同时展示。

**目标表单：** name、description、completionCriteria、startDate、expectedEndDate 均必填；日期关系校验；不输入任务总数、实际耗时或进度。

**接口关联：** API-GOAL-001/002；详情 PAGE-005。范围切换重置游标；GoalView 的版本以字符串保存。

**动作：** 新建成功进入详情；归档先确认影响并调用 GOAL-005；恢复调用 GOAL-006；已完成未归档目标可 GOAL-008 重开。没有删除目标按钮。

**状态：** 列表空、筛选空和失败分别提示；提交后显示服务端最终状态及预计日期，不能用前端自算日期覆盖自动延期结果。

## 6. PAGE-005 目标详情与阶段任务拆解

**布局文字原型：** 上部目标信息、日期、C/N、累计投入、编辑/归档/结束等操作；中部为手动排序的阶段卡片；每阶段内显示任务分页和创建入口；右侧或抽屉显示选中阶段详情。

### 6.1 目标区

显示 GoalDetailView 的名称、描述、条件、日期、业务状态、归档状态、当前进度和未结束执行数量。目标预计日期已被系统延期时，显示最终日期并提供历史节点入口，不长期悬挂“目标已逾期”标签。

编辑复用 PAGE-004 的目标表单，通过 GOAL-004 提交 expectedVersion。归档通过 GOAL-005；恢复 GOAL-006；结束 GOAL-007；重开 GOAL-008；历史进入 PAGE-006。

结束对话框区分：

- 全任务完成确认：显示当前 C/N 和轮次，提交 ALL_TASKS_CONFIRMED。
- 用户主动结束：显示未完成数，说明不会补完成子任务，提交 USER_ENDED。

有任何未结束执行先打开全局处理器；全部结束后刷新目标版本，再让用户确认结束。归档不能自动替用户结束执行。

### 6.2 阶段区与表单

| 内容 | 字段/规则 | 接口 |
|---|---|---|
| 阶段列表 | name、description、status、progress、投入、sortOrder | STAGE-002、003 |
| 创建 | name、description 必填；completionCriteria、startDate、endDate 可空 | STAGE-001 |
| 编辑 | 同创建字段，带阶段 expectedVersion | STAGE-004 |
| 手动排序 | 当前全部有效阶段身份，不含已删除历史 | STAGE-009 |
| 暂停 | 显示会暂停运行任务、保留计划/进度 | STAGE-005 |
| 恢复 | 明确不自动计时 | STAGE-006 |
| 完成 | 当前有效未完成任务数为 0，空阶段也可确认 | STAGE-007 |
| 重开 | 保留旧完成节点和已完成任务 | STAGE-008 |

| 当前目标进度 | 若展示则明确“当前有效任务”，与历史完成数分开 |
| 习惯完成 | 完成数与应执行数均来自日结果；今天未结算时有提示 |
| 周日历史 | PLAN-012，进入对应只读计划；旧安排迁走也能看到真实投入摘要 |
| 精确区间 | FOCUS 历史接口，展示真实任务和当时周日归属 |
| 目标结束历史 | GOAL-010 固定快照，不用当前任务数重算 |

支持完整三年及更早历史范围的一致汇总与历史分页，不新增日期范围硬上限。范围变化重置游标，卡片与列表标注口径，不从各页条数累加伪造总计，也不把多次变化快照简单拼成精确总数。

**接口关联：** HISTORY-001 一致统计、HISTORY-002 历史记录分页；04 的 GOAL-009/010、TASK-008、PLAN-012。空、失败、部分未刷新分开；有尚未完成的新统计时不能用上个范围的数字冒充。

## 17. PAGE-016 站内通知

**布局文字原型：** 未读/全部筛选；通知列表显示目标名、条件提示、时间、已读/处理/失效状态；每项提供查看目标和合法动作。

| 动作 | 要求 |
|---|---|
| 阅读 | 只改变已读状态，不结束目标 |
| 确认结束目标 | 获取最新 GoalDetailView，确认当前版本和 conditionRound，再 GOAL-007 |
| 继续推进 | 使用 05 通知处理接口记录用户选择；目标仍 ACTIVE，任务完成事实不撤销 |
| 旧条件变化 | 显示条件已变化，禁用过期确认；允许查看当前目标 |
| 已归档/已结束 | 显示动作失效原因；不把旧消息当恢复或重开指令 |

**接口关联：** NOTICE-001 列表、002 阅读、003 继续推进、004 详情；确认目标统一复用 API-GOAL-007，提交 expectedVersion、endType=ALL_TASKS_CONFIRMED、conditionRound、confirmed=true，不定义第二条通知完成目标接口。

通知投递失败不能使已完成任务回退。刷新不能重复创建同轮消息。离线通知登录后可见，不新增用户私信、短信或邮件能力。

## 18. PAGE-017 个人资料

**布局文字原型：** 用户名、昵称编辑卡；当前业务时区和待生效提示；修改密码与退出链接。

用户名可随时修改但必须合规唯一；昵称可重复，后续不会随用户名自动变化。保存提交当前版本，成功后顶部同步昵称；旧用户名不再作为当前账户登录名，现有会话仍关联同一 userId。

时区默认自动匹配设备有效 IANA 值。时区变化显示“将在当前日结束后生效”；尚未识别有效时区时展示合法选择器，日期相关写入不可擅用服务器地区。历史日期不整体重排，进行中的执行按规则暂停。

**接口关联：** AUTH-006 查询 SelfSession.account，AUTH-007 保存 expectedVersion 和已修改的 username/nickname；AUTH-010 用 detectedZoneId、expectedVersion 同步设备时区；候选时区从 PUB-002 取得。显示 account.timeZone.activeZoneId、pendingZoneId、pendingEffectiveAt；不提交 effectiveAt、ownerId 或 role。页面没有头像、签名、手机号、邮箱、冷静期或普通用户自助重置密码入口。

**失败：** 用户名冲突定位字段；版本冲突保留本人输入，刷新后比较。账户被撤销立即遮蔽资料和其他页面正文，不只更新导航昵称。

## 19. PAGE-018 修改密码与退出处理

**修改密码表单：** currentPassword 原密码、newPassword 新密码、confirmPassword 确认新密码；带当前 account.version 作为 expectedVersion，以及用户确认后的 confirmed=true。新密码 8–50 码点、与原密码不同、两次一致；强度提示不是额外准入门槛。

提交前或收到 UNFINISHED_EXECUTION 后，列出全部未结束执行。用户可以取消回到系统；选择逐个结束后刷新状态再提交密码修改。不能把暂停视为结束，也不能为了改密而静默完成任务。

改密成功使全部既有会话失效，当前页清理秘密与个人缓存并转登录。响应丢失不因 AUTH-006 返回未登录就断言密码已改成功，因为其他撤销也可使会话失效；显示待核实并按 03 使用新凭据正常登录核实，建立同一账户的新有效身份后可用 API-COMMON-001 查询原 API-AUTH-008 意图安全结果。不重新自动提交同一改密，不重放旧退出请求撤销新会话，也不新增自助找回流程。

**正常退出：** 从任何页面点退出同样先处理全部未结束执行；全部结束后提交 AUTH-009，Body 只有 confirmed=true、不提交账户 expectedVersion。退出响应丢失用 AUTH-006 核实，当前确已未登录则按退出状态清理，不恢复旧身份。再次需要匿名提交时先 AUTH-001 取得当前匿名 CSRF。直接关闭进程无法被可靠阻止，重登显示服务端暂停结果；不声称网页能强制拦住操作系统退出。

**接口关联：** AUTH-008 改密、009 退出、006 身份；FOCUS-011 分页取全未结束执行、005 逐个结束。03 错误若仅给数量，处理器先补查 FOCUS-011 全部分页；最终账户请求仍持锁重查，不能凭前端清空列表绕过。

## 20. PAGE-019 后台账户管理

**布局文字原型：** 顶部账户数量卡片，区分未删除 USER、ADMIN、已删除等允许统计；下方用户名/角色/状态筛选和分页账户表；新增/编辑抽屉与禁用/删除确认。

| 操作者 | 可见与可用范围 |
|---|---|
| ADMIN | 仅普通 USER 的规定管理操作，不显示管理员/超级管理员编辑入口 |
| SUPER_ADMIN | 普通用户及管理员的规定管理；角色修改只在 USER/ADMIN 允许范围 |
| USER | 菜单隐藏，直接路由被拒绝；接口仍必须校验 |

账户表仅显示安全资料：用户名、昵称、角色、启用/禁用、删除标记及允许的账户数量信息；没有普通用户目标、任务、习惯正文或“代替执行”按钮。

创建表单为 username、可省略 nickname、initialPassword、confirmPassword、role、initialZoneId；角色默认 USER，合法初始时区明确选择，不擅自把操作者时区当成目标用户地区。编辑提交 expectedVersion，以及已改 username、nickname、status、允许的 role；不显示密码原文/哈希，不增加任意重置密码。

禁用/删除提示会停止登录并暂停可信执行，历史保留；管理员不必等待目标用户主动结束。最后一个可用超级管理员保护由服务端判定，不能只靠前端禁用一行按钮。

**接口关联：** ADMIN-001 人数、002 列表、003 当前安全详情、004 新建、005 修改、006 删除、007 撤销会话。列表参数是 role、status、deletion=ACTIVE/DELETED/ALL、q 及公共分页；ADMIN 的统计 administrators=null 表示无权，不画为 0。

显式“撤销全部会话”通过 ADMIN-007，提交目标 expectedVersion、confirmed=true；提示会按可信点暂停并使旧会话失效，不结束任务、不改密码。解除 DISABLED 是 ADMIN-005 的 status=ENABLED，不恢复已删除账户或旧会话。

必要审计失败时不能提示管理成功；版本或角色变化后刷新权限。后台操作成功后不把目标账户的数据装入当前操作者 Pinia。

## 21. PAGE-020 后台系统配置

**布局文字原型：** 仅两个配置项、当前值及保存按钮，旁边说明立即生效。

| 控件 | 配置与校验 |
|---|---|
| 站点显示名称 | CFG-001；1–30 个可见字符，不能全空白 |
| 是否开放注册 | CFG-002；开放/关闭二选一 |

SUPER_ADMIN 可读写；ADMIN/USER 均无后台配置权限。保存成功后更新后续页面站点名/注册入口；关闭注册不使已有账户退出，也不阻止合规管理员新增账户。

**接口关联：** ADMIN-008 读取固定两项；ADMIN-009 提交 items 数组，每项为 key、value、expectedVersion。CFG-001 对应 SITE_NAME 且 value 为 string，CFG-002 对应 REGISTRATION_OPEN 且 value 为 boolean，不能提交字符串 "true"。两项同时保存任一冲突则整批不提交，前端不得提示另一半已成功。站点公开展示通过 PUB-001 取得，不能公开完整后台配置。

不增加计时许可窗、密码成本、连接池、备份、延期系数、任意配置键或角色策略控件。未知键被服务端拒绝；审计和版本冲突按统一状态处理。

## 22. 关键跨页面交互的固定步骤

### FLOW-UI-01 创建与执行闭环

PAGE-004 创建目标 → PAGE-005 创建阶段和任务 → PAGE-009 取得周身份并安排 → 需要明确日期时 PAGE-010 → PAGE-012 执行、暂停、继续、结束 → PAGE-008 确认完成 → PAGE-003/005 查看进度与投入 → PAGE-016 确认目标结束。

每次写入成功后保存新版本，计数与进度由服务端返回。没有计划不能执行；无日期周任务可以跳过日安排；结束一次执行不能跳过任务完成确认。

### FLOW-UI-02 改期与历史

在任务详情或待处理页选择新去向 → 显示运行时暂停说明 → 提交同一个 TASK-007 → 成功后更新任务/新旧清单 → 原日安排项移除 → 真实旧日投入仍在历史可见。

未取得成功结果前不在新旧两边各显示一个确认任务，也不能删除真实区间。未知结果先核实，不能自动建新任务解决。

### FLOW-UI-03 归档或删除遇到未结束执行

提交前说明影响 → 服务端若返回 UNFINISHED_EXECUTION，展示执行总数和首批提示，按FOCUS-011对应scope分页取全 → 用户可取消，或逐个调用 FOCUS 结束 → 全部处理成功后刷新原目标/计划/任务版本 → 再次展示确认并提交新意图。

目标归档、任务/计划删除不会自动结束；管理员撤销走后台用例，其自动暂停与普通清理流程不同。没有当前运行条不意味着没有暂停中的未结束执行。

### FLOW-UI-04 成功提交后刷新失败

保持“已保存”结果和返回的新对象 → 概览区域标“尚未更新” → 使用查询重试刷新 → 不再用新键重新执行刚成功的写操作。完成任务不能因看板失败回到未完成。

### FLOW-UI-05 结果未知

保持原 Idempotency-Key、原字段和目标身份 → 显示结果待核实，禁用重复确认 → 查询权威对象或原键核实 → 只有确定结果后才允许用户形成下一次意图。去重期限已过的意图不得自动盲重放。

已认证的本人操作可调用 API-COMMON-001：GET /api/v1/operations/{idempotencyKey}?operation=原API编号；它只返回本人意图的安全结果，不重执行原请求、不签发秘密。404 OPERATION_RESULT_NOT_FOUND 表示未知或已过期，不代表原操作一定没有发生；保留提示，通过对象、历史或人工判断进一步核实。匿名登录/注册不能用它查询某用户结果；改密或退出使旧会话失效后，先按 AUTH-006 判断，再经正常登录恢复合法身份后查询旧意图，不用旧命令撤销后来新建的会话。

### FLOW-UI-06 切换账户、重连与权限撤销

立即遮蔽旧个人内容和停止旧控制页的确认 → 校验当前身份/安全代次 → 同步当前执行与页面快照 → 验证本次响应仍属于当前账户/页面请求代次 → 再显示正文及开放动作。

旧账户的迟到响应必须丢弃；不能因浏览器返回历史而显示上一账户的表单、任务或执行许可。

## 23. 可用性、可访问性与原型验收

- 表单标签、必填、时间单位和服务端错误明确；日期选择器显示当地日期，绝对时间展示时保留可理解时区。
- 用户名称、描述、条件、通知正文和错误信息按安全文本展示，不把输入当成可执行 HTML；浏览器控制台、分析日志和截图反馈不记录密码或执行许可。
- 状态不只用颜色表达；运行、暂停、已完成、归档、删除保留和待处理均有文字及可访问名称。
- 全部核心表单、完成勾选、暂停/继续、确认对话框可键盘操作；对话框关闭后焦点返回触发控件。
- 排序提供上下移动，不能强迫只能拖动；保存前后顺序可核对，失败恢复原序。
- 长列表分页，不一次渲染三年历史；排序只加载当前队列的必要完整成员，不能因此下载全账户。
- 全局反馈使用稳定语义：已保存、执行已结束但任务未完成、结果待核实、历史保留，避免所有成功都说“已完成”。
- 有关确认、刷新与通知的 5 秒目标、专注确认时间等以 05 和 NFR 为验证依据；本设计不宣称浏览器后台或网络故障时已经实测通过。

原型阶段必须走完 PAGE-001～020 的合法路径及 UI-STATE-01～12。只画“正常有数据”页面不算完成；至少逐页核对加载、空、失败、权限、只读、冲突与未知结果是否有明确表达。

页面实现与联调按06、08执行；当前验证状态为NOT_VERIFIED。

## 24. 页面与需求分析的统一使用方式

读[10需求全景](10-MVP需求分析与业务全景.md)确定角色与业务目的，再按本册文字原型落实页面；每个按钮对应03～05某个现行接口。文字原型用于说明待实现页面，实际界面需在前端阶段验证。

| 页面动作 | 产品交互 | 对应设计链 |
|---|---|---|
| 创建/编辑 | 原型显示字段与约束，提交时保留单个意图，成功使用服务端版本 | 本册字段→对应接口Request DTO→业务流程→01存储 |
| 完成/删除/归档 | 明确不可逆或历史保留影响；存在执行阻塞时先处理 | 生命周期接口→标准阻塞提示→FOCUS逐个结束→刷新版本重新确认 |
| 执行与接管 | 明确控制页/观察页，接管由用户触发，页面倒数不决定真实耗时 | 05控制协议→11异常暂停→服务端状态回显 |
| 周日到期/目标延期 | 读服务端补偿后的状态，不在浏览器自行增加日期或复制任务 | 11系统用例→04查询→本册只读/待处理界面 |
| 今日习惯完成 | 只提交当日合法完成，完成后不提供撤销按钮 | 05HABIT-010→habit_day真实完成→11日结→历史 |
| 空、失败、未知 | 三种不同反馈，数据获取失败不能显示0或空集合 | 02错误/幂等→本册UI-STATE→08验证 |

前端联调记录按“PAGE编号、按钮、API编号、请求关键字段、HTTP/code、服务端事实、界面变化”留证，不只截最终成功弹窗。系统自动处理的结果也要从页面验证，但不能新增一排“手工执行JOB”产品按钮来绕过自动业务。
