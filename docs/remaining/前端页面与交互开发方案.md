## 关键交互规则

- 开始和恢复都服从后端当前安排及父链资格，不增加自由专注、番茄钟、补时或客户端改时间。
- 同用户最多一条运行，不静默切换任务；保留多个暂停会话。同任务重新开始复用原会话。
- 跨设备查看可暂停／结束；控制身份不同的界面不发送心跳，接管按先暂停再恢复处理。
- 显示时间以服务端实际秒数和当前段截止为准，客户端仅平滑展示，始终封顶，不因后台扫描延迟继续增长。
- 控制端每 20 秒心跳，自动 current、overview、未读数轮询不改写登录会话有效期；网络异常给出明确状态，不盲目重发开始请求。
- 习惯仅用户名下维护的分类、每天或指定星期、一次有效打卡，不增加数量限制。规则以修订为准，今天完成后改规则、分类、暂停、结束或删除，仍保留 1/1。
- 暂停／结束后的当天打卡可撤销，删除后不可撤销；不开放过去或未来日期补卡。
- 消息已读与业务处理分开，失效来源不可确认；确认携带消息和目标版本，继续保持不完成目标。
- 总／周／月／年／自定义周期均展示，当前周期不纳入未来日期，零分母显示无应做；真实状态历史不由当前状态倒推。
- 目标筛选只作用于成长／执行／安排，习惯仍为账户维度并明确标注，避免误解统计口径。
- 页面局部更新，避免操作按钮、自动轮询和菜单折叠引起整页刷新；提交中禁用重复动作，错误时保留表单，409 重新读取受影响记录。

## 页面与样式

沿用现有深色侧栏、浅色内容区、蓝色主要操作、白色卡片、圆角和浮动阴影。补齐面包屑、筛选、分页、状态标签、空状态、骨架加载、错误与重试、移动端布局、焦点反馈及 reduced-motion 支持。统计使用 ECharts 展示实际投入、完成动作和习惯完成率；图表使用真实接口数据，空数据不伪造样本。

普通用户有看板权限时默认进入今日看板；管理员仍默认进入管理页面。新菜单在前端完成构建与启动检查后，使用现有 SQL 标记块手工启用；不自动建表或迁移。执行记录与成长时间线从对应主页面进入，不额外增加未审批的后端菜单节点。

## 实施顺序与验证

页面范围确认后按 API 封装与公共状态 → 执行与全局计时 → 习惯与分类 → 通知 → 看板与统计 → 原详情接入 → 导航及菜单启用的顺序实现。

验证按既有要求，只做前端构建、开发服务启动与必要页面资源检查；不建立或运行严格单元、系统、集成测试。业务人工验收继续独立记录，不将构建通过作为业务通过。涉及已有后端菜单组件白名单的必要兼容补齐，仍使用原技术版本和原接口。
