# 后续模块后端业务与接口约定

本次仅实现后端。统一前缀为 /asterway，成功和失败沿用 ResultVO，分页为 PageResultVO(items,total,page,size)。标识使用字符串返回；版本是非负整数；page 默认 1，size 默认 20、最大 100。

全部个人核心能力只属于拥有 USER 且没有 ADMIN／SUPER_ADMIN 的当前用户。收件人、所属用户、账号时区、当前日期和操作时间均从服务端取得，接口不接受指定他人的 userId。跨用户资源返回 404，管理身份返回 403，状态／版本变化返回 409，参数错误返回 400。

写入口先按当前身份检查，再锁定用户并重新加载角色、权限及认证版本；等待锁期间发生停用、改密或身份变化时拒绝旧请求。生命周期联动加入父事务，仍遵循先用户锁、后业务对象的顺序。

## 分层和接口数量

新增 38 个 HTTP 操作：习惯 19、通知 7、看板 4、统计 5、原成长主体状态历史 3。不增加 Maven 子模块，不增加业务工程间依赖。

业务调用仍为 Controller → Service 接口 → ServiceImpl → Mapper/XML。habit_category 使用自己的完整链路；habit_revision、habit_checkin 隶属 Habit 主链，不另拆增删改查 Service。三个状态历史 Mapper 隶属各自原主体主链；通知处理目标完成，通过 common 中立契约交回 GoalService。看板、统计只读真实事实，不创建专用实体表或缓存表。

## 习惯分类：4 个操作

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | /habit-categories | habit:category:list |
| POST | /habit-categories | habit:category:create |
| PUT | /habit-categories/{id} | habit:category:update |
| DELETE | /habit-categories/{id}?version=… | habit:category:delete |

保存字段：name、sortOrder、version。创建不要求版本，更新必须提供当前版本。名称去首尾空格、有效分类同用户不重名；删除只逻辑停用，不修改既有习惯及其历史修订。已删除分类不允许新选择；既有习惯保持原分类时可以继续保留引用。

| POST | /habits/{id}/resume | habit:habit:resume |
| POST | /habits/{id}/end | habit:habit:end |
| POST | /habits/{id}/reopen | habit:habit:reopen |
| DELETE | /habits/{id}?version=… | habit:habit:delete |

| GET | /habits/{id}/checkins | habit:checkin:read |
| GET | /habits/{id}/revisions | habit:habit:history |

创建／保存资料：

```json
{
  "name": "阅读",
  "description": "",
  "completionCriteria": "完成当天阅读",
  "categoryId": null,
  "cycleType": "WEEKLY_DAYS",
  "weekdays": [1, 3, 5],
  "startDate": "2026-11-04",
  "expectedTime": "20:30",
  "version": 0
}
```

DAILY 固定每天，WEEKLY_DAYS 使用不重复的 1～7 数组；底层位图不作为 API 入参。提示时间仅 HH:mm，不触发定时提醒。创建缺省开始日期取账号今天；不存在的过去规则不补造。PATCH 的空值保留原资料；PUT 清空可选分类／时间／文本，必填名称仍须提供。资料与规则无变化不新建修订。

默认习惯列表不含 ENDED，status=ENDED 或 archived=true 读取结束归档项；可按 keyword、categoryId、status 和分页查询。已删除主体不再出现在当前资料列表，但本人可继续读取其 revisions 和 checkins。打卡历史支持 dateFrom、dateTo、cancelled 和分页筛选。

暂停／恢复／结束／重新开启请求为 {version}。ACTIVE 可暂停，PAUSED 可恢复；ACTIVE／PAUSED 可以结束，ENDED 需重新开启；逻辑删除不恢复。重复已到达的目标状态不重写历史。结束后的资料需先重新开启再修改。

打卡请求 {version} 中的版本为习惯版本，只允许今天且符合周期、开始日期和 ACTIVE 状态；已有有效打卡直接返回已有记录，不覆盖时间。撤销参数 version 为打卡版本，允许暂停／结束后撤销当天打卡；不允许删除后撤销或回写过去日期。撤销保留原行，重新打卡新建行。

今日列表按该日有效修订判断应做；已完成日优先保留为 1/1，即便之后改分类、暂停、结束或删除。today 结果返回所用 revisionId、checkinId、doneCount／dueCount 和动作可用标志，不用当前分类重算已完成日。

## 站内消息：7 个操作

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | /notifications | notification:message:list |
| GET | /notifications/{id} | notification:message:read |
| GET | /notifications/unread-count | notification:message:list |
| PATCH | /notifications/{id}/read | notification:message:mark_read |
| POST | /notifications/read-all | notification:message:mark_read |
| POST | /notifications/{id}/confirm | notification:message:handle |
| POST | /notifications/{id}/continue | notification:message:handle |

列表支持 unread、handleStatus 和分页；unread=true 排除失效消息，unread=false 只包含实际已读行。读取详情不隐式标记已读。单条标记请求 {version}；标记全部已读不需要请求体。已读和处理独立，失效不会伪造已读，未读数排除 INVALIDATED。

确认请求 {version,goalVersion}，继续请求 {version}，也可提供 goalVersion。详情中的 goalVersion 是来源当前版本，canHandle 为可处理标志。消息只能由本人处理，且当前目标仍满足非空有效任务全部完成、未归档、未完成、未删除及当前轮次一致。重复相同处理幂等返回；已失效或改选不同处理结果返回冲突。

确认由 Goal 主链更新目标状态并追加 NOTIFICATION 来源历史，再把当前消息标为 CONFIRMED；同一事务失败整体回滚。继续保持原目标状态并标为 CONTINUED，同轮不重发。目标完成／归档、任务回落或失去个人身份会撤回待处理消息；再达标才进入下一轮。没有公开发送、公告、邮件或群发接口。

## 今日看板：4 个操作

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | /dashboard/overview | dashboard:board:read |
| GET | /dashboard/tasks | dashboard:board:read |
| GET | /dashboard/goals | dashboard:board:read |
| GET | /dashboard/habits | dashboard:board:read |

后三个列表支持分页。tasks 新增可选 section=TODAY／WEEK_UNDATED，筛选后再执行分页与计数；不传时保持原混合列表行为，非法值返回 400。overview 返回 today、timeZone、serverTime、metrics 和 currentExecution。今日已安排任务与 WEEK_UNDATED 分开；当前计划已完成数不声称是今天真实完成动作数。当前执行返回计时截止、段标识和 canHeartbeat，不暴露控制端 SID。

所有指标独立聚合：不将任务、执行段和打卡直接做一对多联结后再求和。过期运行段即使调度未扫描也封顶；今日习惯用实际打卡或当日规则，包含已完成后暂停／删除的事实。

## 历史统计：5 个操作

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | /statistics/summary | statistics:report:read |
| GET | /statistics/trends | statistics:report:read |
| GET | /statistics/timeline | statistics:report:read |
| GET | /statistics/habits | statistics:report:read |
| GET | /statistics/objects | statistics:report:read |

统一周期参数：period=TOTAL／WEEK／MONTH／YEAR／RANGE，默认 MONTH；anchorDate 选择自然周期，缺省今天；RANGE 必须同时提供 dateFrom、dateTo，含首尾日期且不能在未来。当前周期截至今天。TOTAL 从账号最早可得业务事实开始，没有数据时返回今天的空统计。

可选 goalId、stageId、taskId 仅筛选成长状态／执行／安排；会核对本人及父子关系，已归档／逻辑删除对象仍可筛选。习惯独立于目标，习惯指标保持账户维度，不通过目标关联过滤。返回结构和本节说明用于区分这两种口径。

summary 返回累计与区间实际耗时、按会话去重计数、习惯总完成／应做和真实状态动作；时间段数量不当作会话数量。trends 按日期分页，先切分页日期再查询该页事实，零数据日期补零；timeline 采用发生时间、事实类型、主键、事件类型稳定排序。habits 支持 groupBy=HABIT／CATEGORY，返回总计及分组分页，分组使用当时修订的分类引用。objects 返回当前有效未归档对象分布，与历史完成动作独立。

执行以真实段交集计毫秒，再统一转秒；暂停不计时，删除任务仍保留投入。状态历史区分完成动作数与去重完成任务数：同任务完成后重开再完成记两次动作，但区间任务去重计一。BASELINE 不算完成，可信 COMPLETION_IMPORTED 算真实旧完成事实。不提供根据当前任务状态推测的过去完成率，也不伪造历史权重进度曲线。

## 账户与时区联动

停用、删除账号或授予管理身份会暂停其 ACTIVE 习惯、撤回个人待处理提醒；重新启用或撤销管理身份不自动恢复习惯。注销、改密、踢下线继续沿用 Execution 的控制端暂停规则，不因此暂停日常习惯。

时区仍在旧时区下一日零点生效。清除待生效时区前封存旧时区最后一天；习惯写入入口即便账户接口尚未整理该字段，也先完成封存。回拨到已封存日不能修改规则、打卡或撤销；原打卡 businessDate 不搬移。系统暂停在这种情况只对首个未封存日追加规则快照，主体立即 PAUSED，不改写封存日。

自动执行心跳、执行 current 轮询、看板 overview 轮询和通知 unread-count 轮询不延长七天登录有效期。其他主动成功操作沿用既有会话规则。

## 人工业务验收清单

以下仅为后续人工验收项，本轮未执行，不以编译／启动代替业务验收：

- 分类重名、删除分类后旧引用、新选择拦截。
- 创建、修改、暂停、恢复、结束、重新开启和逻辑删除习惯；无变化不生成修订。
- 今日打卡、重复打卡、撤销重打、暂停／结束后撤销、过去和未来日期限制。
- 同日完成后换分类／改周期／暂停／结束／删除，仍保留一次完成；多周期／零分母统计。
- 目标精确达标、继续保持、回落撤回、重新达标下一轮、确认完成及版本冲突。
- 执行开始任务历史、任务完成重开再完成、归档恢复、删除后历史保留。
- 多用户／管理身份隔离、时区延后生效与回拨封存、自动轮询不续签。
