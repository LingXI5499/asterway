> 文档版本：V2.0。
> 用途：本版正文的结构化编制输入；阅读从 [V2.0 文档目录](../README.md) 开始。

## 1. 请求与响应

| 编号 | 项目 | 规则 |
|---|---|---|
| HTTP-001 | 地址 | 同源部署；业务公共前缀 /api/v1；02～05各接口及索引写完整路径，联调时不再自行拼接两次前缀；不暴露数据库表名作为通用 CRUD |
| HTTP-002 | 请求体 | JSON，UTF-8。分页/过滤放 Query；创建、修改、动作放 Body。DELETE 不传 Body，版本及确认放 Query |
| HTTP-003 | 状态码 | 创建新身份 201；读取、更新、动作、删除 200；不在 204 响应塞 JSON。其余按第 5 节 |
| HTTP-004 | 统一外壳 | 每次 JSON 响应均为 code:string、message:string、data:对象或 null、traceId:string；成功 code=OK，提示可中文，程序判断 code |
| HTTP-005 | 写请求头 | Idempotency-Key:UUID；X-CSRF-TOKEN:string；登录前也先取得 CSRF。Cookie 凭证由浏览器处理，不放 URL |
| HTTP-006 | 内容边界 | 不认识的字段和不可写字段拒绝；不将数据库行直接序列化。部署请求体上限初值1 MiB，代理与应用一致且可调整，超出413 PAYLOAD_TOO_LARGE并保留表单；它会限制单次可提交体积，须明确提示，但不能把此值变成单字段业务max或截断已提交内容 |
| HTTP-007 | 缓存 | 认证和个人接口 Cache-Control:no-store；代理不缓存个人 JSON，Service Worker 不离线缓存个人内容 |

GET 允许复用已授权的到期补偿用例，使读取反映已到日期的事实；不借 GET 创建用户规划、完成任务或打卡。需要可靠提交的到期处理先完成独立事务，再执行本次命令；后续命令失败不能撤回已经发生的到期暂停。

## 2. 基础类型与空值

| 编号 | 类型 | 传输格式与校验 |
|---|---|---|
| TYPE-001 | UUID | 标准 UUID 字符串；非法格式 400；不存在或不属于本人 404 |
| TYPE-002 | date | YYYY-MM-DD；严格有效日期；不是 UTC 零点时间戳 |
| TYPE-003 | UTC | ISO 8601 UTC 字符串，以 Z 结尾，小数最多 6 位；服务端持久化到微秒 |
| TYPE-004 | long | version、expectedVersion、conditionRound、sortOrder、revision、控制代次/序号及所有秒/毫秒/微秒时长使用十进制字符串；不发给 TypeScript number，避免丢精度 |
| TYPE-005 | number | 条数、分页大小、ISO 星期、cycleNo 等已明确为普通整数的字段；不得超出契约与数据库范围 |
| TYPE-006 | 百分数 | 两位小数字符串，如 66.67；无考核任务时 null，另带 hasTasks=false；真实完成条件用 C=N 且 N>0 判断 |
| TYPE-007 | enum | 严格采用各 DTO 列出的英文值；不接受展示中文和未知值 |
| TYPE-008 | null / 缺省 | 响应中声明可空字段固定返回 null。PATCH 缺省表示不改；null 只可清除可空字段。不能把 null 变为字符串 null |
| TYPE-009 | 字符 | 密码按 Unicode 码点计 8～50，全空白按未填，其余完整参与验证、不 trim；用户名/昵称按现行业务规则 校验 1～30。业务必填文本不能全空白，不自动修改正文和密码 |

基础 DTO：Page<T> 具有 items:T[]、nextCursor:string|null、hasMore:boolean；Violation 具有 field:string、message:string；EmptyResult 没有业务字段，成功 data 固定为空对象。03 中的安全 DTO、04 中的 GoalView/StageView/TaskView/AssignmentView、05 中的执行/习惯/查询 DTO 是对应领域的唯一对外定义。

## 3. 身份、权限和版本

| 编号 | 规则 | 具体要求 |
|---|---|---|
| SEC-001 | 服务端会话 | 使用 Spring Security + Spring Session JDBC；登录成功更换会话身份；principal 绑定稳定用户 UUID，不绑定可改的用户名 |
| SEC-002 | Cookie | 生产 Secure、HttpOnly、SameSite=Lax；会话仅同源传输。CSRF 值由接口取得并保存在当前页面内存，不能读取 HttpOnly 凭证 |
| SEC-003 | 每次授权 | 受保护入口检查账户可用、会话安全版本及恢复代次；不能只在首次登录检查。角色只用于管理权限，不能绕过个人归属 |
| SEC-004 | 账户范围 | 所有本人查询带当前身份约束，写入在账户锁内重验父子关系。不存在与不属于本人均 404，不回传别人的名称 |
| SEC-005 | 管理范围 | ADMIN 只管理 USER；SUPER_ADMIN 按 03 管理允许对象；最后可用超级管理员不得失去；后台不返回成长正文 |
| SEC-006 | 并发版本 | 修改既有聚合传 expectedVersion:string；不接受客户端 version 新值。版本不符 409，返回已授权对象的 currentVersion，用户刷新后再决定 |
| SEC-007 | 排序版本 | 使用所属目标/计划列表版本并核验完整排序集合；不可只更新一个索引而覆盖并发成员变化。具体字段见 04 |
| SEC-008 | 恢复保护 | 恢复会使全部旧会话失效；独立安全账本未核实的账户拒绝敏感访问。控制权代次与对象版本分别校验，不能互相代替 |

本 MVP 不新增闲置自动退出或登录后固定小时数自动退出规则，也不能把框架默认超时无声当成产品要求。工程配置须显式关闭未约定的自动过期，并实测框架长会话行为；改密、禁用、删除、主动撤销和灾难恢复仍立即使相应会话失效。未来若增加会话期限，先走需求变更和计时中断验证。

## 4. 幂等与结果待确认

### 4.1 同一次意图只产生一次效果

| 编号 | 情况 | 服务端和页面行为 |
|---|---|---|
| IDEM-001 | 双击、断网重试、响应丢失 | 同一路径动作、同一参数保留原 Idempotency-Key。先查已提交结果，再校验旧版本；成功重放不能误报版本冲突 |
| IDEM-002 | 同键异参 | 409 IDEMPOTENCY_KEY_REUSED；用户改变了操作内容才生成新键，不能用新键掩盖未知结果 |
| IDEM-003 | 正在处理 | 409 REQUEST_IN_PROGRESS，返回 retryAfterSeconds:string；不重复进入事务。页面保持处理中，可用原键核实 |
| IDEM-004 | 提交状态不明 | 503 RESULT_UNKNOWN；保留原键、原请求和上下文，查询对象或用原键重试。不能立即写失败、乐观完成或自动换键 |
| IDEM-005 | 已明确拒绝 | 可保存该次明确业务拒绝，不含秘密。版本/状态已改变后用户再次决定，是新意图；参数修正后必须新键 |
| IDEM-006 | 记录过期 | 普通业务去重结果终态后至少保留7天作为工程默认；未决先核实。验证码取图/验证是短期例外，只在挑战有效窗内受控重取，不长期留图或验证凭据。UI不自动重放超过期限的意图，先查询业务事实再由用户决定 |

作用域是账户 UUID+操作+键；注册/登录的匿名作用域绑定服务端预认证浏览器会话与用途，不能仅靠客户端自报 userId。没有业务意义的验证码“发起”本身也按意图去重，避免重试批量发挑战。

去重状态和核心业务结果在同一可证明的事务中提交；PROCESSING 不能先永久提交后无人接管。若使用短事务认领，须有到期恢复和最终结果核实，不能因过期就无条件重复写。数据库唯一键和业务自然键仍是最终保护。

DB-30.operation统一保存原接口编号，例如API-AUTH-008；同一编号的Path对象标识进入请求指纹，不让不同对象共用同键却绕过参数比较。

请求摘要包含方法、规范化路径及契约参数；秘密参数使用服务端密钥的 HMAC 指纹，不保存密码、验证码答案或普通快速摘要。结果只留对象标识、安全摘要、HTTP 与业务 code；登录会话、CSRF、执行许可不进入缓存结果。重试应重建当前授权下的响应：原效果保持一次，当前 DTO 可以更晚；如已删除或权限撤销，只确认原意图结果，不复活对象、不返回过期秘密。

### 4.2 执行确认的特殊规则

执行确认还须校验owner、控制代次、顺序和短期许可，见05。确认响应丢失时，同键重试只取得原确认结果，不把新的网络到达时间记作新确认点。API-FOCUS-007将原sessionId、segmentId、confirmedAt和confirmedFocusMicroseconds存入DB-30.result_summary.confirmationResult安全摘要；不含许可，保证后续确认已推进时仍能核实早先意图。下一许可仅在仍匹配当前有效控制状态时受控取得，过期或换代后不能重发或续命。登录/退出/改密重试也不重发旧登录令牌；会话已失效时按03的重登和核实分支处理。

### API-COMMON-001 查询本人原操作结果

#### 需求分析

写入可能已经提交，但页面没收到响应。用户需要核实原意图，避免重复改密、重复完成或错误显示失败。入口为全局“结果待确认”交互 UI-GLOBAL-08；本人有效会话可查本人原操作，管理操作还需具备当前对应权限。它是落实 NFR-REL-003/007 的通用工程接口，不另造 FR 编号。

#### 业务流程

1. 从当前会话取得稳定账户 UUID，构造本人 `USER:UUID` 作用域；不接受客户端指定 userId/scope。
2. 校验 operation 是真实写接口编号，与查询键一起定位原请求记录。
3. 重新校验原操作目前的角色及对象可见范围；撤销后的后台权限不能借此读出原后台结果。
4. 返回处理状态与安全摘要，不重做原业务，不签发旧 Cookie、CSRF、验证码或执行许可。
5. 未找到/已过期只说明结果查询不能确定，不能据此判定原动作未发生；页面继续查询业务事实，再由用户决定后续动作。

改密结果丢失且旧会话已失效时，先正常验证凭据重新登录，再查原意图，只核实、不再改密。退出同理不撤销重新登录后的新会话。匿名注册/登录先按03当前会话及同键协议处理，本接口不提供任意匿名结果检索。计时控制仍走05受控协议。

#### 接口设计

| 项目 | 约定 |
|---|---|
| 方法与路径 | GET /api/v1/operations/{idempotencyKey} |
| 权限 | 本人有效会话，任何角色均只查本人作用域；另重验原操作权限 |
| 请求头 | 浏览器自动携带同源会话Cookie；GET不传Idempotency-Key和CSRF写入头 |
| 请求体 | 无；不接受userId、scope或原请求秘密 |
| 成功 | 200，data为OperationResult |

| 位置 | 参数 | 类型 | 必填 | 约束 |
|---|---|---|---|---|
| Path | idempotencyKey | UUID字符串 | 是 | 原写请求的键，不是新的请求键 |
| Query | operation | string | 是 | 02～05定义的真实写接口编号，例如API-TASK-005；不能是任意字符串或GET编号 |

OperationResult 字段完整定义如下，响应按02统一外壳包装。

| 字段 | JSON类型 | 可空 | 含义 |
|---|---|---|---|
| operation | string | 否 | 原接口编号 |
| idempotencyKey | string(UUID) | 否 | 原意图键 |
| state | string枚举 | 否 | PROCESSING / SUCCEEDED / REJECTED |
| httpStatus | number | 是 | 已确定结果的HTTP状态；处理中为空 |
| resultCode | string | 是 | 已确定结果的业务code |
| effectApplied | boolean | 是 | 是否确认业务效果已应用；未定为空 |
| resultType | string | 是 | 原结果的安全资源类型摘要，不是Java类名 |
| resultId | string(UUID) | 是 | 可见的主要结果身份 |
| resourceIds | string(UUID)[] | 否 | 当前有权查看的相关身份；无则[] |
| versions | object | 否 | UUID键到十进制版本字符串；无则{} |
| createdAt | string(UTC) | 否 | 意图记录创建时刻 |
| updatedAt | string(UTC) | 否 | 最近状态变更时刻 |
| expiresAt | string(UTC) | 否 | 该结果查询记录的保留期限 |

| HTTP/code | 具体触发 | 页面动作 |
|---|---|---|
| 400 VALIDATION_ERROR | Path不是UUID | 修复调用参数，原意图不变 |
| 401 AUTH_REQUIRED | 当前会话无效 | 先重新认证，不凭键恢复旧登录身份 |
| 403 FORBIDDEN | 原管理权限已撤销 | 不展示原受限资料，不绕过授权 |

| 503 SERVICE_UNAVAILABLE | 无法读取/核实结果 | 保留待确认状态，稍后重查 |

失败示例（HTTP 404）：

```json
{"code":"OPERATION_RESULT_NOT_FOUND","message":"未找到可查询的操作结果，请继续核实业务状态","data":null,"traceId":"operation-query-missing"}
```

#### 数据操作

按本人作用域、operation、idempotency_key读取DB-30，映射其状态及result_summary。读取已过期结果不暴露；已删或无权对象只确认允许返回的原意图事实，资源身份和版本按当前授权裁剪。查询不更新原请求状态、不延长保留期限、不重新进入原事务，不从任意数据库列拼出秘密信息。

#### 分层实现步骤

1. `OperationResultController.get`绑定路径/查询，取得当前身份；与一般GET一致做权限检查。
2. `OperationResultQueryService.findOwned`读取去重记录并调用原操作的当前授权检查，映射安全结果；不会调用原写Service。
3. `RequestDedupMapper.selectVisibleResult`在XML中绑定作用域、操作、键及有效期；仅查需要的列。
4. 明确区分处理中、成功、明确拒绝和查不到，按上述HTTP/code组装；不返回缓存的旧认证响应。

## 5. 统一错误目录

| HTTP | code | 含义/页面动作 |
|---|---|---|
| 400 | VALIDATION_ERROR | JSON、路径或基础类型解析失败，定位字段 |
| 401 | AUTH_REQUIRED | 遮蔽个人数据，重新登录，保留不含秘密的结果核实提示 |
| 403 | FORBIDDEN / CSRF_INVALID | 权限或 CSRF 防护失败；不自动绕过校验 |
| 404 | NOT_FOUND | 对象不可见或不存在 |
| 409 | VERSION_CONFLICT | 刷新当前已授权对象，保留用户输入供比较，不自动覆盖 |
| 409 | STATE_CONFLICT | 当前状态不允许此动作，显示原因及可用动作 |
| 409 | UNFINISHED_EXECUTION | 展示全部相关未结束执行，引导逐个结束；不能直接归档、删除、退出或完成 |
| 409 | EXECUTION_CONTROL_LOST / PERMIT_EXPIRED | 停止本页确认，刷新状态，提示暂停/接管；不悄悄抢占控制权 |
| 409 | IDEMPOTENCY_KEY_REUSED / REQUEST_IN_PROGRESS | 依第 4 节处理 |
| 413 | PAYLOAD_TOO_LARGE | 提示请求过大，保留未提交表单 |
| 422 | VALIDATION_ERROR | 业务字段范围、确认、日期或完整列表不合法 |
| 429 | RATE_LIMITED | 资源限流，按 Retry-After 重试；与凭据错误锁定分开统计 |
| 503 | RESULT_UNKNOWN | 效果待核实，保持原键 |
| 503 | SERVICE_UNAVAILABLE | 无法完成服务；安全校验失败不能放行 |

03～05 可以声明用途明确的附加 code，但必须写 HTTP、触发条件和页面动作。凭据失败对用户统一“用户名或密码错误”；验证码失败不增加用户名/密码错误次数。错误不带 SQL、异常栈、密码内容、其他用户数据。

ErrorData 可包含 violations:Violation[]、currentVersion:string、currentState:string、blockingCodes:string[]、unfinishedExecutions:UnfinishedExecutionHint[]、retryAfterSeconds:string。每个错误只返回必要字段；无附加信息时 data=null。traceId 无论成功失败均可供定位，不能用用户正文生成。

批量配置修改API-ADMIN-009使用专有`currentVersions`对象，固定配置key映射到各自版本字符串；字段及返回条件见03，不以某一个对象的currentVersion代表整批配置。

UNFINISHED_EXECUTION统一采用UnfinishedExecutionError：unfinishedExecutionCount:number、unfinishedExecutions:UnfinishedExecutionHint[]（最多100条）、unfinishedExecutionsHasMore:boolean；提示按startedAt、sessionId升序，Hint字段见03/04。该页只是提示，服务端检查完整集合；超过100条通过05的FOCUS-011按相应scope分页取全，不能漏掉余下阻塞记录。

## 6. 分页、排序、筛选和时间范围

1. limit 默认 20、范围 1～100；cursor 可省略。游标绑定身份、筛选、排序及上一页边界，有签名/防篡改；非法游标 422。每个列表写清排序并加稳定主键作最后一列。
2. 默认列表仅本人的当前有效对象。历史、归档、已删除保留身份必须用明确视图取得，不能为方便把全部表扫给前端再筛。
3. 列表无总量需求时只返回 Page；确需统计的卡片独立给 count，不通过遍历分页计算。过滤变化后重新从第一页读取。
4. 日期范围用 fromDate/toDate，含两端；支持非功能需求规定的完整三年范围单次一致性汇总，不新增366天限制。明细和按日结果分页，历史不按年限裁剪；大范围查询在服务端优化，不能要求浏览器把不同时间的多次汇总相加冒充一致结果。
5. 多页列表是逐请求的新视图，不承诺跨翻页冻结。写入后刷新有关列表；严格汇总在单次只读一致性快照内完成，不能把不同事务的数字拼成一个精确总计。
6. 字符筛选使用参数化查询、固定可选排序；不能把排序字段、原始 SQL 或表名交给客户端。

## 7. 数据从哪里来，到哪里去

| 编号 | 数据 | 来源→处理→保存→返回/缓存 |
|---|---|---|
| FLOW-001 | 规划与状态 | 用户表单→Controller 参数验证→应用用例/领域能力→本人表与事实表事务→VO；浏览器仅当前账户内存 |
| FLOW-002 | 执行时间 | 服务端时间+短许可确认→执行控制→区间最后可信点/归属→页面正向估计；客户端时钟不落为真实耗时 |
| FLOW-003 | 日期/时区 | 设备 IANA 值→服务器校验→当前/待生效时区区间→业务日边界与不可变历史；不采定位 |
| FLOW-004 | 统计 | 事实区间、完成快照、habit_day→短只读一致性快照→有口径的卡片/分页；不存可手工修改的累计总数 |
| FLOW-005 | 通知 | 核心事实+outbox 同事务→消费者按轮次去重→notification→列表；失败重试不回滚任务完成 |
| FLOW-006 | 安全变更 | 独立账本 INTENT→本地变更/审计/安全记录提交→独立 RESULT→会话逐请求校验；不把密码材料放事件 |
| FLOW-007 | 草稿与缓存 | 表单在当前页面内存暂存；凭据、正文不放 localStorage/sessionStorage/IndexedDB。切号、失效、退出立即清理/遮蔽；重连先认证 |

Pinia 按账户会话维护短期 UI 状态，收到服务端成功才确认写入。允许保存不含正文的界面偏好，例如导航折叠；不能让偏好缓存保存个人响应或执行许可。

### 8.1 类型、分页与错误的共同判读示例

`expectedVersion:"2"`为合法字符串，`expectedVersion:2`应被契约校验拒绝；UUID是字符串，条数是number，UTC时刻与业务日分别是`2026-10-18T02:00:00Z`和`2026-10-18`，不能互换。响应声明可空的字段保留null，集合为空返回[]。

空分页成功（HTTP 200）：

```json
{"code":"OK","message":"查询成功","data":{"items":[],"nextCursor":null,"hasMore":false},"traceId":"empty-page-example"}
```

版本冲突（HTTP 409），页面保留输入，刷新对象并比较，由用户决定是否形成新意图，不能自动覆盖：

```json
{"code":"VERSION_CONFLICT","message":"内容已更新，请刷新后确认","data":{"currentVersion":"3"},"traceId":"version-conflict-example"}
```

业务字段校验失败（HTTP 422）；解析错误才使用400：

```json
{"code":"VALIDATION_ERROR","message":"请检查填写内容","data":{"violations":[{"field":"expectedEndDate","message":"预计结束日期不能早于开始日期"}]},"traceId":"validation-example"}
```

### 8.2 幂等、版本和控制代次的处理次序

先完成当前身份和权限检查，再用同作用域operation/key核实是否已有原意图终态；有则按当前授权安全重放，不能先用旧expectedVersion拒绝已成功原意图。只有首次执行才进入当前业务状态与版本校验。相同键不同参数拒绝，不能偷偷采用新参数。

普通聚合version保护业务对象并发；执行owner/controlEpoch/确认序号等保护当前控制资格。两者分别检查，查询原意图结果也不能重新签发执行控制或续期。遇到不确定提交结果保留原键，不能自动换键“再试一次”。
