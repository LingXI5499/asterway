## 1. 版本采用规则

本项目以正式发布、组件兼容和可复现构建作为稳定版本的选择标准。Java 固定 17，Maven 固定本机 3.9.4，Spring Boot 固定 3.x 的 3.5.16；Node.js 采用 24 LTS。前端依赖使用下表中的精确版本，排除 alpha、beta、RC、SNAPSHOT 和 nightly。

后端父子工程和后端依赖版本已写入 POM，前端工程及锁文件尚未建立。前端精确版本属于设计记录，建立工程前须核验可解析版本与兼容关系。

### 2.1 Flyway、schema 与本地配置覆盖

以下仅记录核查时文件中的非秘密配置事实，不展示数据库地址、用户名、密码或其他私有值。公开模板与被忽略的 local 配置必须分别核对；不能只读公共模板就宣称运行时最终值已确定。

| 配置项 | 公共 application.yml | 被忽略的 local 配置 | 静态判断与待核验 |
|---|---|---|---|
| spring.flyway.baseline-on-migrate | false | true | local 文件会在相应 profile 生效时覆盖公共值；本版未启动，不将此结果称为已验证的运行时有效值 |
| spring.flyway.baseline-version | 未单独声明 | 0 | local 中声明 0；不据此推断历史表已建立、基线动作已发生或 V001 已被 Flyway 正确登记 |
| spring.flyway.default-schema | migration_meta | 需与全部配置来源合并核对 | 历史表 schema 已有公共绑定，实际历史及权限未查询 |
| spring.flyway.schemas | migration_meta、app、session_store | 需与全部配置来源合并核对 | 只说明涉及的 schema 名称，不代表它们已经存在或表已落在正确 schema |
| spring.flyway.create-schemas | false | 需与全部配置来源合并核对 | schema 需由受控环境预先准备；本版未执行创建或验证 |
| spring.session.jdbc.initialize-schema | never | 需与全部配置来源合并核对 | 框架自动建表关闭；无外键会话仓库、表名及增删/清理 SQL 适配仍未实现 |

公共 schema 绑定属于部分进展，不能再写成“完全未配置”，也不能写成“会话及迁移模式已经验证完成”。Spring Session 的存储及无外键事务适配还需在隔离库核验，Flyway schemas 列表不等于为 Session 自动选择目标表。未来实施前须核实 profile、环境变量、启动参数和其他外置配置，明确是否保留 local 的自动 baseline 覆盖；不能在存在未核实历史的库中直接依赖自动 baseline。

真实账户脚本为 `V001__create_app_user.sql`；用户反馈已执行，本版不连接数据库、不核实历史、不修改配置或脚本。其保护及后续新版本分配见 01 第 1.1、14 节，不能用配置静态值替代执行证据。

## 5. 远程 PostgreSQL 与扩展核验

现有服务器采用 PGDG RPM 安装方式，软件包为 `postgresql17-server` 和 `pgvector_17`。用户提供的安装说明如下，仅作为现有环境来源记录；已安装服务器无需为本次文档调整重新执行安装：

```bash
# 存在冲突模块时才需要；具体以当前系统仓库为准
dnf module disable postgresql -y
dnf install -y postgresql17-server pgvector_17
```

软件包名只限定 PostgreSQL 17 系列，实际补丁取决于仓库；本次精确版本来自以下命令的截图输出：

```text
/usr/pgsql-17/bin/postgres --version
postgres (PostgreSQL) 17.11

rpm -q pgvector_17
pgvector_17-0.8.7-1PGDG.rhel8.10.x86_64
```

部署基线为连接已有远程 PostgreSQL 17.11。应用编排管理 Nginx 与一个 Java 17 应用；数据库由远程主机管理，使用受控地址和独立账户连接。开发、测试和生产分别使用隔离数据库与凭据，测试在真实 PostgreSQL 17.11 上执行。数据库主机的数据目录、备份及升级由其部署流程管理。

上线前通过受控连接对**运行中的目标实例及目标数据库**执行以下只读 SQL，并保存结果：

```sql
SHOW server_version;
SHOW server_version_num;

SELECT name, default_version, installed_version
FROM pg_available_extensions
WHERE name IN ('btree_gist', 'vector');

SELECT extname, extversion
FROM pg_extension
WHERE extname IN ('btree_gist', 'vector');
```

`postgres --version` 表示该路径下的二进制版本，不能单独证明当前连接实例的版本；RPM 已安装也不等于目标数据库已执行 `CREATE EXTENSION vector`。MVP 仍不使用向量字段或向量检索，pgvector 只登记为服务器已有组件，迁移不以启用 `vector` 为前提。`btree_gist` 则是 01 的时间排除约束依赖，迁移前检查并由受控迁移角色准备。[PostgreSQL 17 的 btree_gist](https://www.postgresql.org/docs/17/btree-gist.html)、[pgvector 安装与启用说明](https://github.com/pgvector/pgvector#installation)。
