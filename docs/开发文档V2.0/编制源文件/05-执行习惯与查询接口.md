## 2. 执行计时：先读懂控制权

### 2.1 执行与控制权

| 项目 | 固定规则 |
|---|---|
| session | 一次可暂停/继续的执行；结束后不可恢复 |
| segment | 一段不间断计时；恢复会新增段 |
| 单账户限制 | 可以暂停多次执行，同时只计时一项 |
| 新开始 | 新session累计从0开始 |
| 恢复 | 同session保留旧累计，暂停间隔不计 |
| 任务完成 | 另调04的TASK-005；先结束相关全部执行 |
| 控制页确认 | 每10秒一次 |
| 一次性许可 | 15秒到期；接收和持锁后都校验 |
| 服务端扫描 | 默认每5秒扫描失效许可 |
| 暂停可见时效 | 健康服务中最后T后45秒内；不是续期宽限 |
| 观察页同步 | 默认每2秒GET；不替控制页保活 |
| 页面不可见 | 仍能可靠确认就继续；冻结/休眠断确认才暂停 |
| 进程重启 | 旧代次开放段截到持久化T，恢复完才放行执行写入 |

### API-FOCUS-001 查询当前执行状态

**接口：** `GET /api/v1/focus/state`

#### 需求分析

**目的：** 页面首次进入、重连或观察页轮询时，需要知道真实运行执行、已确认累计和控制归属。

**入口：** PAGE-003 /today、PAGE-008 /tasks/:taskId、PAGE-012 /focus。

**前置：** 可无任何执行；运行恢复门禁必须完成。

**追溯：** FR-FOCUS-005、FR-FOCUS-013、FR-FOCUS-015；FR-DASH-002；BL-FOCUS-004、BL-FOCUS-005；BL-DASH-001。

#### 业务流程

1. 完成相关到期补偿。
2. 读取唯一运行执行与最后可信点。
3. 计算本页是否仍有控制权。
4. 返回权威状态；不推进计时。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 完成相关失联、日/周期和旧运行代次补偿；必要写入先独立提交。
2. 读取最新控制指针和运行会话，聚合闭合段和开放段至T的专注值。
3. 根据真实会话加可选实例头计算是否本页控制；返回serverNow供显示锚定，GET不推进T。
4. 运行门禁未就绪返回503，UI显示恢复中；无执行则activeSession/activeSegment为null，仍可有暂停执行。

</details>

#### 接口设计

**参数位置：** Path：无；Query：无；Body：无。

| 位置 | 字段 | 类型 | 必填 | 约束/含义 |
|---|---|---|---|---|
| Header | X-Controller-Instance | UUID | 否 | 只用于计算isCurrentController；不授予控制权 |

**返回：** HTTP 200；data为[FocusStateView](#dto-focusstateview)。

### API-FOCUS-002 开始新一次任务执行

**接口：** `POST /api/v1/tasks/{taskId}/focus/start`

#### 需求分析

**目的：** 用户点击一个今日指定任务或本周无日期任务的“开始”；如另一任务运行，需要明确切换且保持唯一计时。

**入口：** PAGE-003 /today、PAGE-008 /tasks/:taskId、PAGE-009 /plans/week、PAGE-010 /plans/day。

**前置：** 任务未完成未删除，任务开始日已到；目标ACTIVE且未归档，阶段非PAUSED/DONE；当前安排可执行。

**追溯：** FR-FOCUS-001、FR-FOCUS-012、FR-FOCUS-015；BL-FOCUS-001、BL-FOCUS-005。

#### 业务流程

1. 核对任务、父链和当前安排资格。
2. 核对用户所见活动执行与控制代次。
3. 同事务暂停旧执行，打开新session和首段。
4. 提交新控制许可；页面从0正向计时。

**关键分支：** 同任务已有未结束执行 → 转恢复；控制快照变化 → 刷新后重新决定切换。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 按02建立幂等意图并补偿到期处理；持运行护栏、账户锁后重读任务父链、当前安排及版本。
2. 以expectedControlEpoch和expectedActiveSessionId核对用户所见快照；不允许未经知情切换新出现的第三项任务。
3. 本任务有RUNNING/PAUSED执行时返回SESSION_ALREADY_EXISTS，页面转恢复或详情，不重复开会话。
4. 有旧运行任务时验证可选finalConfirmation：有有效许可截至锁后实际时刻，无则截至原T；旧session/任务置PAUSED，原因SWITCH。
5. 同事务写新session和首segment；固定当前计划/时区/资格上界，started_at=last_confirmed_at；换代、绑定真实会话/本页并发许可；任务IN_PROGRESS。
6. 提交后才显示从零开始；旧新任务和计划版本同事务更新。任一步失败整条切换回滚，已独立完成的到期补偿不回滚。

</details>

### API-FOCUS-006 显式接管正在运行的执行

**接口：** `POST /api/v1/focus/takeover`

#### 需求分析

**目的：** 另一标签页或设备明确请求接管仍在运行的执行，原页面必须立即失去发送确认的能力。

**入口：** PAGE-012 /focus 的“接管”确认框。

**前置：** 同一账户合法会话，当前所见session仍RUNNING、控制代次未变，资格仍有效。

**追溯：** FR-FOCUS-012、FR-FOCUS-013；BL-FOCUS-001、BL-FOCUS-005。

#### 业务流程

1. 用户明确确认接管。
2. 重验RUNNING、任务资格和原代次。
3. 旧段止于T，同session另开当前段。
4. 控制换代并给本页许可。

**关键分支：** 旧段T到新段起点之间的空档不计；旧页许可立即失效。

<details>
<summary>展开完整业务规则与事务顺序</summary>

2. 持锁重验session版本、RUNNING、控制代次和执行资格；若已失联暂停，只能003恢复。
3. 旧开放段以已持久化T关闭，原因OWNER_TAKEOVER；不得将旧许可未确认空档补到现在。
4. 同一个session在锁后当前时刻打开新段并更换控制代次，绑定本页真实会话并签初始许可；旧新段无重叠。
5. 提交后本页才开始确认；旧页下一确认409 EXECUTION_CONTROL_LOST，停止估计和确认。

</details>

### API-FOCUS-007 提交一次可信执行确认

**接口：** `POST /api/v1/focus/confirm`

#### 需求分析

**目的：** 控制页持续确认仍在专注，只能按服务端时间推进可信点；网络重试不得重复增时或延长旧许可。

**入口：** PAGE-012 /focus 当前控制页内部每10秒确认。

**前置：** 真实会话、控制页、运行代次及活动session/segment全部匹配，现有许可接收与持锁时均未过期。

**追溯：** FR-FOCUS-005、FR-FOCUS-013、FR-FOCUS-015；BL-FOCUS-004、BL-FOCUS-005。

#### 业务流程

1. 请求到达时检查15秒许可。
2. 持账户锁后再次检查期限与控制归属。
3. 以数据库实际时刻推进T并补齐日归属。
4. 消费旧许可，返回下一许可。

**关键分支：** 到达时或获锁时任一步过期都不推进T；同键保持原T与期限。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 每10秒发一次；同页同时只保留一个未完成确认请求；观察页每2秒GET同步，不替控制页续命。
2. 接收时保存数据库可校验的到达时刻并验证15秒许可；取得护栏/账户锁后取数据库实际当前时刻再次校验，排队期间过期也拒绝。
3. 按原键检查幂等：已成功从DB-30.result_summary.confirmationResult返回原confirmedAt/原累计；下一许可另查DB-19并重验当前控制及原期限，不能以本次到达重新推进T或重发失效秘密。
4. 新确认验证owner、真实会话、页面、runtime/controlEpoch、活动对象、next_sequence、随机permit；全部成功后更新last_confirmed_at，不越资格上界。
5. 同事务补全日边界，消费旧许可，sequence+1，随机生成新许可，expires_at=新T+15秒；段/控制版本递增，session内容未变不必递增。
6. 任一校验失败不推进T；页面停止估计并刷新，超时扫描以原T关闭，健康服务应在最后T后45秒内呈现暂停。

</details>

### API-FOCUS-010 补齐既有异常末段终点

**接口：** `POST /api/v1/focus/segments/{segmentId}/adjust-end`

#### 需求分析

**目的：** 用户能确认异常中断后实际停止时刻，补齐已有末段并留痕，不能据此补录不存在的执行。

**入口：** PAGE-012 /focus 的异常中断修正框。

**前置：** 本人已闭合且interruption_repairable=true的该次中断末段；不得跨越主动暂停、后续恢复或其他执行。

**追溯：** FR-FOCUS-014；FR-HISTORY-009；BL-FOCUS-005；BL-COMMON-002。

#### 业务流程

1. 确认既有异常末段及版本。
2. 重算T下界和当前允许上界。
3. 验证新终点合法且不重叠。
4. 同事务改末段、追加修正事实、补日边界。

**关键分支：** 只修异常末段；主动暂停间隔和后续任何执行区间都不能覆盖。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 独立处理到期事项后持账户锁，按segment_id+user_id重读段、session及版本。
2. 检查已闭合、异常中断可修正、确为中断末段；用户主动暂停或正常完整结束不能开放回填。
3. 重新计算下界T与上界min(当前时刻、原资格上界、时区生效边界、后续任意本人段起点)，验证新旧不同、不覆盖恢复后的区间、无重叠。
4. 同事务只改该段ended_at/version，追加DB-20旧新终点/版本/理由/操作ID与修正当时固定日期时区，补DB-21必要边界。
5. 累计从源段重新求和或按差值展示；修正事件是留痕，不是另一份专注投入。失败保留全部原事实。

</details>

**目的：** 一个账户可以有多项暂停执行；需要分页取全某范围全部RUNNING/PAUSED，逐个处理后重试原业务。

**入口：** 退出/改密/归档/完成/删除的未结束执行处理框。

**前置：** 本人会话有效；范围对象本人可见，不能只取当前活动执行。

**追溯：** FR-FOCUS-002、FR-FOCUS-004；FR-AUTH-003、FR-AUTH-004；BL-FOCUS-002；BL-AUTH-003、BL-AUTH-004。

#### 业务流程

1. 验证范围类型和本人范围身份。
2. 合并当前安排或历史段关联的未结束执行。
3. 按startedAt/id升序分页。
4. 页面取全并逐个结束后重试原业务。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 验证scopeType/scopeId组合与归属；每次一个范围，不用多个父ID组合扩大或缩小。
2. ACCOUNT查询本人全部未结束；目标/阶段/任务按任务父链；WEEK/DAY使用当前安排或历史段关联的并集去重。
3. 状态只取RUNNING/PAUSED，按started_at ASC、id ASC分页；无许可，允许进入详情逐条结束。
4. 前端不能只处理第一页；取完hasMore=false后刷新原对象版本，再提交原命令，原命令持锁仍重验完整集合。

</details>

### API-FOCUS-012 取回仍有效的原控制许可

**接口：** `POST /api/v1/focus/permit/recover`

#### 需求分析

**目的：** 本页刚提交确认成功却丢失响应，需取回仍有效的原下一许可，不能凭观察数据续命。

**入口：** PAGE-012 /focus 确认响应丢失后的内部核实流程。

**前置：** 本页内存仍保存FOCUS-007原键和原确认参数，原意图成功，当前真实会话/页面/代次仍绑定。

**追溯：** FR-FOCUS-013、FR-FOCUS-015；BL-FOCUS-004、BL-FOCUS-005；BL-COMMON-002。

#### 业务流程

1. 核实原FOCUS-007意图已经成功。
2. 核对原指纹及当前会话/页面/代次。
3. 确认原序号恰为当前序号前一项。

4. 即使本恢复请求同键重放，仍重验当前控制/期限；换代或过期不返回旧秘密。
5. 首次start/resume/takeover响应丢失，使用对应原键原参重试002/003/006；本接口不能凭空发首许可，普通GET和COMMON-001也不发许可。

### API-HABIT-004 修改习惯规则

**接口：** `PATCH /api/v1/habits/{habitId}`

#### 需求分析

**目的：** 用户修改习惯内容，新规则当天立即生效，同时保留旧规则和今天已经完成的事实。

**入口：** PAGE-014 /habits/:habitId 的规则编辑表单。

**前置：** 本人未删除且非ENDED习惯；PAUSED可改规则但保持暂停。

**追溯：** FR-HABIT-003、FR-HABIT-004、FR-HABIT-005、FR-HABIT-006、FR-HABIT-007、FR-HABIT-018；BL-HABIT-003、BL-HABIT-006。

#### 业务流程

1. 合并PATCH后校验完整规则。
2. 结算过去日期并重验版本。
3. 值有变化才闭旧版、开新版、写节点。
4. 重评今日，保留已有完成。

**关键分支：** 已完成仍1/1；未完成按新规则重评；相同内容不造规则版。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 合并PATCH与当前规则后校验完整结果；至少提供一个内容字段，切换cycleType必须同时给weekdays；必填内容不能null，description/executionTime可null清空。
2. 先可靠结算过去日期；锁内重验习惯版本、未删除及可编辑状态，ENDED要求先reopen。
3. 新旧内容全部相同则无变化200，不生成新规则、事件或虚假版本。
4. 有实际变化：旧规则valid_to=当前时刻，新版revision+1/valid_from=同一时刻，插新星期、更新current_rule_id、追加RULE_CHANGED，同一事务提交。
5. 重新评估今日未完成due；已完成保留completed_at/completed_rule_id/due=true，不要求按新规则重做。
6. 过去已结算日整体不改，当前PAUSED不因修改变ACTIVE；同日多次改动保留节点，零长旧版本也保留。

</details>

**目的：** 用户只看今天需要执行的习惯，并保留今日完成后暂停或结束但尚未删除的只读完成项。

**入口：** PAGE-003 /today 的独立习惯区。

### API-HISTORY-001 查询范围汇总或逐日统计

**接口：** `GET /api/v1/history/statistics`

#### 需求分析

**目的：** 用户查询完整时间范围的完成数、真实投入和习惯完成率，可聚焦某目标/阶段而不混入全账户习惯。

**入口：** PAGE-015 /history 的汇总和按日图表。

**前置：** 日期范围合法、终点不晚于当前业务日；过滤父链一致。

**追溯：** FR-HISTORY-002、FR-HISTORY-008、FR-HISTORY-009、FR-HISTORY-010、FR-HISTORY-011；FR-FOCUS-006、FR-FOCUS-007、FR-FOCUS-008、FR-FOCUS-009；BL-HISTORY-001、BL-HISTORY-004、BL-HISTORY-005；BL-FOCUS-004；BL-HABIT-006。

#### 业务流程

1. 校验日期和目标/阶段范围。
2. 完成必要到期补偿后开启一致性快照。
3. 从完成、区间和习惯日事实汇总。
4. 返回SUMMARY或按日分页。

**关键分支：** 目标/阶段筛选不含个人习惯；习惯分母0返回null。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 校验范围和筛选父链，保留删除历史身份可访问；允许单次完整三年一致汇总，不新增366天上限。
2. 可靠处理相关过去习惯结算、时区/计划边界，再进入短只读一致性快照，不能分页多次加总冒充同一汇总。
3. 完成数读不可变task_completion.business_date的不同task；专注读段有效终点与原固定日边界求交，包含保留删除贡献。
4. 无目标/阶段筛选时，习惯按完成优先汇总；含今天则合并当前规则状态投影，即使今日尚无habit_day也不漏due。
5. 有goalId/stageId时仅统计对应任务完成/投入，habitScopeIncluded=false、habit两计数0、比例null，不能把个人习惯归入目标。
6. SUMMARY返回整个范围单对象；DAY按businessDate ASC分页，可补齐零值日期作图但不写假日结果；分母0比例null。
7. 读失败503且图表显示失败，预计耗时不进实际投入；修正事件本身不另加一次专注。

</details>
