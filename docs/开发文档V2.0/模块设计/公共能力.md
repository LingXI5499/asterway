# 04 公共能力与跨模块契约

> 项目：Asterway · 个人成长管理
> 文档版本：V2.0　编制日期：2026-10-22　状态：设计审阅稿
> 工程基点：`419be71af9e6b86846717f155d464e0ec5da1829`；软件版本：`0.1.0-SNAPSHOT`。

## 一、模块范围

这是工程支撑规范，不增加第十三个产品模块。common 提供中立机制，app 处理 HTTP、安全装配、调度及跨业务协调；八个业务工程保持数据写入所有权。

## 第一部分：业务逻辑

请求进入 → 认证/CSRF → 必要运行与恢复门禁 → 到期补偿 → 原意图结果核实 → 锁后版本、父链、归属和资格重验 → 核心事务 → 权威结果。重复请求不重复效果，未知结果不新建操作重做。系统处理 JOB-001～007 的完整流程见 A07。

## 第二部分：数据库设计

DB-03～05、DB-29～31、DB-33 是公共机制表：中立契约与端口归 common，具体锁、去重、outbox、审计和检查点持久适配归 app/infrastructure，迁移仍集中 app。框架会话与迁移历史 DB-34～36 分别由 app 的 Session 适配和 Flyway 管理，业务代码不手改历史。身份拥有 DB-32 安全变化本地依据，独立账本在数据库之外。完整字段、约束和删除规则见 A01/A13，不建立物理外键。

## 第三部分：接口设计

除业务接口外，公共结果查询是第 95 个唯一 HTTP 契约；完整请求、响应和错误如下。

#### 需求分析

写入可能已经提交，但页面没收到响应。用户需要核实原意图，避免重复改密、重复完成或错误显示失败。入口为全局“结果待确认”交互 UI-GLOBAL-08；本人有效会话可查本人原操作，管理操作还需具备当前对应权限。它是落实 NFR-REL-003/007 的通用工程接口，不另造 FR 编号。

#### 业务流程

1. 从当前会话取得稳定账户 UUID，构造本人 `USER:UUID` 作用域；不接受客户端指定 userId/scope。
2. 校验 operation 是真实写接口编号，与查询键一起定位原请求记录。
3. 重新校验原操作目前的角色及对象可见范围；撤销后的后台权限不能借此读出原后台结果。
4. 返回处理状态与安全摘要，不重做原业务，不签发旧 Cookie、CSRF、验证码或执行许可。
5. 未找到/已过期只说明结果查询不能确定，不能据此判定原动作未发生；页面继续查询业务事实，再由用户决定后续动作。

改密结果丢失且旧会话已失效时，先正常验证凭据重新登录，再查原意图，只核实、不再改密。退出同理不撤销重新登录后的新会话。匿名注册/登录先按03当前会话及同键协议处理，本接口不提供任意匿名结果检索。计时控制仍走05受控协议。

#### 接口设计

| 项目 | 约定 |
|---|---|
| 方法与路径 | GET /api/v1/operations/{idempotencyKey} |
| 权限 | 本人有效会话，任何角色均只查本人作用域；另重验原操作权限 |
| 请求头 | 浏览器自动携带同源会话Cookie；GET不传Idempotency-Key和CSRF写入头 |
| 请求体 | 无；不接受userId、scope或原请求秘密 |
| 成功 | 200，data为OperationResult |

| 位置 | 参数 | 类型 | 必填 | 约束 |
|---|---|---|---|---|
| Path | idempotencyKey | UUID字符串 | 是 | 原写请求的键，不是新的请求键 |
| Query | operation | string | 是 | 02～05定义的真实写接口编号，例如API-TASK-005；不能是任意字符串或GET编号 |

OperationResult 字段完整定义如下，响应按02统一外壳包装。

| 字段 | JSON类型 | 可空 | 含义 |
|---|---|---|---|
| operation | string | 否 | 原接口编号 |
| idempotencyKey | string(UUID) | 否 | 原意图键 |
| state | string枚举 | 否 | PROCESSING / SUCCEEDED / REJECTED |
| httpStatus | number | 是 | 已确定结果的HTTP状态；处理中为空 |
| resultCode | string | 是 | 已确定结果的业务code |
| effectApplied | boolean | 是 | 是否确认业务效果已应用；未定为空 |
| resultType | string | 是 | 原结果的安全资源类型摘要，不是Java类名 |
| resultId | string(UUID) | 是 | 可见的主要结果身份 |
| resourceIds | string(UUID)[] | 否 | 当前有权查看的相关身份；无则[] |
| versions | object | 否 | UUID键到十进制版本字符串；无则{} |
| createdAt | string(UTC) | 否 | 意图记录创建时刻 |
| updatedAt | string(UTC) | 否 | 最近状态变更时刻 |
| expiresAt | string(UTC) | 否 | 该结果查询记录的保留期限 |

请求示例（演示ID，仅用于解释契约）：

```http
GET /api/v1/operations/6bc2c57f-18a3-42d5-b21e-7195779351c4?operation=API-TASK-005
Accept: application/json
```

| HTTP/code | 具体触发 | 页面动作 |
|---|---|---|
| 400 VALIDATION_ERROR | Path不是UUID | 修复调用参数，原意图不变 |
| 401 AUTH_REQUIRED | 当前会话无效 | 先重新认证，不凭键恢复旧登录身份 |
| 403 FORBIDDEN | 原管理权限已撤销 | 不展示原受限资料，不绕过授权 |
| 404 OPERATION_RESULT_NOT_FOUND | 本人作用域无记录或记录已过期 | 显示不能确定，核实业务事实；不宣称未提交 |
| 422 VALIDATION_ERROR | operation不是定义的写接口编号 | 修复前端关联，保留原键 |
| 503 SERVICE_UNAVAILABLE | 无法读取/核实结果 | 保留待确认状态，稍后重查 |

失败示例（HTTP 404）：

```json
{"code":"OPERATION_RESULT_NOT_FOUND","message":"未找到可查询的操作结果，请继续核实业务状态","data":null,"traceId":"operation-query-missing"}
```

#### 数据操作

按本人作用域、operation、idempotency_key读取DB-30，映射其状态及result_summary。读取已过期结果不暴露；已删或无权对象只确认允许返回的原意图事实，资源身份和版本按当前授权裁剪。查询不更新原请求状态、不延长保留期限、不重新进入原事务，不从任意数据库列拼出秘密信息。

#### 分层实现步骤

1. `OperationResultController.get`绑定路径/查询，取得当前身份；与一般GET一致做权限检查。
2. `OperationResultQueryService.findOwned`读取去重记录并调用原操作的当前授权检查，映射安全结果；不会调用原写Service。
3. `RequestDedupMapper.selectVisibleResult`在XML中绑定作用域、操作、键及有效期；仅查需要的列。
4. 明确区分处理中、成功、明确拒绝和查不到，按上述HTTP/code组装；不返回缓存的旧认证响应。

#### 功能测试

| 输入与操作 | 预期结果 | 关联 |
|---|---|---|
| 完成任务响应丢失，使用原operation/key查询 | 返回SUCCEEDED；只存在一份完成事实，无第二次写入 | TEST-054 |
| 用户B查询用户A的相同key | 查不到A记录和对象资料 | TEST-055 |
| 管理员操作后被撤角色，再查询原管理结果 | 按当前权限拒绝，不泄露原资料 | TEST-060、064 |
| 结果保留期限已过，查询返回404 | 页面保持不能确定，先核实任务事实，不自动新键重做 | TEST-054 |
| 改密已提交并重登后核实原意图 | 确认原结果，不再次改密，不撤销新会话 | TEST-064 |

## 第四部分：类设计

| 规划位置 | 类/职责 | 依赖与边界 |
|---|---|---|
| common/context | 身份与业务日上下文 | 不承载领域对象 |
| common/error、exception、pagination | ErrorCode、CommonErrorCode、BusinessException、CursorPage | 中立契约，不依赖 Web/Security 或业务工程 |
| common/concurrency | 固定锁序及护栏端口 | 不代业务资格，不承载具体 SQL |
| common/idempotency | 原意图和结果的中立契约/端口 | 不保存凭据或正文 |
| common/event | 中立事件契约/端口 | 不决定目标结束，持久适配归 app |
| app/infrastructure | 护栏、去重、outbox、审计、检查点适配 | 只访问自身机制表，不直接写领域表 |
| app/web/contract | ApiResponse、ErrorData、Violation | HTTP 外壳与安全数据，data 承载响应 VO |
| app/web/error、web/filter | Advice、ApiErrorFactory/Writer、TraceIdFilter | 与安全入口共享响应契约，分别处理边界 |
| app/application | 跨模块命令与读前补偿 | 取得稳定上下文后调用公开能力 |
| app/security | 过滤链、CSRF、授权版本、会话适配 | 框架事务内无外键清理 |
| app/bootstrap | 运行代次和恢复门禁 | 未核实安全依据不开放 |
| app/scheduling | JOB 调度与补偿 | 重用业务用例，不拼跨域 SQL |

规划类尚未存在。现有真实启动类、POM 和配置见 09 的文件清单。核心事务和锁序细节、框架会话适配测试见 A09/A10。

## 五、模块设计一致性检查

逐请求授权、稳定锁序、原意图查询、核心提交、可靠消费和恢复门禁必须共同验证；单一机制通过不能代表整条业务链通过。
