## 一、模块范围

### 1.1 模块职责

目标完成条件的站内确认通知。通知可追踪，已读不等于目标已结束，过时条件不能推动结束。

### 1.2 对应功能清单

| 功能 | 名称 | 本模块承担部分 |
|---|---|---|
| FR-NOTICE-001 | 系统发送目标完成确认通知 | 任务完成条件事务→GOAL_CONDITION_MET事件→通知消费者 |
| FR-NOTICE-002 | 用户查看系统通知 | API-NOTICE-001、API-NOTICE-004 |
| FR-NOTICE-003 | 用户处理目标完成确认通知 | API-NOTICE-003、API-GOAL-007 |
| FR-NOTICE-004 | 用户标记通知已读 | API-NOTICE-002 |

### 1.3 模块依赖

| 依赖 | 使用原因 | 交互内容 | 失败处理 |
|---|---|---|---|
| 目标条件轮次和可靠事件 | 核对业务资格及形成统一结果 | 由 app 在同一上下文协调业务公开能力 | 依赖不可用按接口错误反馈；核心事务整体回滚 |
| common | 身份、时间、锁、幂等、错误及事件机制 | 明确上下文与固定锁序 | 恢复门禁未开放时拒绝相关写入 |
| PostgreSQL | 持久化与约束 | 本人数据和唯一性/排除约束 | 提交未知则保留原意图核实 |

## 第一部分：业务逻辑

### FR-NOTICE-001 系统发送目标完成确认通知

**触发：**调度、访问前补偿或内部事件。**发起者：**系统。

**前置：**本人有效身份或受控系统上下文；日期、对象和状态满足现行业务规则。

**输入：**当前状态、权威时刻和有效业务日，不接收客户端虚构完成事实。

**事件流：**核对身份和对象 → 按 A07 先补偿到期事实 → 执行 任务完成条件事务→GOAL_CONDITION_MET事件→通知消费者 → 形成结果或标准拒绝 → 留存必要事实及可追踪记录。

**规则与异常：**通知可追踪，已读不等于目标已结束，过时条件不能推动结束。 消费者暂时失败可补偿；条件失效后提示状态变化，不重复结束目标。 系统处理使用原业务身份去重，失败不提前推进检查点。

**执行结果：**系统发送目标完成确认通知；无权或依赖失败不伪装成空结果。

**关联验证：**TEST-020、043、052～054。

**关联功能/处理：**任务完成条件事务→GOAL_CONDITION_MET事件→通知消费者；**开发批次：**DEV-008、009、017。

### FR-NOTICE-002 用户查看系统通知

**触发、发起者与前置：**

**目的：** 用户查询离线期间也会保留的目标确认通知；动作可用性必须随最新目标/轮次计算。

**入口：** PAGE-016 /notifications 及站内通知入口。

**前置：** 仅站内通知，无邮件/短信/私信。

**追溯：** FR-NOTICE-002；FR-NOTICE-001；BL-NOTICE-001。

**输入：**采用本章第三部分 API-NOTICE-001 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 筛选本人通知。
2. 重验最新目标状态与条件轮次。
3. 计算当前可用动作。
4. 按createdAt/id倒序分页。

**关键分支：** 旧通知文字不能授权动作；已读与确认分开。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 按本人及未读/处理状态过滤，created_at DESC、id DESC分页，不因GET创建通知。
2. 读取目标最新状态、archived_at、condition_round和精确有效任务条件，计算canConfirm/canContinue及goalVersion。
3. 通知旧文字不能授权动作：已结束/归档/旧轮/条件失效则动作关闭，通知只读保留；必要失效补偿走统一用例。
4. read_at为空表示未读，不代表目标未结束；CONTINUED表示当前轮已处理，不因页面刷新再次提醒。
5. 通知尚在outbox重试时可以暂未出现，不能回滚已完成任务或给目标重新开轮；空列表与读失败分开。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

### FR-NOTICE-003 用户处理目标完成确认通知

**触发、发起者与前置：**

**目的：** 目标任务已全部完成，用户选择保持目标进行中，同一轮不再反复提醒。

**入口：** PAGE-016 /notifications 的“继续推进”。

**前置：** 本人通知PENDING，目标仍ACTIVE未归档且当前conditionRound及N>0,C=N仍有效。

**追溯：** FR-NOTICE-003；BL-NOTICE-001。

**输入：**采用本章第三部分 API-NOTICE-003 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 重验PENDING通知及最新目标条件。
2. 同轮有效才改CONTINUED。
3. 记录handledAt，必要时一并已读。
4. 保持目标ACTIVE，同轮不再提醒。

**关键分支：** 目标保持ACTIVE，当前轮次不变；同轮不重新提醒。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 核实原意图并持账户锁重读通知/目标；不能仅凭收到过通知就继续过期轮次。
2. 校验通知PENDING、goal有效、轮次相同、N>0且C=N；失效拒绝NOTIFICATION_EXPIRED，必要失效事实独立可靠更新。
3. action_state=PENDING→CONTINUED，handled_at=当前时刻；read_at为空则同时写已读。
4. 目标保持ACTIVE，completion_condition_met仍true、condition_round不变；不靠清false再刷新重发同轮通知。
5. 本版不再弹通知；以后任务条件失效再满足才开新轮；用户仍可从目标详情合法结束目标。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

### FR-NOTICE-004 用户标记通知已读

**触发、发起者与前置：**

**目的：** 用户只想消除未读标记，不能因为阅读把目标确认结束。

**入口：** PAGE-016 /notifications 的已读动作/打开通知。

**前置：** 本人通知可见，expectedVersion匹配；任何处理状态都允许仅已读。

**追溯：** FR-NOTICE-004；BL-NOTICE-001。

**输入：**采用本章第三部分 API-NOTICE-002 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 核实原意图并重验本人通知版本。
2. 首次已读写readAt。
3. 已读同状态不重复修改。
4. 返回最新通知和未读状态。

**关键分支：** 只消除未读标记，不改变actionState或目标。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 先核实幂等结果，账户锁内重验本人通知及expectedVersion。
2. read_at为空时写当前服务端时刻并递增version；已读且版本匹配时无变化成功，不覆盖首次read_at。
3. action_state/handled_at和目标状态完全不因已读改变；重新计算当前动作可用性后返回。
4. 提交后刷新未读数和列表，后续用户仍可继续或确认；失效通知也可以标已读。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

### 状态变化

| 当前状态 | 触发 | 目标状态 | 约束/失败反馈 |
|---|---|---|---|
| 条件成立 | 可靠消费 | 待确认 | 同轮唯一 |
| 待确认 | 阅读 | 已读 | 不代表目标结束 |
| 待确认/已读 | 条件失效或目标关闭 | 已失效/已确认 | 重验轮次，不重复结束 |

### 事务、并发与重复请求

核心事实与必要审计、去重结果及 outbox 同库提交。锁序遵循运行护栏、管理锁（如适用）、按稳定顺序排列的账户锁；锁后重验当前时刻、归属、父链和 expectedVersion。昂贵密码计算、外部网络和重度统计不占用账户短事务。读请求复用必要到期补偿，但补偿与随后可拒绝业务的提交边界必须明确。

同一次意图使用同一 Idempotency-Key；不同参数重用旧键返回冲突。响应丢失不新建意图自动重做。安全账本采用先独立意图、同库提交、再同步结果的协议，结果无法核实保持隔离，不声称跨存储原子提交。

### API-GOAL-007 确认完成或主动结束目标

**POST /api/v1/goals/{goalId}/close**

本人权限；写请求头按[公共规则](../附录/A04-目标计划接口与对象.md#11-路径权限请求头和基本类型)。Query：无。

| 位置 | 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| Path | goalId | UUID | 是 | 本人目标 |
| Body | expectedVersion | string | 是 | 目标当前版本 |
| Body | endType | enum | 是 | ALL_TASKS_CONFIRMED/USER_ENDED |
| Body | confirmed | boolean | 是 | 必须true |

返回：**HTTP 200 → [GoalCloseResult](../附录/A04-目标计划接口与对象.md#dto-goal)**。

## 第四部分：类设计

### 4.1 包结构

现有工程仅含包说明；以下为本模块的规划类，尚未实现。

```text
backend/notification/src/main/java/com/asterway/notification/
  api/NotificationApi.java           模块之间调用的 Java 公开能力
  api/model/                  公开 Command / Result / Snapshot，按用例创建
  api/error/                  本业务错误码和必要的带类型异常
  service/NotificationService.java   规则与本模块拥有数据的写入
  mapper/NotificationMapper.java     本模块数据访问或明确允许的只读投影
  model/                      内部存储/查询模型，不直接作为 HTTP 响应
backend/notification/src/main/resources/mapper/notification/NotificationMapper.xml
backend/app/src/main/java/com/asterway/app/
  web/notification/NotificationController.java
  web/notification/request/           请求 DTO：前端提交的允许字段
  web/notification/response/          响应 VO：返回前端的安全字段
  application/notification/NotificationUseCase.java   需要协调时创建
```

`request` 和 `response` 是 Java 包，分别存请求 DTO 和响应 VO；DTO/VO 是数据传输对象，不是额外 Maven 工程。请求 JSON 绑定为请求 DTO，Controller 调用用例/公开能力，业务结果映射为响应 VO，再放入统一 `ApiResponse.data`。`api` 指模块间 Java 调用契约，HTTP 路由集中在 app 的 Controller。

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper。只保留 insights 聚合事实、administration 授权账户摘要两类明确的只读投影例外，不取得其他模块写权。账户写入由 identity 处理，app 协调管理权限。
