## 第一部分：业务逻辑

### FR-HABIT-001 用户创建习惯

**触发、发起者与前置：**

**目的：** 用户建立独立于目标/任务的生活习惯，明确完成条件、周期和可选当地期望钟点。

**入口：** PAGE-013 /habits 的新增表单。

**前置：** 本人有效会话、已取得有效IANA时区；不需要存在目标、任务或计划。

**追溯：** FR-HABIT-001、FR-HABIT-004、FR-HABIT-005、FR-HABIT-006、FR-HABIT-007；BL-HABIT-001、BL-HABIT-006。

**输入：**采用本章第三部分 API-HABIT-001 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验名称、条件、类别与周期。
2. 取得当前时区及业务日。
3. 同事务创建习惯、首版规则、星期和CREATE节点。
4. 评估今日是否应执行后返回。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 校验必填文本、八类枚举及周期；DAILY星期必须空，WEEKLY至少选一个1～7，拒绝重复星期和非00秒。
2. 先处理本人到期时区/日结算，取得当前业务日和固定日边界。
3. 同事务预生成habit/rule身份，创建ACTIVE习惯、首版revision=1、规则星期和CREATE事件，current_rule_id指向首版。
4. 按创建当日规则形成必要habit_day或今日投影：今天应执行才可勾选，不生成创建前未完成日。
5. 同事务记录幂等结果；成功刷新启用清单/今日清单；executionTime仅描述，不能生成提醒/定时任务。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**入口：** PAGE-013 /habits 的启用/暂停/归档队列。

**前置：** 无需先有习惯记录。

**追溯：** FR-HABIT-002、FR-HABIT-008、FR-HABIT-009、FR-HABIT-014；BL-HABIT-002、BL-HABIT-006。

**输入：**采用本章第三部分 API-HABIT-002 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验状态、类别与分页条件。
2. 查询本人未删除习惯。
3. 合并当前规则与今日投影。
4. 按创建时刻/id倒序返回。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 确认当前业务日并先完成必要边界补偿；校验状态/类别与游标。
2. 按DB-22本人未删除习惯、status及当前规则category过滤，created_at DESC、id DESC分页。
3. 组装currentRule和今日权威投影；ACTIVE非执行日不隐藏，只设置due=false/canComplete=false。
4. PAUSED在独立队列、ENDED在归档；deleted_at非空在所有操作清单中排除。
5. 返回items=[]为该范围空态；过滤无结果与请求失败分别显示。

</details>

### FR-HABIT-003 用户修改习惯

**触发、发起者与前置：**

**目的：** 用户修改习惯内容，新规则当天立即生效，同时保留旧规则和今天已经完成的事实。

**入口：** PAGE-014 /habits/:habitId 的规则编辑表单。

**前置：** 本人未删除且非ENDED习惯；PAUSED可改规则但保持暂停。

**追溯：** FR-HABIT-003、FR-HABIT-004、FR-HABIT-005、FR-HABIT-006、FR-HABIT-007、FR-HABIT-018；BL-HABIT-003、BL-HABIT-006。

**输入：**采用本章第三部分 API-HABIT-004 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 合并PATCH后校验完整规则。
2. 结算过去日期并重验版本。
3. 值有变化才闭旧版、开新版、写节点。
4. 重评今日，保留已有完成。

**关键分支：** 已完成仍1/1；未完成按新规则重评；相同内容不造规则版。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 合并PATCH与当前规则后校验完整结果；至少提供一个内容字段，切换cycleType必须同时给weekdays；必填内容不能null，description/executionTime可null清空。
2. 先可靠结算过去日期；锁内重验习惯版本、未删除及可编辑状态，ENDED要求先reopen。
3. 新旧内容全部相同则无变化200，不生成新规则、事件或虚假版本。
4. 有实际变化：旧规则valid_to=当前时刻，新版revision+1/valid_from=同一时刻，插新星期、更新current_rule_id、追加RULE_CHANGED，同一事务提交。
5. 重新评估今日未完成due；已完成保留completed_at/completed_rule_id/due=true，不要求按新规则重做。
6. 过去已结算日整体不改，当前PAUSED不因修改变ACTIVE；同日多次改动保留节点，零长旧版本也保留。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-045～051、057；本接口功能测试：

状态：NOT_VERIFIED。

| 用例 | 输入/操作步骤 | 预期结果 |
|---|---|---|
| CHECK-HABIT-004-01 | 周日把每天未完成改为周一三五 | today从0/1变0/0；旧规则闭合，新版revision2，历史不变。 |
| CHECK-HABIT-004-02 | 今天已完成后改为非执行日或更高条件 | 仍1/1，completedRuleId指旧规则；不重复完成。 |
| CHECK-HABIT-004-03 | 完全相同字段保存两次 | 无新规则/事件；第二次不得制造版本节点。 |
| CHECK-HABIT-004-04 | 同一瞬间多次有效改动、两页旧版并发 | 先后节点保留，零长区间合法；旧版并发409 VERSION_CONFLICT。 |

### 状态变化

| 当前状态 | 触发 | 目标状态 | 约束/失败反馈 |
|---|---|---|---|
| 有效 | 暂停 | 暂停 | 保留已完成结果 |
| 暂停 | 恢复 | 有效 | 按当前规则及日期重验 |
| 有效/暂停 | 结束或删除 | 结束/删除 | 过去不重算；删除不可恢复 |

### 事务、并发与重复请求

核心事实与必要审计、去重结果及 outbox 同库提交。锁序遵循运行护栏、管理锁（如适用）、按稳定顺序排列的账户锁；锁后重验当前时刻、归属、父链和 expectedVersion。昂贵密码计算、外部网络和重度统计不占用账户短事务。读请求复用必要到期补偿，但补偿与随后可拒绝业务的提交边界必须明确。

同一次意图使用同一 Idempotency-Key；不同参数重用旧键返回冲突。响应丢失不新建意图自动重做。安全账本采用先独立意图、同库提交、再同步结果的协议，结果无法核实保持隔离，不声称跨存储原子提交。

## 第四部分：类设计

### 4.1 包结构

现有工程仅含包说明；以下为本模块的规划类，尚未实现。

```text
backend/habit/src/main/java/com/asterway/habit/
  api/HabitApi.java           模块之间调用的 Java 公开能力
  api/model/                  公开 Command / Result / Snapshot，按用例创建
  api/error/                  本业务错误码和必要的带类型异常
  service/HabitService.java   规则与本模块拥有数据的写入
  mapper/HabitMapper.java     本模块数据访问或明确允许的只读投影
  model/                      内部存储/查询模型，不直接作为 HTTP 响应
backend/habit/src/main/resources/mapper/habit/HabitMapper.xml
backend/app/src/main/java/com/asterway/app/
  web/habit/HabitController.java
  web/habit/request/           请求 DTO：前端提交的允许字段
  web/habit/response/          响应 VO：返回前端的安全字段
  application/habit/HabitCommandUseCase.java   需要协调时创建
```

`request` 和 `response` 是 Java 包，分别存请求 DTO 和响应 VO；DTO/VO 是数据传输对象，不是额外 Maven 工程。请求 JSON 绑定为请求 DTO，Controller 调用用例/公开能力，业务结果映射为响应 VO，再放入统一 `ApiResponse.data`。`api` 指模块间 Java 调用契约，HTTP 路由集中在 app 的 Controller。

|---|---|---|---|---|---|

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper。只保留 insights 聚合事实、administration 授权账户摘要两类明确的只读投影例外，不取得其他模块写权。账户写入由 identity 处理，app 协调管理权限。
