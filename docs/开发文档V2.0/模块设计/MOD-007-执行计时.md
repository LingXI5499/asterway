## 第一部分：业务逻辑

### FR-FOCUS-001 用户开始执行任务

**触发、发起者与前置：**

**目的：** 用户点击一个今日指定任务或本周无日期任务的“开始”；如另一任务运行，需要明确切换且保持唯一计时。

**入口：** PAGE-003 /today、PAGE-008 /tasks/:taskId、PAGE-009 /plans/week、PAGE-010 /plans/day。

**前置：** 任务未完成未删除，任务开始日已到；目标ACTIVE且未归档，阶段非PAUSED/DONE；当前安排可执行。

**追溯：** FR-FOCUS-001、FR-FOCUS-012、FR-FOCUS-015；BL-FOCUS-001、BL-FOCUS-005。

**输入：**采用本章第三部分 API-FOCUS-002 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 核对任务、父链和当前安排资格。
2. 核对用户所见活动执行与控制代次。
3. 同事务暂停旧执行，打开新session和首段。
4. 提交新控制许可；页面从0正向计时。

**关键分支：** 同任务已有未结束执行 → 转恢复；控制快照变化 → 刷新后重新决定切换。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 按02建立幂等意图并补偿到期处理；持运行护栏、账户锁后重读任务父链、当前安排及版本。
2. 以expectedControlEpoch和expectedActiveSessionId核对用户所见快照；不允许未经知情切换新出现的第三项任务。
3. 本任务有RUNNING/PAUSED执行时返回SESSION_ALREADY_EXISTS，页面转恢复或详情，不重复开会话。
4. 有旧运行任务时验证可选finalConfirmation：有有效许可截至锁后实际时刻，无则截至原T；旧session/任务置PAUSED，原因SWITCH。
5. 同事务写新session和首segment；固定当前计划/时区/资格上界，started_at=last_confirmed_at；换代、绑定真实会话/本页并发许可；任务IN_PROGRESS。
6. 提交后才显示从零开始；旧新任务和计划版本同事务更新。任一步失败整条切换回滚，已独立完成的到期补偿不回滚。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

### FR-FOCUS-002 用户结束本次任务执行

**触发、发起者与前置：**

**目的：** 用户确认结束当前或暂停的执行，使其不再阻塞后续退出、完成或归档；结束不会替用户完成任务。

**入口：** PAGE-012 /focus、退出/改密/归档/完成的未结束执行处理框。

**前置：** 本人RUNNING或PAUSED执行；用户明确confirmed=true。

**追溯：** FR-FOCUS-002；BL-FOCUS-002；BL-AUTH-003。

**输入：**采用本章第三部分 API-FOCUS-005 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 核对版本并要求confirmed=true。
2. RUNNING先关段；PAUSED直接采用旧段。
3. 记录session结束，保持任务未完成。
4. 后续完成/退出/归档另发请求。

**关键分支：** 结束session不会写任务完成；后续业务失败不撤销已结束执行。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 核实原意图结果后持锁重读session和版本；RUNNING先按004关闭，PAUSED直接沿用已保存段。
2. 有有效finalConfirmation才截到当前时刻；无则截T，已暂停到点击结束的间隔不计入。
3. session.status=ENDED，ended_at是实际结束动作时刻，pause_reason=null；任务保持未完成PAUSED。
4. 撤销本执行控制，返回permit=null；保留异常段可修正信息，允许用户采用已保存时间直接结束，不逼用户填写较晚终点。
5. 先结束各相关执行后刷新业务对象版本，再独立请求完成/退出/归档；后一请求失败不撤回已结束执行。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

### FR-FOCUS-003 用户继续执行未完成任务

**触发、发起者与前置：**

**目的：** 用户为暂停的同一次执行点击“继续”，需要保留旧累计，并重新检查当前计划。

**入口：** PAGE-008 /tasks/:taskId、PAGE-012 /focus。

**前置：** 本人session=PAUSED，任务父链与当前安排重新满足002资格；ENDED只能新开始。

**追溯：** FR-FOCUS-003、FR-FOCUS-012；FR-TASK-014；BL-FOCUS-002、BL-FOCUS-003、BL-FOCUS-005；BL-TASK-009。

**事件流：**

1. 核对暂停session版本与当前计划资格。
2. 核对控制快照，必要时暂停另一运行任务。
3. 在原session新增当前时刻开始的段。
4. 返回原累计与新许可。

**关键分支：** ENDED不能恢复；原计划过期时先重新安排。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 先核实原键成功结果，再持锁校验session版本和PAUSED状态。
2. 按任务现有安排重新校验资格；不能凭旧段的周/日期继续过期任务，先引导重新安排。
3. 核对控制快照并按002规则关闭其他运行任务；可选最终确认四项齐全且新鲜才补到锁后当前时刻。
4. 保留原session.started_at和旧段；新建从当前时刻起的新段，采用新安排上下文，换控制代次和许可；session和任务恢复IN_PROGRESS。
5. 返回该session全部段累计；暂停间隔不计入，新段从0累计但页面本次专注保留已确认值。

<details>

身份依赖真实框架会话、账户状态、安全版本及恢复代次。这里存会话标识不会使已清理或已撤销会话继续有效。

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper；insights 只读查询允许按固定表契约关联，不取得写所有权。
