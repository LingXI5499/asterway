# 04 MOD-006 日计划模块设计

> 项目：Asterway · 个人成长管理
> 文档版本：V2.0　编制日期：2026-10-22　状态：设计审阅稿
> 工程基点：`f4aca730c81eddd9ba6a8598f4a0df2cbde02bed`；软件版本：`0.1.0-SNAPSHOT`。

> 对应功能：FR-DAY-001, FR-DAY-002, FR-DAY-003, FR-DAY-005, FR-DAY-006, FR-DAY-007, FR-DAY-008, FR-DAY-009
> 工程归属：`backend/planning`；HTTP 和跨模块应用用例归 `backend/app`。

## 一、模块范围

### 1.1 模块职责

日身份、今日安排和过去只读。同一业务日身份唯一；改期后旧日不保留虚假的当前任务副本。

### 1.2 对应功能清单

| 功能 | 名称 | 本模块承担部分 |
|---|---|---|
| FR-DAY-001 | 用户创建日计划 | API-TASK-007（DAY，按需创建轻表） |
| FR-DAY-002 | 用户查看日计划 | API-PLAN-005、API-PLAN-006 |
| FR-DAY-003 | 用户将周计划任务加入日计划 | API-TASK-007（DAY） |
| FR-DAY-005 | 用户调整日计划任务顺序 | API-PLAN-008 |
| FR-DAY-006 | 用户将未完成任务重新安排到其他日期 | API-TASK-007 |
| FR-DAY-007 | 系统展示日计划任务状态 | API-PLAN-005、API-PLAN-006 |
| FR-DAY-008 | 用户删除日计划 | API-PLAN-010 |
| FR-DAY-009 | 系统展示日计划未完成待处理项 | API-PLAN-011；JOB-003 |

### 1.3 模块依赖

| 依赖 | 使用原因 | 交互内容 | 失败处理 |
|---|---|---|---|
| 周计划、任务和执行 | 核对业务资格及形成统一结果 | 由 app 在同一上下文协调业务公开能力 | 依赖不可用按接口错误反馈；核心事务整体回滚 |
| common | 身份、时间、锁、幂等、错误及事件机制 | 明确上下文与固定锁序 | 恢复门禁未开放时拒绝相关写入 |
| PostgreSQL | 持久化与约束 | 本人数据和唯一性/排除约束 | 提交未知则保留原意图核实 |

## 第一部分：业务逻辑

### FR-DAY-001 用户创建日计划

**触发、发起者与前置：**

统一处理加入周、指定日、跨周迁移、取消指定日及回池，不复制任务。

**入口：** 任务池/任务详情/今日看板/待处理 → 安排抽屉。**前置：** 未删除未DONE；父目标可管理、阶段未DONE，PAUSED阶段仍可规划。

**依据：** FR-TASK-010、FR-WEEK-003、FR-WEEK-004、FR-WEEK-005、FR-DAY-001、FR-DAY-003、FR-DAY-006、FR-DASH-007；BL-TASK-008、BL-WEEK-002、BL-WEEK-003、BL-DAY-001、BL-DAY-004。

**输入：**采用本章第三部分 API-TASK-007 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 按destination严格校验互斥日期：POOL无日期；WEEK只weekStartDate；DAY只planDate；不接收任意周日身份。
2. 锁内重读任务/父状态/版本及旧安排；WEEK所选周至少一天不早于目标/任务开始，DAY不早于两者开始日。预计结束与dueDate均不作为重排硬上界。
3. 目标周期身份按(user_id,week_start_date)/(user_id,plan_date)唯一取得；必要时创建/复用归档身份，日必属同一周。
4. 实际去向变化且本任务RUNNING时，验证可选finalConfirmation后暂停：有确认保存确认点，无确认截旧T；段保留旧计划/时区上下文。
5. 在同一事务更新唯一task_assignment或POOL删除；DAY填新日身份，WEEK清日身份，清除旧pending四字段；计划队列末尾排序。
6. 更新task与新旧周日版本，旧日/周不留独立“已改期/原未完成”任务；focus_session仍同一本次、paused累计保留。 若相同去向没有实际变化则返回现状，不因重复保存暂停运行任务或重复增版本；提交后刷新所有affectedPlans与任务池。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-024～029、039～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 今天已计20分钟任务迁到10月21日 | 预期旧日无卡片、新日1项、session为PAUSED、累计20分钟仍归今天。 |
| DAY改WEEK且周一起点相同 | 预期dailyPlanId=null，周无日期队列1项，旧日任务消失、历史段日身份不变。 |
| 旧周PENDING迁本周DAY | 预期仍同taskId、pending四字段清空、旧周不留副本；POOL再清全部当前关系。 |
| 目标10月20日开始，DAY选10月19日 | 预期422 PLAN_DATE_BEFORE_START，旧安排与运行状态不因本命令部分改变。 |

**关联功能/处理：**API-TASK-007（DAY，按需创建轻表）；**开发批次：**DEV-006、009、010。

### FR-DAY-002 用户查看日计划

**触发、发起者与前置：**

打开具体一天的安排、完成和真实投入，明确日计划为空状态。

**入口：** 日历日期点击、今日计划。**前置：** planDate合法；过去日只读，GET不自动建空日身份。

**依据：** FR-DAY-002、FR-DAY-007；BL-DAY-001、BL-DAY-005、BL-HISTORY-002。

**输入：**采用本章第三部分 API-PLAN-005 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 从planDate推导周一，按本人/日期查日身份与可能已存在的周身份。
2. 无日身份返回exists=false、id/version=null；若周身份存在可返回weeklyPlanId，否则null，不能写空日行。
3. 有日身份仅组合该日当前安排和scheduled_date对应完成事实；本周无日期任务不混进日清单。
4. 按日队列顺序及完成时间稳定展示；过去/归档为readOnly，真实投入含迁出任务的原日贡献。
5. 页面无安排显示空状态，网络/服务错误显示加载失败，不能把错误伪装为0投入。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-024～029、039～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 本周有周计划但今天无日身份 | 预期exists=false、id/version=null、weeklyPlanId有值、不插日行。 |
| 本周无日期任务有20分钟实际投入 | 日任务清单不出现该任务，实际按日期统计仍可从HISTORY查询。 |
| 已迁出昨日任务 | 昨日清单无重复卡片，原日执行投入仍可查，readOnly=true。 |

**关联功能/处理：**API-PLAN-005、API-PLAN-006；**开发批次：**DEV-006、009、010。

### FR-DAY-005 用户调整日计划任务顺序

**触发、发起者与前置：**

保存同一天当前未完成任务的手动顺序。

**入口：** 今日日计划/未来日 → 拖动任务。**前置：** 今天/未来日与周身份均未归档；提交日计划version。

**依据：** FR-DAY-005；BL-DAY-003。

**输入：**采用本章第三部分 API-PLAN-008 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 锁内校验日→周同账户关系、日期非过去及两个归档标记，核日版本。
2. 重查当前日全部有效未完成安排；提交集合不能包含其他日、周无日期或完成项。
3. 按数组更新唯一安排行顺序及version，日/周version整体更新。
4. 不改任务内容、优先级、完成和投入；相同完整顺序无变化可不增版本。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-024～029、039～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 今天A、B两任务提交[B,A] | 预期日version+1、周version+1、安排顺序0/1。 |
| 把同周另一日C混入 | 预期422 ORDER_MEMBERS_CHANGED，日周版本与顺序不变。 |
| 昨天日计划拖动请求 | 预期422 PAST_PLAN_READ_ONLY，页面无排序控件。 |

**关联功能/处理：**API-PLAN-008；**开发批次：**DEV-006、009、010。

| 已迁出昨日任务 | 昨日清单无重复卡片，原日执行投入仍可查，readOnly=true。 |

### FR-DAY-008 用户删除日计划

**触发、发起者与前置：**

取消一天的具体日期，任务仍保留所属周；已有事实归档保留。

**入口：** 日计划 → 删除日安排确认。**前置：** 本人日与周归属一致；该日全部当前或历史关联执行已结束。

**依据：** FR-DAY-008；BL-DAY-007、BL-HISTORY-005。

**输入：**采用本章第三部分 API-PLAN-010 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 锁内查日/周、版本与全部历史关联执行，包含已迁出任务的PAUSED。
2. 清当前任务daily_plan_id，保留weekly_plan_id，把条目移入该周无日期队列末尾；不是删除任务或撤销周安排。
3. 本周PENDING DAY解除日期后可变ACTIVE且pending四字段清空；若所属周已经过期，则统一PENDING WEEK并保留真实周边界依据。
4. 无必要历史的日可DELETED，有完成/执行事实或必须保留的过去身份则ARCHIVED；已完成结果不可清除。
5. 日、周、任务与安排版本同事务；过去仅清理当前关系/归档历史，绝不编辑已发生顺序、完成或时间。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-024～029、039～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 本周今天2项未完成，无执行完成 | 删除日后2项仍同周无日期、clearedDayAssignmentCount=2、returnedToPool=0。 |
| 旧周PENDING DAY任务清日 | 预期仍同一PENDING WEEK，不能在旧周直接执行。 |
| 有已结束执行20分钟 | 预期ARCHIVED、原日投入和完成事实保留，currentAssignmentRemoved=false。 |

**关联功能/处理：**API-PLAN-010；**开发批次：**DEV-006、009、010。

### FR-DAY-009 系统展示日计划未完成待处理项

**触发：**调度、访问前补偿或内部事件。**发起者：**系统。

**前置：**本人有效身份或受控系统上下文；日期、对象和状态满足现行业务规则。

**输入：**当前状态、权威时刻和有效业务日，不接收客户端虚构完成事实。

**事件流：**核对身份和对象 → 按 A07 先补偿到期事实 → 执行 API-PLAN-011；JOB-003 → 形成结果或标准拒绝 → 留存必要事实及可追踪记录。

**规则与异常：**同一业务日身份唯一；改期后旧日不保留虚假的当前任务副本。 跨周日身份、重复安排或试图改写过去结果时拒绝；取消保持原安排。 系统处理使用原业务身份去重，失败不提前推进检查点。

**执行结果：**系统展示日计划未完成待处理项；无权或依赖失败不伪装成空结果。

**关联验证：**TEST-024～029、039～044。

**JOB-003 详细事件流：**

1. 从 PLAN_DAY/PLAN_WEEK 检查点找到最早未完成绝对边界，按保存的 zone_period_id 解释当时日/周，不用当前设备时区重新推算。
2. 取得账户锁，完成到该边界必须发生的可信计时截断；正在执行但执行资格在边界结束的段不能跨过原资格边界持续累计。
3. 对该日/周仍然存在的未完成安排逐个重验任务、父目标、计划归属。已完成任务的安排已由完成用例移除，不新增待处理；已迁出原周期的任务不重复处理。
4. 日资格结束时，将同一 task_assignment 标为 PENDING，pending_kind=DAY，保存原日日期和绝对边界。保留真实执行及原归属，不新建下一日安排。
5. 周资格结束时，同一安排升级/设为 PENDING、pending_kind=WEEK，保存该周起点和周末绝对边界；已经 DAY 待处理的仍只有同一个 task_id 身份。
6. 更新该边界检查点，业务结果与游标同事务提交。日周恰逢同一绝对边界时，按同账户一致次序处理，最终待处理含义为周已结束；不能遗留可继续本周执行的假资格。
7. 用户之后从待处理或当前任务入口选择新周/新日/返回池，复用 API-TASK-007；成功后原待处理状态消失，过去投入不移动。

**关联功能/处理：**API-PLAN-011；JOB-003；**开发批次：**DEV-006、009、010。

### 状态变化

| 当前状态 | 触发 | 目标状态 | 约束/失败反馈 |
|---|---|---|---|
| 日日期位于所属周内；本人身份与任务资格满足。 | 本章动作 | 已提交结果 | 重验版本、归属和日期；只读查询不改变业务事实 |

### 事务、并发与重复请求

核心事实与必要审计、去重结果及 outbox 同库提交。锁序遵循运行护栏、管理锁（如适用）、按稳定顺序排列的账户锁；锁后重验当前时刻、归属、父链和 expectedVersion。昂贵密码计算、外部网络和重度统计不占用账户短事务。读请求复用必要到期补偿，但补偿与随后可拒绝业务的提交边界必须明确。

同一次意图使用同一 Idempotency-Key；不同参数重用旧键返回冲突。响应丢失不新建意图自动重做。安全账本采用先独立意图、同库提交、再同步结果的协议，结果无法核实保持隔离，不声称跨存储原子提交。

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper；insights 只读查询允许按固定表契约关联，不取得写所有权。
