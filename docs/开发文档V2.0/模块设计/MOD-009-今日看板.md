# 04 MOD-009 今日看板模块设计

> 项目：Asterway · 个人成长管理
> 文档版本：V2.0　编制日期：2026-10-22　状态：设计审阅稿
> 工程基点：`27661335d458bc74294c6c3cc303649a175eddc9`；软件版本：`0.1.0-SNAPSHOT`。

> 对应功能：FR-DASH-001, FR-DASH-002, FR-DASH-003, FR-DASH-004, FR-DASH-005, FR-DASH-006, FR-DASH-007, FR-DASH-008, FR-DASH-009
> 工程归属：`backend/insights`；HTTP 和跨模块应用用例归 `backend/app`。

## 一、模块范围

### 1.1 模块职责

本人今日事实、当前安排和下一步展示。有任务时可找到下一步，无数据时出现规划入口；失败不展示为零。

### 1.2 对应功能清单

| 功能 | 名称 | 本模块承担部分 |
|---|---|---|
| FR-DASH-001 | 用户查看今日任务 | API-DASH-002（TODAY_TASKS） |
| FR-DASH-002 | 用户查看今日任务执行情况 | API-DASH-001、API-DASH-002、API-FOCUS-001 |
| FR-DASH-003 | 用户查看今日应执行习惯 | API-DASH-003 |
| FR-DASH-004 | 用户查看多个进行中目标的概览 | API-DASH-002（GOALS） |
| FR-DASH-005 | 用户按目标筛选今日任务 | API-DASH-002（goalId） |
| FR-DASH-006 | 用户按任务状态筛选今日任务 | API-DASH-002（status） |
| FR-DASH-007 | 用户从今日看板重新安排未完成任务 | API-TASK-007 |
| FR-DASH-008 | 用户查看本周未指定日期的任务 | API-DASH-002（WEEK_FLEXIBLE） |
| FR-DASH-009 | 用户查看未完成计划待处理项 | API-DASH-002（PENDING） |

### 1.3 模块依赖

| 依赖 | 使用原因 | 交互内容 | 失败处理 |
|---|---|---|---|
| 目标、计划、执行、习惯和通知 | 核对业务资格及形成统一结果 | 由 app 在同一上下文协调业务公开能力 | 依赖不可用按接口错误反馈；核心事务整体回滚 |
| common | 身份、时间、锁、幂等、错误及事件机制 | 明确上下文与固定锁序 | 恢复门禁未开放时拒绝相关写入 |
| PostgreSQL | 持久化与约束 | 本人数据和唯一性/排除约束 | 提交未知则保留原意图核实 |

## 第一部分：业务逻辑

### FR-DASH-001 用户查看今日任务

**触发、发起者与前置：**

**目的：** 各看板区域独立分页，并按本人目标和任务状态筛选；重新安排复用统一任务迁移。

**入口：** PAGE-003 /today 的今日/本周无日期/待处理/目标区域。

**前置：** 可选goalId必须本人可见；view明确指定。

**追溯：** FR-DASH-001、FR-DASH-004、FR-DASH-005、FR-DASH-006、FR-DASH-007、FR-DASH-008、FR-DASH-009；BL-DASH-001、BL-DASH-002、BL-DASH-003。

**输入：**采用本章第三部分 API-DASH-002 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验view、目标和任务状态筛选。
2. 按view读取今日、周无日期、待处理或目标。
3. 使用该view自己的稳定游标分页。
4. 改期动作复用TASK-007。

**关键分支：** 四个view不共用游标；GOALS不接收任务status。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 校验view及条件组合，先完成相关到期补偿，过滤变化重置游标。
2. TODAY_TASKS复用04日清单：仅今日指定安排及今日固定日完成项，同任务去重；不得将周无日期任务冒充今日安排。
3. WEEK_FLEXIBLE仅本周有效未完成无日期安排；已完成无日期任务去本周历史/完成统计，不重复留待执行卡。
4. PENDING按同一task_assignment唯一待处理身份展示；GOALS仅当前未归档ACTIVE目标，带精确进度和保留历史投入。
5. 任务按队列sortOrder/taskId；待处理pendingBoundaryAt/taskId；目标createdAt/id稳定排序；四种view游标互不通用。
6. 点击改期调用04 API-TASK-007，成功才刷新旧新清单/概览；GET筛选不修改任务。空态、筛选无结果和失败三态分开。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-044、067～070；本接口功能测试：

状态：NOT_VERIFIED。

| 用例 | 输入/操作步骤 | 预期结果 |
|---|---|---|
| CHECK-DASH-002-01 | TODAY_TASKS查询，同时存在周无日期/待处理任务 | 只返回今日固定清单；另两个view分别可查。 |
| CHECK-DASH-002-02 | 筛选goalId=U2目标、GOALS带status=DONE | 404或422，不能返回其他账户或忽略矛盾条件。 |
| CHECK-DASH-002-03 | task改期成功后回原今日清单 | 原安排条目消失，新日/周出现，原日历史投入保留。 |
| CHECK-DASH-002-04 | 分页后改变status但仍使用旧cursor | 422，前端重新取第一页。 |

### FR-DASH-002 用户查看今日任务执行情况

**触发、发起者与前置：**

**目的：** 用户进入系统先看到今天任务/习惯完成、真实投入、可推进目标及待处理数量，数字须来自同一事实时点。

**入口：** PAGE-003 /today 概览卡片。

**前置：** 有效时区；没有任务仍能展示习惯。

**追溯：** FR-DASH-001、FR-DASH-002、FR-DASH-003、FR-DASH-004、FR-DASH-008、FR-DASH-009；BL-DASH-001；BL-HISTORY-004。

**输入：**采用本章第三部分 API-DASH-001 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 完成本次读取所需边界补偿。
2. 在同一只读快照取得当前业务日。
3. 分别汇总任务、习惯、专注、通知与目标。
4. 返回完整卡片；核心读取失败则报错。

**关键分支：** 今日固定任务、周无日期和待处理分别计数；失败不能返回假零。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 先可靠完成相关目标开始/延期、日周计划结束、习惯结算和时区生效补偿。
2. 以短只读一致性快照取得businessDate/zoneId/serverNow和各计数，不边查边使用不同事务的数据。
3. todayTaskCount=今日固定有效安排任务与今日真实完成任务ID的去重并集；todayCompletedCount按今日完成事实；周无日期、待处理、习惯各自计数。
4. 今日习惯统计包含删除/暂停/结束前已有完成1/1；未完成按当前规则状态投影；投入按DB-18与21求交，不使用浏览器秒表。
5. 仅ACTIVE且未归档目标计activeGoalCount；通知按read_at为空计未读。
6. 核心查询失败返回503，不返回成功全零；可采用通知区独立加载，但当前精确DTO成功时所有数值必须真实。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-044、067～070；本接口功能测试：

状态：NOT_VERIFIED。

| 用例 | 输入/操作步骤 | 预期结果 |
|---|---|---|
| CHECK-DASH-001-01 | 今日固定A/B、今日完成C、周无日期D、待处理E | todayTaskCount=3，completed=1，flexible=1，pending=1；D/E不混入today。 |
| CHECK-DASH-001-02 | 今日未完成A移到明天但上午有10分钟投入 | todayTaskCount减1，原日投入仍10分钟。 |
| CHECK-DASH-001-03 | 习惯今日完成后删除 | 不在今日操作清单，统计due=1/completed=1。 |
| CHECK-DASH-001-04 | 核心DB查询超时 | 503，页面显示加载失败，不能显示全零概览。 |

### FR-DASH-003 用户查看今日应执行习惯

**触发、发起者与前置：**

**目的：** 用户只看今天需要执行的习惯，并保留今日完成后暂停或结束但尚未删除的只读完成项。

**入口：** PAGE-003 /today 的独立习惯区。

**前置：** 今天按服务端生效时区判断。

**追溯：** FR-DASH-003；FR-HABIT-013、FR-HABIT-014；BL-DASH-001；BL-HABIT-005、BL-HABIT-006。

**输入：**采用本章第三部分 API-DASH-003 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 取得服务端今天。
2. 纳入今日应做ACTIVE习惯。
3. 补入今日已完成且未删除的暂停/结束项。
4. 返回独立清单，完成调用HABIT-010。

**关键分支：** 今日完成后暂停/结束可只读显示；删除项仅保留统计贡献。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 完成必要日/时区补偿后取得当前业务日；按本人和可选类别查习惯。
2. 纳入未删除ACTIVE且今日应执行项；另纳入今日已完成后PAUSED/ENDED但未删除项，标明只读状态。
3. ACTIVE非执行日仅在完整习惯列表查看，删除项不出操作清单；删除前今日完成贡献仍进DASH-001/HISTORY-001。
4. 按created_at ASC、id ASC分页；未完成按钮调用HABIT-010，成功才勾选，已完成没有取消勾选入口。

</details>

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-044、067～070；本接口功能测试：

状态：NOT_VERIFIED。

| 用例 | 输入/操作步骤 | 预期结果 |
|---|---|---|
| CHECK-DASH-003-01 | ACTIVE应做A、非执行日B、已完成后PAUSED的C、已完成后删除D | 清单A/C，C只读；B在完整列表，D仅保留统计贡献。 |
| CHECK-DASH-003-02 | 无任务但有习惯 | 任务区空态，习惯区仍正常可操作。 |
| CHECK-DASH-003-03 | 勾选时规则被其他页改动 | HABIT-010返回RULE_CHANGED，刷新新规则，不能乐观保留勾选。 |

| 位置 | 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| Path | taskId | UUID | 是 | 本人任务 |
| Body | expectedVersion | string | 是 | 任务当前版本 |
| Body | destination | enum | 是 | POOL/WEEK/DAY |
| Body | weekStartDate | date | 条件 | 仅WEEK必填；周一且本周或未来 |
| Body | planDate | date | 条件 | 仅DAY必填；今天或未来，推导周一 |
| Body | finalConfirmation | FinalConfirmation或null | 否 | 当前运行页可选；完整结构见2.1 |

返回：**HTTP 200 → [TaskAssignmentResult](../附录/A04-目标计划接口与对象.md#dto-stage-task)**。
特有失败：409 VERSION_CONFLICT、STATE_CONFLICT、EXECUTION_CONTROL_LOST；422 VALIDATION_ERROR、PLAN_DATE_BEFORE_START。原来 PENDING 可以通过本接口处理，不要求编辑过去计划。 共同失败见[02错误目录](../附录/A02-公共接口规范.md#5-统一错误目录)。

## 第四部分：类设计

### 4.1 包结构

现有工程仅含包说明；以下为本模块的规划类，尚未实现。

```text
backend/insights/src/main/java/com/asterway/insights/
  api/DashboardApi.java           模块之间调用的 Java 公开能力
  api/model/                  公开 Command / Result / Snapshot，按用例创建
  api/error/                  本业务错误码和必要的带类型异常
  service/DashboardService.java   查询口径与只读投影，不写业务事实
  mapper/DashboardMapper.java     本模块数据访问或明确允许的只读投影
  model/                      内部存储/查询模型，不直接作为 HTTP 响应
backend/insights/src/main/resources/mapper/insights/DashboardMapper.xml
backend/app/src/main/java/com/asterway/app/
  web/insights/DashboardController.java

  web/insights/response/          响应 VO：返回前端的安全字段
  application/insights/DashboardQueryUseCase.java   需要协调时创建
```

`request` 和 `response` 是 Java 包，分别存请求 DTO 和响应 VO；DTO/VO 是数据传输对象，不是额外 Maven 工程。请求 JSON 绑定为请求 DTO，Controller 调用用例/公开能力，业务结果映射为响应 VO，再放入统一 `ApiResponse.data`。`api` 指模块间 Java 调用契约，HTTP 路由集中在 app 的 Controller。

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper。只保留 insights 聚合事实、administration 授权账户摘要两类明确的只读投影例外，不取得其他模块写权。账户写入由 identity 处理，app 协调管理权限。
