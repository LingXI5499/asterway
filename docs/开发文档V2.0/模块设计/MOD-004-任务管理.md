> 文档版本：V2.0　编制日期：2026-10-22　状态：设计审阅稿

> 对应功能：FR-TASK-001, FR-TASK-002, FR-TASK-003, FR-TASK-004, FR-TASK-005, FR-TASK-006, FR-TASK-007, FR-TASK-008, FR-TASK-009, FR-TASK-010, FR-TASK-011, FR-TASK-012, FR-TASK-013, FR-TASK-014

## 一、模块范围

### 1.1 模块职责

任务规划、完成事实、删除和重新安排。完成形成唯一事实；已完成任务不恢复未完成，已有投入仍按发生日保留。

### 1.2 对应功能清单

| 功能 | 名称 | 本模块承担部分 |
|---|---|---|
| FR-TASK-001 | 用户创建任务 | API-TASK-001 |
| FR-TASK-002 | 用户查看任务列表 | API-TASK-002 |
| FR-TASK-003 | 用户查看任务详情 | API-TASK-003 |
| FR-TASK-004 | 用户修改任务 | API-TASK-004 |
| FR-TASK-005 | 用户删除任务 | API-TASK-006 |
| FR-TASK-006 | 用户设置任务优先级 | API-TASK-001、API-TASK-004 |
| FR-TASK-007 | 用户设置任务预计耗时 | API-TASK-001、API-TASK-004 |
| FR-TASK-008 | 系统展示任务截止日期逾期状态 | API-TASK-002、API-TASK-003 |
| FR-TASK-009 | 用户完成任务 | API-TASK-005 |
| FR-TASK-010 | 用户重新安排未完成任务 | API-TASK-007 |
| FR-TASK-011 | 用户查看任务累计实际耗时 | API-TASK-003、API-HISTORY-001 |
| FR-TASK-012 | 用户查看任务执行历史 | API-TASK-008、API-FOCUS-008、API-FOCUS-009 |
| FR-TASK-013 | 用户暂停任务 | API-FOCUS-004 |
| FR-TASK-014 | 用户恢复暂停任务 | API-FOCUS-003 |

### 1.3 模块依赖

| 依赖 | 使用原因 | 交互内容 | 失败处理 |
|---|---|---|---|
| 阶段、计划、执行和通知 | 核对业务资格及形成统一结果 | 由 app 在同一上下文协调业务公开能力 | 依赖不可用按接口错误反馈；核心事务整体回滚 |
| common | 身份、时间、锁、幂等、错误及事件机制 | 明确上下文与固定锁序 | 恢复门禁未开放时拒绝相关写入 |
| PostgreSQL | 持久化与约束 | 本人数据和唯一性/排除约束 | 提交未知则保留原意图核实 |

## 第一部分：业务逻辑

### FR-TASK-001 用户创建任务

**触发、发起者与前置：**

在阶段下新增独立可执行任务，先进入任务池。

**入口：** 阶段详情 → 新建任务。**前置：** 阶段未删除未DONE；父目标PENDING/ACTIVE且未归档，PAUSED阶段可规划。

**依据：** FR-TASK-001、FR-TASK-006、FR-TASK-007；BL-TASK-001、BL-TASK-004、BL-GOAL-007。

**输入：**采用本章第三部分 API-TASK-001 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 验证输入及父对象归属/状态，不能在body接收stageId/goalId、status、计划或完成字段。
2. 插入task，status=NOT_STARTED，预计耗时与任务日期按输入保存，不创建当前安排和执行。
3. 重新计算当前有效N/C，更新stage与goal版本；新任务使旧全部完成条件下降时失效旧轮确认依据。
4. 任务与条件变化/outbox依据一起提交；返回currentAssignment/execution/completion=null，提示先加入周计划。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-015、018～022、028、030～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 创建HIGH、预计1800秒且无日期任务 | 预期201、NOT_STARTED、无安排无执行、实际0。 |
| estimatedSeconds="0"或priority="URGENT" | 预期422，任务及父版本不改。 |
| 原目标2/2已待确认，新增未完成任务 | 预期变2/3，旧通知条件失效且不自动结束目标。 |

**关联功能/处理：**API-TASK-001；**开发批次：**DEV-005～009。

### FR-TASK-002 用户查看任务列表

**触发、发起者与前置：**

从任务池、已安排、待处理、全部有效或历史范围查找同一任务。

**入口：** 任务页范围标签、目标/阶段筛选、搜索。**前置：** 账户可用；筛选对象属于本人且goalId/stageId真实匹配。

**依据：** FR-TASK-002、FR-TASK-008；BL-TASK-002、BL-TASK-005、BL-HISTORY-005。

**输入：**采用本章第三部分 API-TASK-002 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验筛选归属与父子一致性，补做已过日期边界后查询。
2. POOL要求未完成未删除、无安排行且父对象可管理；DONE无安排也不能回池。
3. PLANNED取有当前安排行的有效任务；PENDING取安排行status=PENDING；ALL取全部未删除含父归档/结束只读项。
4. HISTORY取有执行/完成或保留删除身份的任务，允许deleted_at非空；物理删除且无事实的身份不会出现。
5. 按updated_at/id倒序分页，构造当前安排、执行摘要、动作资格及截止逾期标识。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-015、018～022、028、030～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| DONE任务安排行已删除，scope=POOL | 预期不出现；scope=ALL可读但不可执行。 |
| dueDate=10月17日未DONE，今天10月18日 | 预期isDeadlineOverdue=true，仍允许合法重排。 |
| goalId为本人A、stageId属于本人B | 预期422关系不符；他人ID统一404。 |

**关联功能/处理：**API-TASK-002；**开发批次：**DEV-005～009。

### FR-TASK-003 用户查看任务详情

**触发、发起者与前置：**

统一读取任务正文、安排、完成和执行状态，区分预计与实际投入。

**入口：** 任务卡片 → 详情；历史任务 → 只读详情。**前置：** 本人任务及父链完整；删除保留身份可读，不提供恢复删除。

**依据：** FR-TASK-003、FR-TASK-008、FR-TASK-011、FR-HISTORY-005；BL-TASK-002、BL-TASK-005、BL-HISTORY-004。

**输入：**采用本章第三部分 API-TASK-003 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 读取task并核验stage→goal本人父链；悬空关系返回服务不可用并内部记录traceId。
2. 补偿到期后在同一只读视图分别读取当前安排、唯一完成事实、当前/最近执行摘要及可信投入。
3. DONE返回currentAssignment=null，完成时间和当时计划从task_completion读取；历史删除返回historyOnly=true。
4. 按当前业务日及父状态计算canExecute等资格；预计1800秒、实际2400秒可同时存在，不自动完成。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-015、018～022、028、030～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 预计1800秒、实际2400000000微秒 | 预期两个数值均保留、任务不会自动DONE。 |
| DONE且未删除任务 | 预期completion完整、currentAssignment=null、canExecute=false。 |
| 删除保留任务从历史查看 | 预期historyOnly=true、真实投入与原阶段仍可查。 |

**关联功能/处理：**API-TASK-003；**开发批次：**DEV-005～009。

### FR-TASK-004 用户修改任务

**触发、发起者与前置：**

修改未完成任务的正文、优先级、预计耗时及任务规划日期。

**入口：** 任务详情 → 编辑。**前置：** 本人未删除未DONE；父目标/阶段可管理，暂停阶段允许规划修改。

**依据：** FR-TASK-004、FR-TASK-006、FR-TASK-007；BL-TASK-003、BL-TASK-004。

**输入：**采用本章第三部分 API-TASK-004 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 合并PATCH，除版本外至少一个字段；拒绝stageId/goalId、计划日期、实际秒数及状态。
2. 锁内校验父链/版本；若当前RUNNING且实际变更estimatedSeconds，返回ESTIMATE_LOCKED_WHILE_RUNNING。
3. 新startDate需兼容当前周/日安排，否则DATE_PLAN_CONFLICT，要求先由用户重排。
4. 更新允许字段与task.version，priority与sort_order各自保存；不改区间、不补任务完成、不自动迁移计划。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-015、018～022、028、030～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| PAUSED任务将priority改MEDIUM、estimatedSeconds=null | 预期成功，手动顺序与真实投入不变。 |
| RUNNING时预计1800改3600 | 预期409 ESTIMATE_LOCKED_WHILE_RUNNING，原值保留。 |
| 安排今天10月18日，startDate改10月19日 | 预期409 DATE_PLAN_CONFLICT，不将任务自动搬明天。 |

**关联功能/处理：**API-TASK-004；**开发批次：**DEV-005～009。

### FR-TASK-005 用户删除任务

**触发、发起者与前置：**

清理任务并保留已经发生的执行与完成贡献。

**入口：** 任务详情 → 删除影响确认。**前置：** 用户明确确认，任务全部未结束执行已结束；归档目标下历史任务也遵循保留规则。

**依据：** FR-TASK-005；BL-TASK-007、BL-GOAL-007、BL-HISTORY-005。

**输入：**采用本章第三部分 API-TASK-006 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 锁内校验本人任务/父链/版本，查全部未结束执行；PAUSED也阻塞。
2. 查任意focus_session（含0秒）、focus_segment、task_completion与其他永久引用。
3. 完全无执行/完成/永久引用则清除安排行后物理删除；否则标task.deleted_at，保留原状态和历史身份。
4. 递增受影响计划和阶段/目标版本，重算当前C/N；删除未完成可能使C=N，只发完成确认，N=0不触发。
5. 历史完成、真实投入、原closure全部不删不重算；页面依据mode显示实际删除/保留结果。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-015、018～022、028、030～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 从未执行未完成、已有未来安排任务删除 | 预期DELETED、当前安排消失，不创造历史条目。 |
| 已开始但0秒且执行已结束 | 预期HISTORY_RETAINED，不能因耗时0物理删除。 |
| 目标3项完成2项，删剩余未完成 | 预期2/2只待确认，被删项无completion；删全部后N=0不发确认。 |

**关联功能/处理：**API-TASK-006；**开发批次：**DEV-005～009。

### 状态变化

| 当前状态 | 触发 | 目标状态 | 约束/失败反馈 |
|---|---|---|---|
| 未完成 | 合法完成确认 | DONE | 唯一完成事实；不可恢复未完成 |
| 未完成 | 重新安排 | 原任务状态 | 只改当前安排 |
| 未完成/已完成 | 删除且全部执行已结束 | 移出当前范围 | 有历史保留身份 |

### 事务、并发与重复请求

核心事实与必要审计、去重结果及 outbox 同库提交。锁序遵循运行护栏、管理锁（如适用）、按稳定顺序排列的账户锁；锁后重验当前时刻、归属、父链和 expectedVersion。昂贵密码计算、外部网络和重度统计不占用账户短事务。读请求复用必要到期补偿，但补偿与随后可拒绝业务的提交边界必须明确。

同一次意图使用同一 Idempotency-Key；不同参数重用旧键返回冲突。响应丢失不新建意图自动重做。安全账本采用先独立意图、同库提交、再同步结果的协议，结果无法核实保持隔离，不声称跨存储原子提交。

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper；insights 只读查询允许按固定表契约关联，不取得写所有权。
