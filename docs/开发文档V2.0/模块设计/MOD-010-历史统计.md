### FR-HISTORY-001 用户查看历史成长记录

**触发、发起者与前置：**

**目的：** 用户按事实所属日期查看成长轨迹，能继续进入目标/阶段/任务/计划/习惯/执行原详情，删除不抹除历史。

**入口：** PAGE-015 /history 的事件流。

**前置：** 日期和筛选组合合法。

**追溯：** FR-HISTORY-001、FR-HISTORY-002、FR-HISTORY-003、FR-HISTORY-004、FR-HISTORY-005、FR-HISTORY-006、FR-HISTORY-007；BL-HISTORY-001、BL-HISTORY-002、BL-HISTORY-003、BL-HISTORY-005。

**输入：**采用本章第三部分 API-HISTORY-002 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验日期、kind与互斥筛选。
2. 从各类源事实投影统一事件。
3. 按冻结businessDate过滤。
4. 按occurredAt/kind/id稳定分页。

**关键分支：** 跨日执行按allocation.id分卡；修正事件不再计一份投入。

8. 详情复用04目标/阶段/任务/计划历史以及本册FOCUS-008/009、HABIT-011/012；事件流不新建第二套历史副本。

### FR-HISTORY-002 用户按时间范围查询历史记录

**触发、发起者与前置：**

**目的：** 用户查询完整时间范围的完成数、真实投入和习惯完成率，可聚焦某目标/阶段而不混入全账户习惯。

**入口：** PAGE-015 /history 的汇总和按日图表。

**前置：** 日期范围合法、终点不晚于当前业务日；过滤父链一致。

**追溯：** FR-HISTORY-002、FR-HISTORY-008、FR-HISTORY-009、FR-HISTORY-010、FR-HISTORY-011；FR-FOCUS-006、FR-FOCUS-007、FR-FOCUS-008、FR-FOCUS-009；BL-HISTORY-001、BL-HISTORY-004、BL-HISTORY-005；BL-FOCUS-004；BL-HABIT-006。

**输入：**采用本章第三部分 API-HISTORY-001 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验日期和目标/阶段范围。
2. 完成必要到期补偿后开启一致性快照。
3. 从完成、区间和习惯日事实汇总。
4. 返回SUMMARY或按日分页。

**关键分支：** 目标/阶段筛选不含个人习惯；习惯分母0返回null。

<details>
<summary>展开完整业务规则与事务顺序</summary>

1. 校验范围和筛选父链，保留删除历史身份可访问；允许单次完整三年一致汇总，不新增366天上限。
2. 可靠处理相关过去习惯结算、时区/计划边界，再进入短只读一致性快照，不能分页多次加总冒充同一汇总。

6. SUMMARY返回整个范围单对象；DAY按businessDate ASC分页，可补齐零值日期作图但不写假日结果；分母0比例null。
7. 读失败503且图表显示失败，预计耗时不进实际投入；修正事件本身不另加一次专注。

</details>

**触发、发起者与前置：**

打开具体一天的安排、完成和真实投入，明确日计划为空状态。

**入口：** 日历日期点击、今日计划。**前置：** planDate合法；过去日只读，GET不自动建空日身份。

**依据：** FR-DAY-002、FR-DAY-007；BL-DAY-001、BL-DAY-005、BL-HISTORY-002。

## 第四部分：类设计

### 4.1 包结构

现有工程仅含包说明；以下为本模块的规划类，尚未实现。

```text
backend/insights/src/main/java/com/asterway/insights/
  api/HistoryApi.java           模块之间调用的 Java 公开能力
  api/model/                  公开 Command / Result / Snapshot，按用例创建
  api/error/                  本业务错误码和必要的带类型异常
  service/HistoryService.java   查询口径与只读投影，不写业务事实
  mapper/HistoryMapper.java     本模块数据访问或明确允许的只读投影
  model/                      内部存储/查询模型，不直接作为 HTTP 响应
backend/insights/src/main/resources/mapper/insights/HistoryMapper.xml
backend/app/src/main/java/com/asterway/app/
  web/insights/HistoryController.java
  web/insights/request/           请求 DTO：前端提交的允许字段
  web/insights/response/          响应 VO：返回前端的安全字段
  application/insights/HistoryQueryUseCase.java   需要协调时创建
```

`request` 和 `response` 是 Java 包，分别存请求 DTO 和响应 VO；DTO/VO 是数据传输对象，不是额外 Maven 工程。请求 JSON 绑定为请求 DTO，Controller 调用用例/公开能力，业务结果映射为响应 VO，再放入统一 `ApiResponse.data`。`api` 指模块间 Java 调用契约，HTTP 路由集中在 app 的 Controller。

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper。只保留 insights 聚合事实、administration 授权账户摘要两类明确的只读投影例外，不取得其他模块写权。账户写入由 identity 处理，app 协调管理权限。
