# 04 MOD-005 周计划模块设计

> 项目：Asterway · 个人成长管理
> 文档版本：V2.0　编制日期：2026-10-22　状态：设计审阅稿
> 工程基点：`27661335d458bc74294c6c3cc303649a175eddc9`；软件版本：`0.1.0-SNAPSHOT`。

> 对应功能：FR-WEEK-001, FR-WEEK-002, FR-WEEK-003, FR-WEEK-004, FR-WEEK-005, FR-WEEK-006, FR-WEEK-007, FR-WEEK-008
> 工程归属：`backend/planning`；HTTP 和跨模块应用用例归 `backend/app`。

## 一、模块范围

### 1.1 模块职责

周身份、当前安排、归档和待处理。同账户同周只有一个周期身份；不会自动复制任务到下一周。

### 1.2 对应功能清单

| 功能 | 名称 | 本模块承担部分 |
|---|---|---|
| FR-WEEK-001 | 用户创建周计划 | API-PLAN-001 |
| FR-WEEK-002 | 用户查看周计划 | API-PLAN-003、API-PLAN-004 |
| FR-WEEK-003 | 用户将任务加入周计划 | API-TASK-007（WEEK） |
| FR-WEEK-004 | 用户将任务移出周计划 | API-TASK-007（POOL） |
| FR-WEEK-005 | 用户调整周计划安排 | API-TASK-007、API-PLAN-007 |
| FR-WEEK-006 | 系统展示周计划任务推进情况 | API-PLAN-003、API-PLAN-004 |
| FR-WEEK-007 | 用户删除周计划 | API-PLAN-009 |
| FR-WEEK-008 | 系统展示周计划未完成待处理项 | API-PLAN-011；JOB-003 |

### 1.3 模块依赖

| 依赖 | 使用原因 | 交互内容 | 失败处理 |
|---|---|---|---|
| 任务、日计划和执行 | 核对业务资格及形成统一结果 | 由 app 在同一上下文协调业务公开能力 | 依赖不可用按接口错误反馈；核心事务整体回滚 |
| common | 身份、时间、锁、幂等、错误及事件机制 | 明确上下文与固定锁序 | 恢复门禁未开放时拒绝相关写入 |
| PostgreSQL | 持久化与约束 | 本人数据和唯一性/排除约束 | 提交未知则保留原意图核实 |

## 第一部分：业务逻辑

### FR-WEEK-001 用户创建周计划

**触发、发起者与前置：**

创建本周/未来周计划，已存在或归档时复用同一身份。

**入口：** 周计划日期切换 → 创建/重新规划本周。**前置：** 按账户有效时区确定本周；weekStartDate必须ISO周一且非过去周。

**依据：** FR-WEEK-001；BL-WEEK-001、BL-HISTORY-005。

**输入：**采用本章第三部分 API-PLAN-001 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验周一及范围，weekEndDate由周一加6天推导，不能由请求指定。
2. 锁内按user_id/week_start_date唯一查找；无身份插入并返回201 CREATED。
3. 已有未归档身份返回200 EXISTING；当前/未来归档身份清archived_at并递增版本，返回200 REACTIVATED。
4. 不恢复旧任务安排、不新建空日计划，历史执行/完成保留原计划身份。
5. 并发创建与原键重试都返回同一周ID，自然唯一键作为最终保护。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-023～029、039～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 提交2026-10-19周一 | 首次201 CREATED，再以新意图同日期200 EXISTING且ID相同。 |
| 同周归档且有历史后重新规划 | 预期200 REACTIVATED、历史保留、旧任务不恢复。 |
| 今天10月18日提交2026-10-05过去周 | 预期422 PAST_PLAN_READ_ONLY，不清历史归档标记。 |

**关联功能/处理：**API-PLAN-001；**开发批次：**DEV-006、009、010。

### FR-WEEK-002 用户查看周计划

**触发、发起者与前置：**

按日期打开某周，即使尚未创建也显示完整空视图。

**入口：** 周历切换、默认本周页。**前置：** weekStartDate为周一；GET可看过去/今天所在周/未来，不创建身份。

**依据：** FR-WEEK-002、FR-WEEK-006；BL-WEEK-001、BL-WEEK-004、BL-HISTORY-002。

**输入：**采用本章第三部分 API-PLAN-003 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 按user_id/week_start_date查身份；未找到返回exists=false、id/version=null，任务空页，计数投入0。
2. 已有身份分别取当前安排与完成事实，完成来源独立，不从已删除的安排行恢复完成项。
3. taskScope=UNDATED只取daily_plan_id为空的当前安排及无指定日完成；DATED取有指定日项；ALL分组展示。
4. 按2.4队列顺序稳定分页，当前清单排除删除历史任务；includeRetainedHistory=true才显式显示其完成历史项。
5. 过去/归档readOnly=true；迁出的未完成任务不留副本，旧周真实投入仍通过段保留。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-023～029、039～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 未创建2026-10-19周 | 预期200、exists=false、id/version=null、tasks空页，数据库周行数不变。 |
| 某无日期任务迁往下周，查旧周 | 预期无旧任务卡片，旧周20分钟仍在投入汇总。 |
| UNDATED筛选且某已完成项dailyPlanId=null | 预期该完成事实正确进入无日期结果且不再当当前安排。 |

**关联功能/处理：**API-PLAN-003、API-PLAN-004；**开发批次：**DEV-006、009、010。

### FR-WEEK-003 用户将任务加入周计划

**触发、发起者与前置：**

统一处理加入周、指定日、跨周迁移、取消指定日及回池，不复制任务。

**入口：** 任务池/任务详情/今日看板/待处理 → 安排抽屉。**前置：** 未删除未DONE；父目标可管理、阶段未DONE，PAUSED阶段仍可规划。

**依据：** FR-TASK-010、FR-WEEK-003、FR-WEEK-004、FR-WEEK-005、FR-DAY-001、FR-DAY-003、FR-DAY-006、FR-DASH-007；BL-TASK-008、BL-WEEK-002、BL-WEEK-003、BL-DAY-001、BL-DAY-004。

**输入：**采用本章第三部分 API-TASK-007 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 按destination严格校验互斥日期：POOL无日期；WEEK只weekStartDate；DAY只planDate；不接收任意周日身份。
2. 锁内重读任务/父状态/版本及旧安排；WEEK所选周至少一天不早于目标/任务开始，DAY不早于两者开始日。预计结束与dueDate均不作为重排硬上界。
3. 目标周期身份按(user_id,week_start_date)/(user_id,plan_date)唯一取得；必要时创建/复用归档身份，日必属同一周。
4. 实际去向变化且本任务RUNNING时，验证可选finalConfirmation后暂停：有确认保存确认点，无确认截旧T；段保留旧计划/时区上下文。
5. 在同一事务更新唯一task_assignment或POOL删除；DAY填新日身份，WEEK清日身份，清除旧pending四字段；计划队列末尾排序。
6. 更新task与新旧周日版本，旧日/周不留独立“已改期/原未完成”任务；focus_session仍同一本次、paused累计保留。 若相同去向没有实际变化则返回现状，不因重复保存暂停运行任务或重复增版本；提交后刷新所有affectedPlans与任务池。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-023～029、039～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 今天已计20分钟任务迁到10月21日 | 预期旧日无卡片、新日1项、session为PAUSED、累计20分钟仍归今天。 |
| DAY改WEEK且周一起点相同 | 预期dailyPlanId=null，周无日期队列1项，旧日任务消失、历史段日身份不变。 |
| 旧周PENDING迁本周DAY | 预期仍同taskId、pending四字段清空、旧周不留副本；POOL再清全部当前关系。 |
| 目标10月20日开始，DAY选10月19日 | 预期422 PLAN_DATE_BEFORE_START，旧安排与运行状态不因本命令部分改变。 |

**关联功能/处理：**API-TASK-007（WEEK）；**开发批次：**DEV-006、009、010。

### FR-WEEK-007 用户删除周计划

**触发、发起者与前置：**

取消整周未完成安排，清理无历史周期或归档真实历史。

**入口：** 周计划 → 删除影响确认。**前置：** 本人周；confirmed=true；该周所有相关执行已结束，包括历史上下文关联PAUSED。

**依据：** FR-WEEK-007；BL-WEEK-006、BL-HISTORY-005。

**输入：**采用本章第三部分 API-PLAN-009 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 锁内核周版本，按当前安排行以及focus_segment.weekly_plan_id找所有相关执行；任务已迁出也不能漏查PAUSED。
2. 存在未结束执行返回UNFINISHED_EXECUTION；通过后收集当前/待处理安排及子日所有必要引用。
3. 撤出该周未完成安排，任务回池；不删任务，不产生新延期或补完成记录。
4. 显式先清无引用子日，再判周：无事实无必要引用可物理DELETED；有完成/区间/日历史则ARCHIVED保留同一身份。
5. 过去周仅归档历史和撤出仍存在的当前安排；不改旧顺序/完成/真实投入，不重新开放执行。
6. 返回实际mode与回池数；当前/未来同周将来重新规划时复用保留ID，唯一键不释放。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-023～029、039～044；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 未执行未来周有3项未完成 | 删除后预期DELETED、3任务回池、无完成/时间记录被新增。 |
| 有20分钟执行且已结束的周删除 | 预期ARCHIVED、20分钟仍可查、重规划同周用原ID。 |

### FR-WEEK-008 系统展示周计划未完成待处理项

**触发：**调度、访问前补偿或内部事件。**发起者：**系统。

**前置：**本人有效身份或受控系统上下文；日期、对象和状态满足现行业务规则。

**输入：**当前状态、权威时刻和有效业务日，不接收客户端虚构完成事实。

**事件流：**核对身份和对象 → 按 A07 先补偿到期事实 → 执行 API-PLAN-011；JOB-003 → 形成结果或标准拒绝 → 留存必要事实及可追踪记录。

**规则与异常：**同账户同周只有一个周期身份；不会自动复制任务到下一周。 重复创建返回既有周期或冲突；迁移失败不留下半份安排。 系统处理使用原业务身份去重，失败不提前推进检查点。

**执行结果：**系统展示周计划未完成待处理项；无权或依赖失败不伪装成空结果。

**关联验证：**TEST-023～029、039～044。

**JOB-003 详细事件流：**

1. 从 PLAN_DAY/PLAN_WEEK 检查点找到最早未完成绝对边界，按保存的 zone_period_id 解释当时日/周，不用当前设备时区重新推算。
2. 取得账户锁，完成到该边界必须发生的可信计时截断；正在执行但执行资格在边界结束的段不能跨过原资格边界持续累计。
3. 对该日/周仍然存在的未完成安排逐个重验任务、父目标、计划归属。已完成任务的安排已由完成用例移除，不新增待处理；已迁出原周期的任务不重复处理。
4. 日资格结束时，将同一 task_assignment 标为 PENDING，pending_kind=DAY，保存原日日期和绝对边界。保留真实执行及原归属，不新建下一日安排。
5. 周资格结束时，同一安排升级/设为 PENDING、pending_kind=WEEK，保存该周起点和周末绝对边界；已经 DAY 待处理的仍只有同一个 task_id 身份。
6. 更新该边界检查点，业务结果与游标同事务提交。日周恰逢同一绝对边界时，按同账户一致次序处理，最终待处理含义为周已结束；不能遗留可继续本周执行的假资格。
7. 用户之后从待处理或当前任务入口选择新周/新日/返回池，复用 API-TASK-007；成功后原待处理状态消失，过去投入不移动。

**关联功能/处理：**API-PLAN-011；JOB-003；**开发批次：**DEV-006、009、010。

### 状态变化

| 当前状态 | 触发 | 目标状态 | 约束/失败反馈 |
|---|---|---|---|
| 一周为周一至周日；任务与周身份均为本人且有效。 | 本章动作 | 已提交结果 | 重验版本、归属和日期；只读查询不改变业务事实 |

### 事务、并发与重复请求

核心事实与必要审计、去重结果及 outbox 同库提交。锁序遵循运行护栏、管理锁（如适用）、按稳定顺序排列的账户锁；锁后重验当前时刻、归属、父链和 expectedVersion。昂贵密码计算、外部网络和重度统计不占用账户短事务。读请求复用必要到期补偿，但补偿与随后可拒绝业务的提交边界必须明确。

同一次意图使用同一 Idempotency-Key；不同参数重用旧键返回冲突。响应丢失不新建意图自动重做。安全账本采用先独立意图、同库提交、再同步结果的协议，结果无法核实保持隔离，不声称跨存储原子提交。

## 第四部分：类设计

### 4.1 包结构

现有工程仅含包说明；以下为本模块的规划类，尚未实现。

```text
backend/planning/src/main/java/com/asterway/planning/
  api/WeeklyPlanApi.java           模块之间调用的 Java 公开能力
  api/model/                  公开 Command / Result / Snapshot，按用例创建
  api/error/                  本业务错误码和必要的带类型异常
  service/WeeklyPlanService.java   规则与本模块拥有数据的写入
  mapper/WeeklyPlanMapper.java     本模块数据访问或明确允许的只读投影
  model/                      内部存储/查询模型，不直接作为 HTTP 响应
backend/planning/src/main/resources/mapper/planning/WeeklyPlanMapper.xml
backend/app/src/main/java/com/asterway/app/
  web/planning/WeeklyPlanController.java
  web/planning/request/           请求 DTO：前端提交的允许字段
  web/planning/response/          响应 VO：返回前端的安全字段
  application/planning/PlanChangeUseCase.java   需要协调时创建
```

`request` 和 `response` 是 Java 包，分别存请求 DTO 和响应 VO；DTO/VO 是数据传输对象，不是额外 Maven 工程。请求 JSON 绑定为请求 DTO，Controller 调用用例/公开能力，业务结果映射为响应 VO，再放入统一 `ApiResponse.data`。`api` 指模块间 Java 调用契约，HTTP 路由集中在 app 的 Controller。

| 包 | 类/接口 | 类型 | 职责 | 依赖 | 关键技术 |
|---|---|---|---|---|---|
| com.asterway.app.web.planning | WeeklyPlanController | Controller | 路由、校验、DTO 映射 | 应用用例/公开能力 | Spring MVC |

### 4.3 关键类设计

`PlanChangeUseCase` 是需要应用协调时的落点示例，不要求为每条只读接口建立转发类。写命令涉及统一锁、幂等、补偿和跨模块原子性时由应用用例协调；具体 Service 实现公开能力，不再机械增加同义 Service 接口和 ServiceImpl。公开输入/结果在 api/model，内部存储模型在 model。

| 契约入口 | 输入 | 输出 | 公开职责与边界 |

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper。只保留 insights 聚合事实、administration 授权账户摘要两类明确的只读投影例外，不取得其他模块写权。账户写入由 identity 处理，app 协调管理权限。
