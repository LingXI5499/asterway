> 文档版本：V2.0　编制日期：2026-10-22　状态：设计审阅稿

## 一、模块范围

### 1.1 模块职责

目标内阶段、顺序和推进状态。阶段顺序和推进状态保存；已有历史归属保留。

### 1.2 对应功能清单

| 功能 | 名称 | 本模块承担部分 |
|---|---|---|
| FR-STAGE-001 | 用户创建阶段 | API-STAGE-001 |
| FR-STAGE-002 | 用户查看阶段列表 | API-STAGE-002 |
| FR-STAGE-003 | 用户查看阶段详情 | API-STAGE-003 |
| FR-STAGE-004 | 用户修改阶段 | API-STAGE-004 |
| FR-STAGE-005 | 用户完成阶段 | API-STAGE-007 |
| FR-STAGE-006 | 系统展示阶段推进顺序 | API-STAGE-002 |
| FR-STAGE-007 | 用户查看阶段任务完成情况 | API-STAGE-003 |
| FR-STAGE-008 | 用户查看阶段累计投入时间 | API-STAGE-003、API-HISTORY-001 |
| FR-STAGE-009 | 用户调整阶段顺序 | API-STAGE-009 |
| FR-STAGE-010 | 用户暂停阶段 | API-STAGE-005 |
| FR-STAGE-011 | 用户恢复暂停阶段 | API-STAGE-006 |
| FR-STAGE-012 | 用户重新打开已完成阶段 | API-STAGE-008 |
| FR-STAGE-013 | 用户删除空阶段 | API-STAGE-010 |

### 1.3 模块依赖

| 依赖 | 使用原因 | 交互内容 | 失败处理 |
|---|---|---|---|
| 目标、任务和执行资格 | 核对业务资格及形成统一结果 | 由 app 在同一上下文协调业务公开能力 | 依赖不可用按接口错误反馈；核心事务整体回滚 |
| common | 身份、时间、锁、幂等、错误及事件机制 | 明确上下文与固定锁序 | 恢复门禁未开放时拒绝相关写入 |
| PostgreSQL | 持久化与约束 | 本人数据和唯一性/排除约束 | 提交未知则保留原意图核实 |

## 第一部分：业务逻辑

### FR-STAGE-001 用户创建阶段

**触发、发起者与前置：**

在可管理目标下拆出并行推进的阶段。

**入口：** 目标详情 → 新建阶段。**前置：** 父目标PENDING/ACTIVE且未归档。

**依据：** FR-STAGE-001；BL-STAGE-001。

**输入：**采用本章第三部分 API-STAGE-001 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验父目标与字段，阶段日期只表示规划、不建立阶段依赖或任务执行资格。
2. 锁内取得该目标当前未删除阶段的末尾sort_order，追加新阶段；客户端不能自定sortOrder。
3. 写NOT_STARTED、completed_at/deleted_at为空，进度无任务；递增目标列表版本。
4. 追加STAGE/CREATE节点后提交，页面追加卡片并保持多个阶段可同时推进。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-015～022、044、055；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 目标已有sortOrder=0、1，新增集合基础 | 预期201、sortOrder="2"、NOT_STARTED、目标version加1。 |
| startDate=10月22日、endDate=10月21日 | 预期422，无阶段与节点。 |
| 父目标COMPLETED | 预期409 STATE_CONFLICT，引导先重开，不能偷偷开启目标。 |

**关联功能/处理：**API-STAGE-001；**开发批次：**DEV-005、007、009。

### FR-STAGE-002 用户查看阶段列表

**触发、发起者与前置：**

查看目标的当前阶段顺序、完成情况和投入。

**入口：** 目标详情 → 阶段列表。**前置：** 本人目标，归档/完成目标仍允许只读查看。

**依据：** FR-STAGE-002、FR-STAGE-006、FR-STAGE-007、FR-STAGE-008；BL-STAGE-002、BL-GOAL-007。

**输入：**采用本章第三部分 API-STAGE-002 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 核验目标归属，按stage.deleted_at IS NULL与可选status过滤。
2. 按sort_order、id升序分页；状态过滤仅改变展示，不改变真实顺序。
3. 按阶段当前有效任务求进度；保留已删除任务的历史真实投入。
4. 全部任务DONE不会触发本GET自动完成阶段或目标，空阶段显示无任务。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

| 输入与操作 | 预期 |
|---|---|
| 三阶段顺序0、1、2，其中阶段1被删除 | 预期只显示0、2并按保存顺序。 |
| 阶段4项有效任务完成1项、历史删除任务20分钟 | 预期25.00%，20分钟仍计投入。 |
| status=DONE且不存在 | 预期200空页，不据此自动创建新阶段。 |

**关联功能/处理：**API-STAGE-002；**开发批次：**DEV-005、007、009。

### FR-STAGE-004 用户修改阶段

**触发、发起者与前置：**

更新阶段正文及可选规划日期。

**入口：** 阶段详情 → 编辑。**前置：** NOT_STARTED/IN_PROGRESS/PAUSED且未删除；父目标可管理，DONE须先重开。

**依据：** FR-STAGE-004；BL-STAGE-003。

**输入：**采用本章第三部分 API-STAGE-004 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 解析PATCH并要求至少一个正文/日期可改字段；拒绝goalId、task数组、sortOrder及状态。
2. 锁内查父链、阶段状态和version，合并后校验规划日期。
3. 只修改允许字段；正文同值不生成虚假EDIT节点，不改任务日期、执行段与完成快照。
4. 提交后返回新详情，列表和详情使用同一版本。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

### FR-STAGE-005 用户完成阶段

**触发、发起者与前置：**

用户确认结束当前阶段，真实任务完成条件必须成立。

**入口：** 阶段详情 → 完成 → 确认。**前置：** 父目标可推进，阶段未删除，所有当前有效任务DONE且相关执行已结束。

**依据：** FR-STAGE-005；BL-STAGE-004。

**输入：**采用本章第三部分 API-STAGE-007 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 取得账户锁重查当前有效task集合；任一deleted_at为空且非DONE任务阻塞，历史删除任务不阻塞。
2. 同时查该阶段全部RUNNING/PAUSED；执行未结束须先走FOCUS结束。
3. 允许空阶段经用户确认完成；不得将无任务目标判100%。
4. 写stage.status=DONE、completed_at实际时刻、CLOSE节点，任务与目标状态不联动完成。
5. 同键重试回原结果，已DONE的合法重复动作不重写原completedAt。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

**验收入口：**TEST-015～022、044、055；本接口功能测试：

| 输入与操作 | 预期 |
|---|---|
| 3项有效任务均DONE，另一历史删除未完成任务曾计20分钟 | 预期允许完成，20分钟仍计阶段投入。 |
| 有1项当前有效PAUSED任务 | 预期409 STAGE_HAS_UNFINISHED_TASKS，completedAt仍null。 |
| 空阶段confirmed=true | 预期DONE，目标无任务percent仍null，不能自动结束目标。 |

**关联功能/处理：**API-STAGE-007；**开发批次：**DEV-005、007、009。

## 第四部分：类设计

### 4.1 包结构

现有工程仅含包说明；以下为本模块的规划类，尚未实现。

```text
backend/growth/src/main/java/com/asterway/growth/
  api/StageApi.java           模块之间调用的 Java 公开能力
  api/model/                  公开 Command / Result / Snapshot，按用例创建
  api/error/                  本业务错误码和必要的带类型异常
  service/StageService.java   规则与本模块拥有数据的写入
  mapper/StageMapper.java     本模块数据访问或明确允许的只读投影
  model/                      内部存储/查询模型，不直接作为 HTTP 响应
backend/growth/src/main/resources/mapper/growth/StageMapper.xml
backend/app/src/main/java/com/asterway/app/
  web/growth/StageController.java
  web/growth/request/           请求 DTO：前端提交的允许字段
  web/growth/response/          响应 VO：返回前端的安全字段
  application/goal/StageUseCase.java   需要协调时创建
```

`request` 和 `response` 是 Java 包，分别存请求 DTO 和响应 VO；DTO/VO 是数据传输对象，不是额外 Maven 工程。请求 JSON 绑定为请求 DTO，Controller 调用用例/公开能力，业务结果映射为响应 VO，再放入统一 `ApiResponse.data`。`api` 指模块间 Java 调用契约，HTTP 路由集中在 app 的 Controller。

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper。只保留 insights 聚合事实、administration 授权账户摘要两类明确的只读投影例外，不取得其他模块写权。账户写入由 identity 处理，app 协调管理权限。
