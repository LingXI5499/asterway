## 第一部分：业务逻辑

### FR-GOAL-001 用户创建目标

**触发、发起者与前置：**

把学习或成长意图登记为可拆解目标，未来开始的目标先进入待开始范围。

**入口：** 目标列表 → 新建目标表单。**前置：** 账户可用；表单包含名称、描述、完成条件及两个有效日期。

**依据：** FR-GOAL-001、FR-GOAL-012、FR-GOAL-013；BL-GOAL-001、BL-GOAL-008。

**输入：**采用本章第三部分 API-GOAL-001 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验五个字段、未知字段及日期关系；身份只取登录上下文，拒绝客户端自报所有者。
2. 获得账户锁并读取当前业务日，B=含首尾日历天数；未来开始写 PENDING，否则写 ACTIVE。
3. 插入目标与 CREATE 节点；初始 cycleNo=1、conditionRound="0"、无当前任务，不能因 0/0 发完成通知。
4. 若今天晚于预计结束日且状态 ACTIVE，按 2.6 公式补做一次延期；保留最近人工日期计算的 B。
5. 提交去重结果后返回完整目标，前端打开详情并选择正确的 ACTIVE/PENDING 分组。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

**异常、取消与执行结果：**参数、权限、版本及状态拒绝不产生部分业务写入；成功以提交后的权威状态为准。需要先独立持久化到期补偿的动作遵循 A07；已提交的前序结束执行不随后续拒绝回滚。请求发送前取消不写入；提交后取消不能撤销已提交事实。各动作特有错误如下节接口定义。

|---|---|
| 提交开始日2026-10-20、结束日2026-11-20 | 预期201、PENDING、B=32、N=C=0、percent=null，阶段/任务/计划行数不变。 |
| 提交开始日2026-10-20、结束日2026-10-19 | 预期422，violations定位expectedEndDate，无目标和CREATE节点。 |

### FR-GOAL-002 用户查看目标列表

**触发、发起者与前置：**

在活跃、待开始、已完成和归档范围中查找本人目标。

**入口：** 目标列表四个范围及关键词搜索。**前置：** 已登录；先补偿该账户已经到达的开始/延期边界。

**依据：** FR-GOAL-002、FR-GOAL-009、FR-GOAL-012；BL-GOAL-001、BL-GOAL-002、BL-GOAL-007。

**输入：**采用本章第三部分 API-GOAL-002 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 解析 scope 与关键词；ACTIVE/PENDING/COMPLETED 均排除 archived_at 非空，ARCHIVED 按归档标记取数并保留原 state。
2. 对本人相关到期目标执行独立补偿后开启只读查询，按 updated_at DESC、id DESC 进行游标分页。
3. 以当前未删除任务计算 C/N；汇总投入保留已删除历史任务贡献，不能把两个口径混用。
4. 返回空页或当前页与下一游标；页面切换 scope/keyword 必须清空旧游标。

### FR-GOAL-004 用户修改目标

**触发、发起者与前置：**

修改目标正文或人工规划日期，保留已发生执行事实。

**入口：** 目标详情 → 编辑目标。**前置：** 目标未归档且未完成；提交刚读取的目标版本。

**依据：** FR-GOAL-004、FR-GOAL-013；BL-GOAL-003、BL-GOAL-008。

**输入：**采用本章第三部分 API-GOAL-004 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 合并 PATCH 与现有字段；除 expectedVersion 外至少出现一个可改字段，拒绝状态/归档/计数字段。
2. 锁内核验目标版本、父子归属和首段真实执行业务日；新开始日不得晚于该历史日期。
3. 遍历当前有效安排核对与新开始日的兼容性；有冲突返回 DATE_PLAN_CONFLICT 并保留原数据，先由用户改计划。
4. 人工日期确有变更才按新的人工起止日更新 B；普通正文修改保留 B。
5. 按当前业务日更新 PENDING/ACTIVE；若新预计日已过，按公式延期并分别保存 EDIT、EXTEND 节点，返回最终日期。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

### FR-GOAL-007 用户确认结束目标

**触发、发起者与前置：**

在全部任务完成后确认目标，或在工作已足够时主动结束并冻结真实结果。

**入口：** 目标详情结束按钮；完成确认通知 → 确认结束。**前置：** 未归档、未结束；所有相关执行已结束；用户确认本次结束含义。

**依据：** FR-GOAL-007、FR-NOTICE-003；BL-GOAL-005、BL-NOTICE-001。

**输入：**采用本章第三部分 API-GOAL-007 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 校验confirmed及endType对应字段；取得账户锁，重读state、版本、全部未结束执行及当前有效C/N。
2. ALL_TASKS_CONFIRMED要求ACTIVE、N>0、C=N且conditionRound匹配；条件变化返回CONDITION_CHANGED，不替用户换成主动结束。
3. USER_ENDED允许PENDING、无任务或不足100%；先展示并保留真实未完成数，不批量完成子项。
4. 按当前cycle_no保存唯一goal_closure，冻结名称、日期、完成条件、C/N及真实投入；N=0时percent=null。
5. 目标置COMPLETED并写closed_at，撤出未完成安排、失效旧确认、追加CLOSE；提交后返回目标和本版快照。

**数据与业务规则：**同动作的字段、版本、日期和唯一性约束见第三部分及其完整对象字典；事务内重读、校验归属及父链。

### FR-GOAL-008 用户归档目标

**触发、发起者与前置：**

暂时退出活跃推进，同时撤出任务安排并保留全部历史。

**入口：** 目标详情 → 归档 → 影响确认弹窗。**前置：** 本人目标；用户明确确认；目标下全部执行须已结束，包括PAUSED。

**依据：** FR-GOAL-008；BL-GOAL-004、BL-COMMON-004。

**输入：**采用本章第三部分 API-GOAL-005 的路径、查询或请求体；身份取服务端会话，不能以客户端归属字段授权。

**事件流：**

1. 锁内核验版本并查询目标下所有 RUNNING/PAUSED；有任一未结束则拒绝并返回完整可分页的阻塞提示。
2. 汇总将撤出的安排、未完成有效任务及受影响周日身份；用户已通过confirmed确认影响。
3. 设置 archived_at，保留原state/closed_at/cycle_no；删除当前安排行并递增对应任务和计划版本。
4. 使旧完成确认依据失效，追加 ARCHIVE 节点；不新增延期、完成或执行事实。

### FR-GOAL-013 系统自动延长目标预计结束日期

**触发：**调度、访问前补偿或内部事件。**发起者：**系统。

**前置：**本人有效身份或受控系统上下文；日期、对象和状态满足现行业务规则。

**输入：**当前状态、权威时刻和有效业务日，不接收客户端虚构完成事实。

**事件流：**核对身份和对象 → 按 A07 先补偿到期事实 → 执行 JOB-002；API-GOAL-003、API-GOAL-009 → 形成结果或标准拒绝 → 留存必要事实及可追踪记录。

**规则与异常：**形成可追踪的目标与结束快照；恢复归档或重新打开时遵守既有周期规则。 对象无权限、版本过期或仍有未结束执行时拒绝；目标不提供彻底删除。 系统处理使用原业务身份去重，失败不提前推进检查点。

**执行结果：**系统自动延长目标预计结束日期；无权或依赖失败不伪装成空结果。

**关联验证：**TEST-014～022、043～044。

**JOB-002 详细事件流：**

1. 锁内补齐必要的开始日事实，读取未主动归档、未结束目标。用户刚手动改期后，原扫描身份可能过时，重新判定。
2. 根据目标有效业务日判断旧 expected_end_date 是否已经过去。尚在预计结束日当天不延期。
3. 查询本目标当前有效任务 N、已完成数 C；删除后仅保留历史的任务排除。N=0 只为延期取 P=0，否则使用精确有理数 C/N。
4. 计算 B=baseline_duration_days，Δ=max(1,ceil(B×30%×(1-P)))；新日期=max(旧预计结束日,今天-1 日)+Δ 日。整数/精确十进制计算，不从展示百分数字符串反推。
5. 用目标身份及旧预计结束身份检查已发生的 EXTEND 节点，保证同一旧到期事实只生效一次。更新 expected_end_date，不改 B，不改 start_date，不完成目标。
6. 写 EXTEND 节点的前后日期和依据，更新 version 与 next_action_at；同事务提交。补偿多日停机按公式直接处理当前旧到期身份，不循环把自动延期天数加入 B。

**关联功能/处理：**JOB-002；API-GOAL-003、API-GOAL-009；**开发批次：**DEV-005、008～010。

### 状态变化

| 当前状态 | 触发 | 目标状态 | 约束/失败反馈 |
|---|---|---|---|
| 待开始 | 达到开始日且未主动归档 | ACTIVE | JOB-001；不创建计划 |
| ACTIVE | 本人确认结束且执行已结束 | 已结束 | 冻结快照；不代完成任务 |
| 未结束 | 归档且执行已结束 | 归档标记 | 不能执行；恢复不抹历史 |

### 事务、并发与重复请求

核心事实与必要审计、去重结果及 outbox 同库提交。锁序遵循运行护栏、管理锁（如适用）、按稳定顺序排列的账户锁；锁后重验当前时刻、归属、父链和 expectedVersion。昂贵密码计算、外部网络和重度统计不占用账户短事务。读请求复用必要到期补偿，但补偿与随后可拒绝业务的提交边界必须明确。

同一次意图使用同一 Idempotency-Key；不同参数重用旧键返回冲突。响应丢失不新建意图自动重做。安全账本采用先独立意图、同库提交、再同步结果的协议，结果无法核实保持隔离，不声称跨存储原子提交。

| created_at | timestamptz(6) | 6 | 否 | clock_timestamp() | 真实持久化时刻 |
| user_id | uuid | 按类型 | 否 | 无默认值 | 本人所有者，由服务端身份确定 |
| goal_id | uuid | 按类型 | 否 | — | 所属目标 |
| cycle_no | integer | 按类型 | 否 | — | 与 goal_id 构成唯一结束轮次 |
| end_type | varchar(24) | 24 | 否 | — | ALL_TASKS_CONFIRMED / USER_ENDED |
| closed_at | T | 按类型 | 否 | — | 用户确认的真实结束时刻 |
| task_count | integer | 按类型 | 否 | — | ≥0；结束当时有效任务 N |
| completed_count | integer | 按类型 | 否 | — | 0≤C≤N；不补完成子任务 |
| focus_microseconds | bigint | 按类型 | 否 | — | ≥0；结束当时真实投入快照 |
| schema_version | smallint | 按类型 | 否 | 1 | >0 |
| snapshot | jsonb | 按类型 | 否 | — | 当时名称、日期、完成条件等明确结构 |

N=0 进度显示无任务，不存虚构 100%。重开追加下一 cycle，旧快照不随后来任务删除重算。

### 2.4 约束与索引

本模块的主键、唯一、行内 CHECK、时间排除和查询索引必须同时落实。精确约束清单集中在 A01 第 11～12 章，不以简写替换索引名称和字段顺序；模块字段表说明不可空、生成列和状态。当前尚无 SQL 迁移，不能将设计索引数量视为已安装数量。

### 2.5 数据字典与规范

枚举采用 A01 的稳定值；时刻用 UTC 和 timestamptz，业务日期按有效 IANA 时区冻结；版本和时长通过 HTTP 传输为字符串。金额不适用，本期没有支付。软删除及历史保留以动作定义为准，不统一物理删除。记录永久业务事实时保留完整正文，技术载荷限制不截断结束/完成快照。

### 2.6 数据库脚本/迁移文件

集中目录为 `backend/app/src/main/resources/db/migration/`。工作树已有 `V001__create_app_user.sql` 最小账户表脚本，用户说明已执行，真实数据库及 Flyway 历史未核实。该脚本不改写、删除或重命名；当前暂存为空，提交前须核对实际执行原文。后续按 MG-01～MG-07 设计内容组规划，MG 编号不等于 Flyway 版本；真实文件版本须核实历史后分配未占用编号，不能再次建立另一份 V001。完整分组与前置见 05。

## 第四部分：类设计

### 4.1 包结构

现有工程仅含包说明；以下为本模块的规划类，尚未实现。

```text
backend/growth/src/main/java/com/asterway/growth/
  api/GoalApi.java           模块之间调用的 Java 公开能力
  api/model/                  公开 Command / Result / Snapshot，按用例创建
  api/error/                  本业务错误码和必要的带类型异常
  service/GoalService.java   规则与本模块拥有数据的写入
  mapper/GoalMapper.java     本模块数据访问或明确允许的只读投影
  model/                      内部存储/查询模型，不直接作为 HTTP 响应
backend/growth/src/main/resources/mapper/growth/GoalMapper.xml
backend/app/src/main/java/com/asterway/app/
  web/growth/GoalController.java
  web/growth/request/           请求 DTO：前端提交的允许字段
  web/growth/response/          响应 VO：返回前端的安全字段
  application/goal/GoalLifecycleUseCase.java   需要协调时创建
```

`request` 和 `response` 是 Java 包，分别存请求 DTO 和响应 VO；DTO/VO 是数据传输对象，不是额外 Maven 工程。请求 JSON 绑定为请求 DTO，Controller 调用用例/公开能力，业务结果映射为响应 VO，再放入统一 `ApiResponse.data`。`api` 指模块间 Java 调用契约，HTTP 路由集中在 app 的 Controller。

### 4.4 层次职责与调用链

Controller → HTTP DTO 校验/转换 → app 应用用例 → 领域公开能力/Service → 本模块 Mapper/XML → PostgreSQL → 业务结果 → 安全 VO。业务异常在服务层产生，由 app 的全局异常处理映射到 A02 的 HTTP 和业务码；数据库约束冲突只转换为可披露的标准错误，不回传 SQL、内部路径或堆栈。

Controller 不发起独立通知或跨域直接写表；业务模块不引用兄弟模块 Mapper。只保留 insights 聚合事实、administration 授权账户摘要两类明确的只读投影例外，不取得其他模块写权。账户写入由 identity 处理，app 协调管理权限。
