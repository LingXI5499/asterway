# A04 目标计划接口与对象

> 文档版本 V2.0；核对日期 2026-10-22。继承现行契约和业务规则。架构细化为本地设计审阅稿。后端业务尚未实现；工作树已有最小账户表 V001，用户说明已执行，真实数据库和迁移历史未核实。

## 1. 全部接口共同遵守的规则

### 1.1 路径、权限、请求头和基本类型

- 本文件每条接口和索引均写完整 /api/v1 路径；不再要求读者自行拼接公共前缀。
- 每一条接口的“本人权限”都表示：已登录且账户可用；USER、ADMIN、SUPER_ADMIN 使用个人功能时均只操作自己的数据。管理员身份不能绕过此限制。对象不存在或不属于本人统一返回 404 NOT_FOUND。
- 所有写请求，即 POST、PUT、PATCH、DELETE，必须携带 Idempotency-Key 和 X-CSRF-TOKEN；GET 不携带写请求意图、不产生用户规划行为。
- Idempotency-Key:UUID 表示一个稳定意图；相同意图重试使用原值和相同参数。同键异参返回 409 IDEMPOTENCY_KEY_REUSED。创建首次成功为 201；取得既有周期身份、查询、更新、动作、删除成功为 200；DELETE 不返回 204。
- 请求与响应使用 JSON。统一响应外壳字段为 code、message、data、traceId；成功 code 为 OK。每条接口给出完整统一外壳及成功/失败 JSON，字段定义以本章唯一 DTO 为准。
- UUID 是标准 UUID 字符串；业务日期为 YYYY-MM-DD；绝对时刻为 UTC ISO 8601 字符串，后缀 Z，小数最多 6 位。业务日期由当前账户有效时区判断，不能使用服务器本地日期。
- version、expectedVersion、conditionRound、sortOrder，以及秒、毫秒、微秒时长均为十进制字符串；计数和页大小是普通整数 number。非负长整数只接受 0 或不带前导零的十进制数字；正时长必须大于 0，并符合数据库 bigint 范围。
- 字段后面的“可空”表示 JSON null；“可省略”表示请求不出现该字段。PATCH 中省略表示不修改，明确 null 只可清除已注明可空的字段。必填非空文本不能是全空白；本契约不为名称、描述和完成条件新增业务长度上限。
- 请求不接受 userId、ownerId、数据库状态、真实耗时、任意版本新值或内部归档时间等受保护字段；未知或不允许修改的字段返回 422 VALIDATION_ERROR，不能静默丢弃。

### 1.2 分页、版本和写入顺序

所有标为 Page 的响应包含 items:数组、nextCursor:string|null、hasMore:boolean。Query 中 limit 可省略，默认 20、范围 1–100；cursor:string 可省略。游标不透明，绑定原筛选与排序，不能拿上一筛选的游标用于新筛选；非法游标返回 422 VALIDATION_ERROR。

普通更新和状态动作由 Body 的 expectedVersion 校验目标对象。DELETE 从 Query 取得 expectedVersion 和 confirmed=true。不可逆的 POST 动作必须在 Body 提交 confirmed=true；归档虽可恢复，也按现行业务规则 要求显式确认影响。

版本是十进制字符串，例如 "7"，不能以 JavaScript number 传输。更新不允许客户端指定新版本。排序使用所属目标或计划的版本作为列表版本：

- 目标的阶段成员或顺序改变时，目标 version 递增；阶段任务成员、完成情况或阶段状态改变时，阶段 version 递增。
- 任务自身内容、状态或当前安排改变时，task.version 递增；单纯计时确认不为任务制造一次内容修改。
- 周日计划成员、成员完成结果、清单顺序或归档状态改变时，对应计划 version 递增；修改目标/任务的普通描述不必逐个递增关联计划版本。
- 排序同时更新受影响安排行的版本；任务详情必须返回最新安排，不得将排序误当成优先级修改。

同键成功重放先按已提交结果处理，不因为重放携带旧 expectedVersion 再报版本冲突。尚无成功结果的请求，持锁重验最新版本；失败不得部分改变业务数据。

处理顺序遵循架构：相关到期补偿独立可靠提交 → 运行护栏与账户控制锁 → 查本人父子身份、状态、版本及日期 → 在一个服务事务内显式变更 → 返回已提交结果。到期补偿不能因为后面的命令被拒绝而回滚。

### 1.3 没有物理外键时的接口责任

本系统不建立物理外键，不使用数据库级联或模拟外键触发器。每次创建、关联、排序、迁移、删除都必须在账户锁内查询目标、阶段、任务、计划及 user_id，核对存在性、归属和父子关系。

任务不能换阶段、阶段不能换目标；本文件的“迁移”只指周日安排。目标不提供 DELETE；任务完成后不提供 reopen；因删除保留的历史任务不提供 restore。日计划是独立轻表，只有日期身份与展示状态，不能存另一份任务树。

### 1.4 共通失败与页面处理

| HTTP | code | 含义及页面处理 |
|---|---|---|
| 400 | VALIDATION_ERROR | JSON 或类型不能解析；提示具体字段，保留其他表单值 |
| 401 | AUTH_REQUIRED | 未登录、会话失效或撤销；遮蔽个人缓存并转登录 |
| 403 | FORBIDDEN / CSRF_INVALID | 当前角色或请求防护不允许；不执行写入 |
| 404 | NOT_FOUND | 无此对象或不属于本人；不泄露其他账户资料 |
| 409 | VERSION_CONFLICT | 读取最新版本后由用户重新判断，不直接覆盖他人更新 |
| 409 | STATE_CONFLICT | 当前状态不允许；按返回当前状态展示可用操作 |
| 409 | UNFINISHED_EXECUTION | 必须先结束相关执行；给出全部相关执行提示 |
| 409 | IDEMPOTENCY_KEY_REUSED | 同键不同参数；恢复原意图，不能把旧键用于新操作 |
| 409 | EXECUTION_CONTROL_LOST / PERMIT_EXPIRED | 可选即时确认的控制代次或许可已失效；同步执行状态 |
| 422 | VALIDATION_ERROR | 字段、枚举、日期、完整排序集合或确认值不合法 |
| 503 | RESULT_UNKNOWN | 提交结果暂不能确定；保留原意图，查询或使用原键核实 |
| 503 | SERVICE_UNAVAILABLE | 当前未提交或无法服务；明确提示重试，不能伪装空数据 |

错误仍使用公共外壳。错误 data 可包含 violations:[{field:string,message:string}]、currentVersion:string、currentState:string、unfinishedExecutions:UnfinishedExecutionHint[]；按错误提供必要字段，不返回 SQL、异常栈或其他账户资料。

本人写请求结果不确定时，可复用 02 的 API-COMMON-001：GET /api/v1/operations/{idempotencyKey}?operation=原API编号，核实原意图安全结果，再按返回对象身份读取最新 DTO。404 OPERATION_RESULT_NOT_FOUND 只表示结果未知或已过期，不证明原操作未发生；不能因此直接生成新意图重复创建/完成。该接口不允许匿名读取某用户旧结果，也不重新执行原命令。

UnfinishedExecutionHint 的完整字段为 sessionId:UUID、taskId:UUID、taskName:string、status:RUNNING|PAUSED、version:string、isCurrentController:boolean、requiresTimeRepair:boolean、allowedActions:string[]。其中 allowedActions 至少区分 OPEN_EXECUTION、END_EXECUTION；该提示不携带秘密许可，结束所需受控快照由 API-FOCUS 组取得。目标/阶段/计划可能关联多条 PAUSED，不能只检查第一条。错误data统一采用02的UnfinishedExecutionError，首批最多100条并返回总数/是否更多，剩余通过FOCUS-011按相关scope分页取得；本文“全部相关执行提示”表示完整可取，不得将首批当作全部。

### 2.5 删除结果

DeleteResult 的完整字段为 objectType:STAGE|TASK|WEEKLY_PLAN|DAILY_PLAN、objectId:UUID、mode:DELETED|HISTORY_RETAINED|ARCHIVED、removedFromCurrent:boolean、currentAssignmentRemoved:boolean、removedAssignmentCount:number、clearedDayAssignmentCount:number、returnedToPoolTaskCount:number、historyRetained:boolean、completedFactsRetained:boolean、remainingVersion:string|null、affectedPlans:[{type:WEEK|DAY,id:UUID,version:string}]、goalProgress:ProgressView|null、stageProgress:ProgressView|null、goalConfirmationPending:boolean。

### 2.6 先统一业务判断，再写接口

每个接口按需求、业务流程、契约、数据操作、分层实现和测试组织。采用JDK 17、Maven 3.9.4、Spring Boot 3.5.16、模块化单体、PostgreSQL 17.11、MyBatis XML及Vue 3 + TypeScript，精确依赖见[12技术版本基线](A08-技术版本基线.md)。Mapper属于数据拥有模块内部；app协调器调用模块公开能力，不能直接注入跨模块Mapper。模块边界见[06](A09-分层实施细则.md)。

**状态和日期必须分开判断。**

| 对象 | 可发生的变化 | 不可推导的变化 |
|---|---|---|
| 目标 | 创建/改日期决定PENDING或ACTIVE；用户结束为COMPLETED；重开进入下一cycle | 预计结束日经过不自动完成；archivedAt与state正交 |
| 阶段 | 首次任务执行可由NOT_STARTED进入IN_PROGRESS；用户暂停为PAUSED；恢复/重开按是否执行过还原；完成为DONE | 顺序和阶段日期不构成前置依赖；全部任务DONE不自动完成阶段 |
| 任务 | 创建NOT_STARTED；执行中IN_PROGRESS；暂停PAUSED；执行结束保持未完成PAUSED；用户完成才DONE | 结束执行不完成任务；移计划不清历史进度；DONE不可恢复 |
| 当前安排 | 一任务一行，ACTIVE或PENDING；完成/回池撤掉行 | ACTIVE不等于今天可执行；不能复制一份旧日任务保存迁移历史 |
| 计划 | 周一至周日；日身份由具体日期安排按需取得；历史可归档保留 | GET不建空周日对象；过去日期不可原地编辑或补完成 |

目标/任务开始日限定最早可执行日；阶段日期只是规划。DAY安排不早于目标和任务开始日，WEEK只需该周至少有一天不早于这两个开始日，实际执行时再按当天校验。目标expectedEndDate是可延期的预计日期，任务dueDate是逾期提示，均不作为强制停止重排的硬上界。未完成且dueDate早于业务今天才显示截止逾期；日周过期、目标延期、任务截止逾期分别显示与处理。

**当前进度、真实贡献与条件轮次。** N是目标/阶段下当前未删除任务数，C是其中DONE数；N=0返回hasTasks=false/percent=null，自动条件只在ACTIVE、未归档、N>0且C=N时成立。百分比只作两位小数展示，使用整数计数判断，不能依赖四舍五入的100.00。删除保留任务退出当前C/N，但task_completion与focus_segment仍贡献历史；目标结束快照也不变。

条件false→true才递增condition_round并生成GOAL_CONDITION_MET；true→false生成对应轮GOAL_CONDITION_INVALIDATED，创建任务、完成、删除及目标状态变化都在账户锁内重验。用户对通知选择继续推进属于05通知接口：目标保持ACTIVE，同轮不重发；详情之后仍可主动结束。重新满足条件可开新轮，不能通过刷新把CONTINUED伪造为false→true。通知投递异步，核心完成事务只持久化outbox依据；重试/迟到事件不能改更高轮通知。

**自动开始与延期。** 业务今天由账户当前有效时区得出；开始边界使非归档且未完成目标进入ACTIVE，不安排任务。自动延期只处理ACTIVE、未归档且今天晚于expectedEndDate：

```text
B = 最近一次人工设置的 [startDate, expectedEndDate] 含首尾日历天数，至少1
P = C/N；N=0时仅为延期计算取0
Δ = max(1, ceil(B × 0.30 × (1-P)))
新expectedEndDate = max(旧expectedEndDate, 业务今天-1天) + Δ天
```

计算用整数有理数或精确十进制，不能用显示百分比和二进制浮点舍入。B=30且P=0/50%/90%/100%时Δ分别9/5/1/1。今天2026-10-18、旧预计10月17日、B30/P50%时新预计10月22日；长期未访问旧预计9月30日且P0时新预计10月26日，不能从9月30日起按天循环叠加。自动延期不改B；人工日期实际变化才重算B。保存旧新日期、B/N/C和原因至EXTEND节点；重复处理已更新预计日期不再延期。完整调度/补偿设计见[11 系统自动处理与跨模块业务流程](A07-系统处理.md)。

**安排迁移与历史归属。** task_assignment的task_id是主键。DAY在同一个命令中取得对应周、日身份，再更新该唯一行；跨周同时换周和日，WEEK保留周并清日，POOL删除当前安排。运行任务确有去向变化先暂停，段终点按合法最终确认或旧可信T确定。事务失败不能留下“已暂停但安排没保存”的本命令半成品；已经发生并独立提交的到期暂停不随本命令失败回滚。历史focus_segment的weekly_plan_id、daily_plan_id、scheduled_date与时区固定，迁移只改当前关系，绝不整体搬走旧投入。

日结束仅检查当日有具体日安排的未完成任务，周结束检查整周全部未完成任务；周日结束与周末使用同一本地午夜边界，WEEK合并覆盖原DAY待处理，同一任务只有一条PENDING。边界前已完成/主动移出/迁移/归档撤出的任务不再生成旧待处理。系统暂停越界执行，等待用户新安排，不自动推到今天，不复制计划任务。过去视图readOnly=true；从当前任务/待处理入口用TASK-007重排，与编辑过去日是不同操作。

**无外键时的删除顺序。** 先查本人父链及版本 → 扫完整RUNNING/PAUSED集合 → 查当前安排及全部永久历史引用 → 显式清/改可变关系 → 无永久引用才物理删，否则保留身份 → 同事务更新父/计划版本、进度条件及去重结果。任务开始过即使0秒也保留；阶段当前有效DONE任务同样阻止“空阶段删除”；历史删除任务不阻止空阶段清理。普通新阶段已有永久CREATE节点，因此通常HISTORY_RETAINED。周/日历史归档不清除唯一周期身份，后续合法当前/未来规划复用原ID。所有读写均校验user_id，不能只查UUID或相信管理员角色。

**示例与验收约定。** 以下示例为彼此独立的合成场景，默认账户业务日2026-10-18、Asia/Shanghai，本周10月12日至18日；10月19日至25日为未来周。每条成功JSON展开完整data，字段类型由本章唯一DTO定义；示例不代表已实现返回结果。每条功能测试均为待实现后执行的设计用例（NOT_VERIFIED），数据库断言在真实PostgreSQL验证。只读一致性汇总按02第6节；关键命令在运行护栏共享锁→账户控制锁→业务对象的顺序下重读，版本条件更新影响行数须为1。

### API-GOAL-004 修改目标信息和日期

#### 需求分析

**入口：** 目标详情 → 编辑目标。**前置：** 目标未归档且未完成；提交刚读取的目标版本。

### API-GOAL-007 确认完成或主动结束目标

#### 需求分析

在全部任务完成后确认目标，或在工作已足够时主动结束并冻结真实结果。

**入口：** 目标详情结束按钮；完成确认通知 → 确认结束。**前置：** 未归档、未结束；所有相关执行已结束；用户确认本次结束含义。

#### 业务流程

1. 校验confirmed及endType对应字段；取得账户锁，重读state、版本、全部未结束执行及当前有效C/N。
2. ALL_TASKS_CONFIRMED要求ACTIVE、N>0、C=N且conditionRound匹配；条件变化返回CONDITION_CHANGED，不替用户换成主动结束。

4. 按当前cycle_no保存唯一goal_closure，冻结名称、日期、完成条件、C/N及真实投入；N=0时percent=null。
5. 目标置COMPLETED并写closed_at，撤出未完成安排、失效旧确认、追加CLOSE；提交后返回目标和本版快照。

### API-GOAL-008 重新打开已结束目标

#### 需求分析

保留上次结束结果，重新开启同一目标下一轮推进。

**入口：** 已完成目标详情 → 重新打开确认弹窗。**前置：** state=COMPLETED且未主动归档；当前轮结束快照完整可查。

**依据：** FR-GOAL-011；BL-GOAL-005。

#### 业务流程

1. 核验本人目标、版本和COMPLETED；若仍归档则返回STATE_CONFLICT，引导先restore。
2. 读取当前cycle_no对应closure；缺失或跨账户视为关联损坏，拒绝并内部告警。
3. cycle_no加1、closed_at清空、按开始日恢复PENDING/ACTIVE并补必要延期；保留全部旧closure。
4. 已完成任务继续DONE，有效未完成任务回池，已删除任务不恢复；不重建任何旧安排或执行。
5. 重新评估新推进轮的完成条件：若ACTIVE且仍N>0/C=N，建立新条件轮次与outbox依据；不能沿用旧通知。

本人权限；写请求头按[公共规则](#11-路径权限请求头和基本类型)。Query：无。

### API-STAGE-005 暂停阶段

#### 需求分析

**入口：** 阶段详情 → 暂停。**前置：** 未删除、未DONE，父目标允许推进；finalConfirmation只可由当前控制页提供。

4. 运行执行置PAUSED，任务置PAUSED，执行控制换代并清除活动许可；已暂停执行保持原事实。

### API-TASK-002 分页查看任务池、已安排或历史任务

#### 需求分析

### API-TASK-005 确认完成任务

#### 需求分析

**入口：** 任务详情/看板/计划 → 完成确认。**前置：** 任务未删除未DONE；目标ACTIVE、阶段可推进；安排今天或本周无指定日；所有执行已结束。

1. 按destination严格校验互斥日期：POOL无日期；WEEK只weekStartDate；DAY只planDate；不接收任意周日身份。
2. 锁内重读任务/父状态/版本及旧安排；WEEK所选周至少一天不早于目标/任务开始，DAY不早于两者开始日。预计结束与dueDate均不作为重排硬上界。
3. 目标周期身份按(user_id,week_start_date)/(user_id,plan_date)唯一取得；必要时创建/复用归档身份，日必属同一周。
4. 实际去向变化且本任务RUNNING时，验证可选finalConfirmation后暂停：有确认保存确认点，无确认截旧T；段保留旧计划/时区上下文。
5. 在同一事务更新唯一task_assignment或POOL删除；DAY填新日身份，WEEK清日身份，清除旧pending四字段；计划队列末尾排序。
6. 更新task与新旧周日版本，旧日/周不留独立“已改期/原未完成”任务；focus_session仍同一本次、paused累计保留。 若相同去向没有实际变化则返回现状，不因重复保存暂停运行任务或重复增版本；提交后刷新所有affectedPlans与任务池。

### API-PLAN-009 删除周计划或归档其真实历史

### API-PLAN-010 删除日计划安排或归档其真实历史

#### 需求分析

**入口：** 日计划 → 删除日安排确认。**前置：** 本人日与周归属一致；该日全部当前或历史关联执行已结束。

**依据：** FR-DAY-008；BL-DAY-007、BL-HISTORY-005。

#### 业务流程

1. 锁内查日/周、版本与全部历史关联执行，包含已迁出任务的PAUSED。
2. 清当前任务daily_plan_id，保留weekly_plan_id，把条目移入该周无日期队列末尾；不是删除任务或撤销周安排。

4. 无必要历史的日可DELETED，有完成/执行事实或必须保留的过去身份则ARCHIVED；已完成结果不可清除。
5. 日、周、任务与安排版本同事务；过去仅清理当前关系/归档历史，绝不编辑已发生顺序、完成或时间。

### API-PLAN-012 查看计划历史周期与真实贡献摘要

#### 需求分析

**入口：** 成长历史 → 计划历史 → 日期范围。**前置：** 本人范围；支持完整三年及更早历史，单次一致性汇总与明细分页。

### 7.1 一次手工联调需要观察什么

1. 先查询目标/任务，保存返回的当前 version；修改后的下一步使用新版本，不能硬编码 "0"。
2. 创建目标→阶段→任务后，直接执行或完成任务应拒绝，因为没有周计划。
3. 取得本周计划，TASK-007 以 WEEK 安排；无日期任务本周可执行，不必先建立今日日计划。
4. 改为 DAY 后，只能在指定日执行；今天改到明天后今天立即不可执行。
5. 已执行任务改期时，本次执行暂停且累计保留，旧日任务列表移除；旧日真实投入仍可查。
6. 完成任务先结束其未结束执行；TASK-005 成功后查到 task_completion 和 DONE，当前安排行不再存在。
7. 最后一项完成只进入目标待确认；GOAL-007 才形成目标本版 closure。任务删除造成 C=N 也只产生确认。
8. 有 PAUSED 执行时归档目标、删除任务或计划均拒绝，并给出所有相关执行；不能仅因为当前没有 RUNNING 就通过。
9. 删除已执行/已完成任务后，当前 C/N 改变，历史完成和时间不减少，旧 closure 不改变。
10. 并发创建同周、同日安排和原键重试不生成第二份身份；相同键修改参数必须拒绝。
11. 打开过去日是只读；从当前任务迁出是独立用例，不要求给原日保留“已改期”条目。
12. 归档恢复、目标/阶段重开不恢复删除任务、不撤销已完成任务、不自动还原旧计划或开始执行。
