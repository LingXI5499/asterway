### 2.1 请求与响应

- 全部路径以前缀 `/api/v1` 开始。请求与响应字段使用 camelCase；写请求正文为 JSON 对象，拒绝未声明字段。
- UUID 以标准 UUID 字符串传输。日期为 `YYYY-MM-DD`；时刻为 UTC ISO 8601，使用 `Z`，小数最多 6 位。
- bigint 版本、秒、毫秒、微秒时长以十进制字符串传输，不经过 JavaScript number；普通分页数量、像素尺寸、人数与偏移坐标为 number。
- 成功统一返回 `code、message、data、traceId`；`code=OK`。创建资源使用 HTTP 201，其他成功使用 HTTP 200；不使用 HTTP 204。错误保持相同外壳，HTTP 状态表达错误类别，`data` 不含密码、哈希、验证码答案或会话秘密。
- 每个本文列出的写请求都带 `Idempotency-Key` 和 `X-CSRF-TOKEN`。前者为本次用户意图的 UUID 字符串；后者从 API-AUTH-001 获取。无副作用的 GET 不带这两个写请求头。
- 普通更新在 Body 带 `expectedVersion`；DELETE 在 Query 带 `expectedVersion` 和 `confirmed=true`；动作 POST 带 `confirmed=true`。注册、登录、挑战创建及验证是专用提交，不额外要求确认布尔字段。
- 字段标注“可选”表示可以不传；除明确允许外，显式 null 不等于不传。密码、确认密码、原密码从不放入 URL。
- 当前本人身份只从已验证会话取得。个人接口禁止请求传入 userId、ownerId、role、securityVersion、usernameKey 等内部或所有者字段；后台 Path 的 accountId 只表示管理目标，不表示允许冒充该账户。
- GET 返回无结果集合时使用空数组，分页为 `items、nextCursor、hasMore`，其中 nextCursor 可空。Query 的 limit 默认 20、范围 1—100；cursor 为服务端生成的不透明字符串，不允许前端拼装。
- 本文认证与后台响应使用 `Cache-Control: no-store`。Cookie、CSRF、滑动凭据只用于当次会话和操作，不放入 localStorage、URL、错误上报或普通日志。

### 2.2 身份、权限与框架会话

生产同域会话 Cookie 使用 Secure、HttpOnly、SameSite=Lax，具体站点作用域遵循架构约定。前端通过同域入口访问，不自行保存可当作登录身份的用户编号或角色。

Spring Session 的唯一认证 principalName **固定为稳定账户 UUID 字符串**，不能使用会变化的用户名。框架安全主体的 getName 语义也为该 UUID；展示用户名另从账户资料读取。匿名会话无认证 principal，只保存随机匿名操作作用域、CSRF 等必要短期状态。

已登录会话保存本次建立时的 credentialVersion、securityVersion、restoreEpoch 等校验依据。每次受保护请求核对当前账户、版本、删除与启用状态；运行重启与灾难恢复分别遵循架构门禁。loginNameVersion 用于登录名并发及恢复核验，**不能因为改名而使全部现有会话失效**。

后台授权矩阵如下；本人资料始终从个人接口维护。

| 操作者 | 允许查询或管理的后台目标 | 允许创建的角色 | 后台配置 |
|---|---|---|---|
| USER | 无 | 无 | 无 |
| ADMIN | USER；包括该范围内的禁用、逻辑删除摘要 | USER | 无 |
| SUPER_ADMIN | USER、ADMIN；不通过这些接口管理 SUPER_ADMIN | USER、ADMIN | 可读取和修改固定两项 |

普通管理员不能查询或修改同级、上级账户。管理员对范围外 accountId 的资源请求统一返回 404 NOT_FOUND，避免披露该账户是否存在；普通用户访问后台入口返回 403 FORBIDDEN。超级管理员初始化、修复和必要运维核验另走受控流程，不以本文件增加超级管理员管理产品功能。

### 2.3 字段规则

| 字段 | 类型与规则 |
|---|---|
| username | string，必填时 1—30 个 Unicode 码点；仅 ASCII 英文字母、数字、汉字；不允许空格、下划线或其他符号；不自动 trim；英文大小写不影响唯一性或登录匹配，展示保留原形式 |
| nickname | string，提供时 1—30 个 Unicode 码点，不能全为空白；可重复；创建时省略则取该次注册或后台创建的用户名，后续改名不联动昵称 |
| password／initialPassword／newPassword／confirmPassword | string，新密码 8—50 个 Unicode 码点，包含端点，全空白视为空；不 trim、不截断、不因弱密码拒绝；确认密码必须逐字符相等 |
| currentPassword | string，原密码，不 trim；为空或输入编码无效拒绝；提供的非空错误值作为原密码校验失败处理 |
| expectedVersion | 十进制字符串，表示所更新对象的非负 bigint version，不接受小数、负数、科学计数法或超出 bigint 范围 |
| zoneId／detectedZoneId／initialZoneId | string，1—64 个字符；服务端当前受支持的有效 IANA 时区名，不接受仅偏移量、地区名称或语言名 |
| role | USER／ADMIN／SUPER_ADMIN 的固定枚举；只有明确允许选择角色的后台字段可提交 USER／ADMIN |
| status | ENABLED／DISABLED；逻辑删除以独立 deletedAt 表示，不增加可由前端直接写入的 DELETED 状态 |

前后端使用相同 Unicode 码点口径，测试补充平面汉字和表情的边界。密码强度只在前端按现行业务规则 显示“弱、低、高、强”，不新增后端强度门槛。本文不设计用户名可用性探测接口；唯一性以实际保存为准。

### 2.4 公共错误与提交规则

| HTTP | code | 本文使用场景 |
|---|---|---|
| 400 | VALIDATION_ERROR | JSON、基础类型或UUID语法解析失败 |
| 422 | VALIDATION_ERROR | 字段范围、长度、未知或不可写字段、确认、版本值或游标校验失败 |
| 401 | AUTH_REQUIRED | 未登录、会话失效或凭据版本失效 |
| 401 | CREDENTIALS_INVALID | 登录凭据错误；message 固定“用户名或密码错误” |
| 403 | FORBIDDEN | 角色不允许访问入口 |
| 403 | CSRF_INVALID | CSRF 缺失、失效或不匹配 |
| 403 | REGISTRATION_CLOSED | 公开注册当前关闭 |
| 403 | ACCOUNT_UNAVAILABLE | 凭据正确但账户被禁用或受恢复核验隔离；不披露内部隔离原因 |
| 404 | NOT_FOUND | 对象不存在或处于操作者管理范围之外 |
| 409 | VERSION_CONFLICT | expectedVersion 落后；返回允许披露的当前对象或当前版本 |
| 409 | STATE_CONFLICT | 已删除、状态不允许、验证用途或消费状态冲突 |
| 409 | IDEMPOTENCY_KEY_REUSED | 同一幂等键携带不同契约参数，不能借此改写原意图 |
| 409 | REQUEST_IN_PROGRESS | 原意图仍处理中；data提供retryAfterSeconds字符串 |
| 409 | USERNAME_TAKEN | 保存时用户名键被占用，含逻辑删除账户仍占用的名称 |
| 409 | UNFINISHED_EXECUTION | 本人改密或正常退出时仍有 RUNNING／PAUSED 执行 |
| 400 | CAPTCHA_INVALID | 滑动位置错误、挑战材料无效或过早提交；不增加凭据失败计数 |
| 410 | CAPTCHA_EXPIRED | 挑战或其验证凭据到期，须重新验证 |
| 423 | ACCOUNT_LOCKED | 连续凭据错误达到 5 次后处于 5 分钟临时锁定；提供剩余等待信息 |
| 400 | CURRENT_PASSWORD_INVALID | 本人改密的原密码错误；不返回原密码，也不复用登录失败次数规则 |
| 429 | RATE_LIMITED | 工程流量限制；与 5 次凭据错误锁定区别，遵循 Retry-After |
| 503 | RESULT_UNKNOWN | 提交结果暂不能确认；按原意图核实，不能生成新意图自动重做 |
| 503 | SERVICE_UNAVAILABLE | 依赖不可用、恢复门禁未开放或安全核验依据不可用 |

通用错误 data 可为 null；字段错误可为 `violations` 数组，每项含 field、message；版本冲突提供已授权对象的currentVersion字符串，不回显提交的密码或验证凭据。本文特定错误可另外提供明确定义的安全字段。traceId 是排障标识，不是重试或授权凭据。下文逐接口列出的VALIDATION_ERROR继承400／422的上述区分，不能因为简写错误类别而混用HTTP状态；普通请求体超限依02返回413 PAYLOAD_TOO_LARGE。

所有写入先做身份及 CSRF 检查，再检查已提交意图，最后检查新操作的expectedVersion和状态。包含密码或验证凭据的参数指纹使用服务端独立受控密钥计算的不可逆认证摘要；不得将原文、可离线枚举的无密钥快速摘要或完整请求体保存在 DB-30、日志或技术快照中。相同意图的认证失败只记一次；换参数使用原键返回 IDEMPOTENCY_KEY_REUSED，不走STATE_CONFLICT。所有接口继承02的同键异参、处理中、授权及语法错误，即使逐条未重复列出这些公共错误；STATE_CONFLICT仅用于真正业务状态冲突。

必要到期清理使用独立短事务可靠保存，不能被随后的业务拒绝回滚。具体数据事务遵循运行护栏、管理锁及账户锁顺序；涉及独立安全账本的登录标识、密码、权限、禁用删除和撤销操作沿用架构第 12.2 节的意图预记、事务重验、提交确认和未决隔离协议。

会话不是认证接口可反复返回的秘密。认证结果的去重记录只保存结果引用与非敏感状态，不保存可重放 Set-Cookie 的值。需要重建浏览器会话时重新走合法登录，不通过匿名幂等结果查询取得账户会话。

重新合法登录后，本文账户作用域的原意图可通过02的API-COMMON-001核实：GET `/api/v1/operations/{idempotencyKey}`，Query的operation为原API编号，例如API-AUTH-008或API-AUTH-009。只查询当前稳定UUID的USER作用域，不返回密码或旧会话，不执行原动作；404 OPERATION_RESULT_NOT_FOUND只表示查询不到有效记录，不能证明操作未发生。匿名注册／登录作用域不通过这个本人结果接口公开查询，仍按当前会话、原匿名作用域与原意图核实规则处理。

## 4. 滑动拼图规则

| 项目 | 设计默认 |
|---|---|
| 有效期 | 120秒；验证成功不延长 |
| 尺寸 | 背景320×160；拼图40×40像素 |
| 校验 | 服务端判定；客户端只报原图水平位移 |
| 猜测 | 每挑战1次有效猜测；失败即作废 |
| 失败计数 | 滑动失败不计用户名/密码错误次数 |

<details>
<summary>展开：容差、限流、短期凭据、幂等与保存细则</summary>


采用服务端生成的图片拼图验证，不采用“前端滑条到尾即通过”或客户端布尔值。服务端保存实际孔位与短期校验依据，返回背景和拼图图片；客户端只报告按原图坐标换算的拼图水平偏移，服务端判断。

| 工程项 | 工程默认 | 可配置类型与边界 |
|---|---|---|
| 挑战有效期 | 120 秒，自签发起算，验证通过不延长 | 服务端正整数秒；实际过期时刻由 expiresAt 返回 |
| 图片原始尺寸 | 宽320、高160像素；拼图片40×40像素 | 服务端正整数；前端按响应尺寸换算，不能写死缩放后的像素 |
| 水平容差 | ±4 个原图像素 | 服务端非负整数，不返回实际孔位或判定误差 |
| 最早验证时间 | 签发300毫秒后 | 服务端非负整数毫秒；不信任客户端提交的耗时 |
| 同一挑战的有效猜测 | 1 次；失败即作废，重新取图 | 服务端固定单次策略；本版不以无限试位置替代交互验证 |
| 取图流量初始上限 | 每匿名会话每60秒最多20次 | 服务端正整数窗口与次数，超限429；另有入口总体限流，不得将此数当业务使用配额 |
| 挑战及结果保存 | 只在挑战短期有效窗及必要短期清理窗口内保留 | 服务端正整数期限；不往永久去重表无限积累图片或验证轨迹 |

随机图片和一次性验证凭据由安全随机源生成。挑战绑定当前匿名会话、用途及操作意图；认证成功轮换会话标识后，仍按受控匿名作用域识别同一认证意图，不得将匿名标识当认证 principal。

验证码验证通过产生随机短期 verificationToken，使用32字节安全随机值的小写十六进制表示，固定64个ASCII字符；所有captchaVerificationToken字段按此格式校验。DB-07 的受保护 verification_data 保存验证状态及凭据校验／必要受控重取材料。verificationToken 不是登录凭证，只能连同同一挑战、同一浏览器绑定、匹配用途用于一次注册或登录。验证通过时不写 consumedAt；认证提交实际消费时才写入 consumedAt，并绑定认证意图。错误猜测则立即使挑战失效。

同一创建或验证意图的重试，只能在仍有效时取回原结果，不重新签发期限；敏感原值若需重取，只从受保护短期材料读取，不放进长期 DB-30 快照。验证码失败、超时、用途错误、CSRF失败和工程限流均不增加用户名／密码错误次数。图片拼图只是反自动化措施，不能宣称强身份验证，也不能宣称已经抵御自动识图。

</details>

## 8. 请求链路与必须验证的边界

### 8.1 注册与登录页面的调用次序

1. 读取API-PUB-001站点状态；获取API-AUTH-001匿名CSRF。
2. 注册时识别有效IANA时区，失败则通过API-PUB-002明确选择；登录时不借登录请求悄悄修改业务时区。
3. API-AUTH-002签发本用途图片；API-AUTH-003服务器验证成功后取得短期凭据。
4. 用本次注册／登录意图的独立Idempotency-Key提交API-AUTH-004或005。取图、验证、认证提交是不同意图；同一个意图的网络重试保持原键。
5. 登录成功使用新CSRF，读取本人受保护状态；设备与账户时区确实不同，再以最新version调用API-AUTH-010。不能预先补算未确认的专注时间。

### 8.2 无物理外键时的会话清理

框架会话删除不能只移除父行后把属性留成孤儿，也不能只删除属性而让其他请求把它写回。DB-34父会话行是仓库串行边界：注销、过期清理、属性写入均按相同父行锁规则运行；删除时显式清理DB-35和DB-34。业务账户安全版本是撤销即时生效的判断，物理清理是可靠补偿；两者分别记录结果。后台批量会话清理不能反向先占框架行锁再等待账户锁。

### 8.3 契约验收清单

| 检查场景 | 预期结果 | 对应接口和业务依据 |
|---|---|---|
| 先打开注册页，随后超管关闭注册，再提交注册 | 创建前查最新开关；无半账户 | AUTH-004、ADMIN-009；BL-AUTH-001、BL-ADMIN-003 |
| 两请求同时注册英文大小写不同的同一用户名 | 只有一个账户；另一个USERNAME_TAKEN | AUTH-004；BL-AUTH-001 |
| 7／8／50／51码点新密码、全空白、相同前缀不同尾部 | 8／50允许；7／51和全空白拒绝；完整输入参与Argon2id | AUTH-004、008、ADMIN-004；NFR-SEC-005、006 |

| 同一错误登录的响应丢失后用同键重试 | 原失败只计一次；不重新消费挑战 | AUTH-005；NFR-REL-003、007 |
| 用户改名后再用旧用户名登录、原页面继续访问 | 旧名不再匹配原账户；已有稳定UUID会话仍可访问 | AUTH-007、ADMIN-005；BL-AUTH-005 |
| 仅有PAUSED执行时退出或改密 | 拒绝并引导先结束；不能改成自动暂停后放行 | AUTH-008、009；BL-AUTH-003、004 |
| 管理员禁用、删除或撤销正在计时的用户 | 按最后可信点暂停、旧代次失效、旧授权下一次请求拒绝 | ADMIN-005—007；BL-ADMIN-002 |
| 旧会话物理清理失败 | 已提交安全版本仍拒绝旧凭据；补偿重试，不能恢复旧许可 | AUTH-008、ADMIN-005—007；NFR-SEC-007 |
| ADMIN查询ADMIN账户、请求SUPER_ADMIN创建或变更 | 返回范围错误，不披露或修改同级上级身份 | ADMIN-002—007；现行业务规则第12章 |
| 逻辑删除有历史账户，再注册相同用户名 | 历史和稳定UUID保留；该保留行当前用户名仍占用 | ADMIN-006、AUTH-004；数据库身份唯一设计 |
| 两设备自动上报不同时区、跨日期线、本地日期重复 | 按版本冲突同步，不循环覆盖；旧日结束生效，过去归属不重排、不重复结算 | AUTH-010；现行业务规则第2.3节、NFR-TIME-008 |
| ADMIN读取后台配置、超管提交第三个配置键 | 都拒绝；两项配置保持原值 | ADMIN-008、009；BL-ADMIN-003 |
| 两项配置一项版本过期 | 整批拒绝；不能一项成功一项失败 | ADMIN-009；NFR-REL-002 |

上述是待实现的验收用例，不是运行证据。实施开发完成后需记录实际请求、数据库状态、失败注入与响应，再填写通过／失败结论。
