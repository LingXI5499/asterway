# Identity 后端实现与启动说明

2026-11-04。本轮完成 common 与 identity 后端编码。按用户要求，只执行 Maven 编译打包和应用启动检查，没有新增或运行单元、系统、集成测试，也没有运行接口业务验收。

## 模块与调用链

app 仍只有一个启动类、本地 YAML 与业务 SQL。common 不依赖业务工程，通过中立接口接入账户数据和失败审计。其他九个业务工程继续保留空框架，新前端本轮未开发。

| 主体 | Entity / Mapper | Service 接口与实现 | Controller |
|---|---|---|---|
| 用户 | UserEntity、UserMapper/XML；内部维护 UserRoleMapper/XML | UserService / UserServiceImpl | UserController |
| 角色 | RoleEntity、RoleMapper/XML；内部维护 RolePermission、RoleMenu 关联 | RoleService / RoleServiceImpl | RoleController |
| 权限 | PermissionEntity、PermissionMapper/XML | PermissionService / PermissionServiceImpl | PermissionController |
| 菜单 | MenuEntity、MenuMapper/XML | MenuService / MenuServiceImpl | MenuController |
| 设置 | SettingEntity、SettingMapper/XML | SettingService / SettingServiceImpl | SettingController |
| 登录日志 | LoginLogEntity、LoginLogMapper/XML | LoginLogService / LoginLogServiceImpl | LoginLogController |
| 操作审计 | OperationLogEntity、OperationLogMapper/XML | OperationLogService / OperationLogServiceImpl | OperationLogController |

总计十个 Entity、十个 Mapper/XML、七组 Service 接口与实现、七个 Controller。关联表由所属用户或角色事务维护，不增加无意义的关联表 CRUD 接口；同一主体的查询、新增、修改与删除不拆成独立服务。

DTO 负责请求校验，VO 只返回安全字段，Controller 只做 HTTP 接入。所有数据访问 SQL 在 XML 中，Service 实现承担状态、权限、引用、事务与版本校验。

## common 公共能力

| 内容 | 实现 |
|---|---|
| 统一结果 | common.result.ResultVO；字段 code、message、data、traceId |
| 分页 | PageQueryDTO / PageResultVO，页码从 1 开始，默认 20，最多 100 |
| 异常 | BusinessException、GlobalExceptionHandler；安全过滤器使用相同结果结构 |
| 安全 | SecurityConfig、JwtAuthenticationFilter、PermissionGuard、SecurityUtils |
| JWT | 固定 HS256、签发者及受众，JWT 不携带权威权限快照 |
| 会话 | RedisSessionStore，独立登录会话、用户索引、全局索引、原子续期与撤销 |
| 验证码 | 本地 PNG 拼图、场景与浏览器随机标识绑定、一次性票据 |
| 限流 | RedisAttemptStore，来源限流、五次凭据错误锁定五分钟 |
| 基础配置 | MybatisConfig、JacksonConfig、OpenApiConfig、StartupConfig |
| 工具 | JSON、请求信息、账户字段校验、提交后清理与图片生成工具 |

common 的 AccountSecurityProvider 由 UserService 实现；OperationAuditProvider 由 OperationLogService 实现。公共模块不直接读取身份业务 Mapper，也不设置额外的用例编排层。

统一返回命名已采用 ResultVO，包为 common.result，不使用自定义 Response 类或 response 包。框架本身的 HttpServletResponse、ResponseEntity 等类型正常保留。

## 已编码业务

- 注册、登录、一次性拼图票据与失败锁定；公开注册仅关联 USER，注册成功不自动登录。
- 用户名、昵称、密码、时区管理；密码使用 Argon2id。本人改密校验原密码并撤销全部旧会话。
- 多端独立登录与设备列表；退出当前、指定、全部设备，后台按管理范围强退。
- 连续七天无有效操作过期；成功业务请求原子续期 Redis，并通过 X-Session-Token 返回配套新 JWT。
- 设备列表、后台会话列表和退出请求不负责保活；过期或撤销的会话不会被续签重新创建。
- 当前请求检查数据库账户状态、安全版本与最新角色权限；停用、删除、改密、重置密码、退出全部设备会使旧身份失效。
- 管理员只管理普通账户；超管授予或撤销 ADMIN，保留 USER；SUPER_ADMIN 不通过管理接口增删。
- 三角色展示信息、权限集合和菜单集合维护；USER 核心账户能力及 SUPER_ADMIN 核心授权受保护。
- 权限与菜单维护，关联有效性、循环父链、组件白名单、内置编码和删除引用保护。
- 站点名称与注册开关；注册写入与后台关闭开关通过事务锁协调。
- 登录成功失败记录、成功业务审计、已认证写请求的业务拒绝审计；不记录请求体、密码、令牌或验证码答案。

所有管理写操作使用统一角色安全门锁协调身份与授权变更；用户状态操作再锁定目标账户。数据库 version 防止覆盖其他操作，auth_version 防止旧会话继续认证。数据库提交后的批量 Redis 清理失败时，数据库安全版本仍阻止旧身份访问。

临时设备描述来源于浏览器信息，仅用于显示，不作为永久设备指纹或授权依据。客户端需要在登录状态中保存当前会话标识，丢弃退出后的迟到响应，并只接受同一会话较新的续签结果。

## 接口与运行

接口统一使用 /asterway，保持 [接口与权限清单](接口与权限清单.md) 中的资源划分。当前后端声明 49 个 HTTP 映射，接口实现仍需要后续业务验收。

从仓库根目录准备本地依赖并打包：

```powershell
.\scripts\start_identity_local.ps1
mvn -B -ntp -f backend/pom.xml '-Dmaven.test.skip=true' clean package
java '-Dfile.encoding=UTF-8' -jar backend/app/target/app-0.1.0-SNAPSHOT.jar
```

app 的 application.yml 为唯一开发配置。PostgreSQL、Redis 均连接本机 127.0.0.1，不使用远程数据库、环境变量或多环境 profile。原有 Java 17、Spring Boot、MyBatis 等版本保持不变。移除不再使用的 Spring Session JDBC，引入由原 Boot 版本管理的 Redis 与 JWT 支持依赖。

本机其他项目占用 8088，本项目已在本地 YAML 中改为 8089，不停止其他项目。默认启动后访问 `http://127.0.0.1:8089/swagger-ui/index.html`。需要其他端口时可通过启动参数显式覆盖。

本地接口文档路径为 `/swagger-ui/index.html`，接口 JSON 为 `/v3/api-docs`。登录和验证码入口公开，其余接口按身份与方法权限处理。框架默认的内存用户、Basic 和表单登录已关闭。

本机 JWT 签名材料与数据库连接默认值仅用于本地开发，不作为部署配置。初始 superadmin 仍使用此前 SQL 阶段设置的私有初始密码，首次登录后仅能访问改密所需接口，完成改密会退出全部旧会话。
