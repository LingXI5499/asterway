## 关键实测场景

| 场景 | 输入或操作 | 实测预期 |
|---|---|---|
| 用户名边界 | 单字、30 字、中文英文数字、扩展汉字 | 可写入 |
| 非法用户名 | 空、空格、下划线、表情、31 字 | 数据库拒绝 |
| 大小写重复 | LingXI 后写 lingxi | 唯一约束拒绝 |
| 已删用户名 | 再写已逻辑删除账户的同名 | 仍拒绝，不复用 |
| 关联重复 | 相同用户角色、角色权限、角色菜单 | 联合主键拒绝 |
| 本人权限 | USER 账户 | 仅七项本人能力 |
| 管理员权限 | USER + ADMIN | 19 项权限，没有角色分配和授权维护能力 |
| 普通管理范围 | 普通、管理员、超管、禁用、删除账户 | 包含普通和禁用普通账户，排除管理员、超管和已删除账户 |
| 菜单不等于权限 | 给 USER 增加用户管理菜单，不给动作权限 | 用户管理页仍不进入有效页面查询，API 权限集合不变 |
| 父菜单停用 | 停用系统管理目录 | 子页面不进入有效菜单树 |
| 并发注册 | 两事务同时插入同一用户名 | 只有一次成功，一次唯一冲突 |
| 注册被关闭 | 关闭设置事务持锁，注册事务等待重读 | 注册读到关闭状态，不创建用户 |
| 最后一个超管 | 两事务尝试分别停用仅剩的两个超管 | 超管角色行串行保护，一次停用，一次被保护 |
| 事务回滚 | 用户创建后角色写入错误；授权替换后写入错误 | 不留下半个账户或半套授权 |
| 版本冲突 | 两个旧 version 更新 | 一次生效，另一次 0 行 |
| 时区 | 合法与非法 IANA 查询、纽约夏令时两天 | 能区分有效名称；日长度分别 23/25 小时 |
| 待生效时区 | 未到时刻、已到时刻、再次执行 | 不提前切换，到期只应用一次 |
| 逻辑删除 | 写日志后停用并删除账户 | 有效权限清空，日志仍保留 |
| 审计数据库角色 | 用应用角色插入日志，再修改或删除 | 可追加，不能修改或删除 |
| DDL 失败 | 初始化末尾注入非法配置 | 该初始化事务内所有表回滚 |
| 重复初始化 | 对已有同名表重新执行 SQL | 失败且现有数据不变 |
| 无外键边界 | 直接写入不存在的用户角色关联 | 数据库允许；检查查询能识别，后续 Service 必须拒绝 |
| 多节点菜单循环 | 直接写入两节点父链循环 | 检测查询识别，菜单查询不会无限递归；后续 Service 必须拒绝写入 |

测试报告保留 SQL SHA-256，与本次交付文件一致。索引测试在小样本下关闭顺序扫描，仅证明目标查询可以使用索引，不代表大数据性能验收。

## 本地使用与复测

Windows 仓库根目录执行：

```powershell
.\scripts\start_identity_local.ps1
```

脚本会保持当前 Ubuntu 实例运行并核对两个本机端口。本机 WSL 在没有前台进程后会自动停止，仅安装 systemd 服务不足以维持 Windows 连接。脚本不修改全局 WSL 网络配置。结束保持进程可执行：

```powershell
.\scripts\start_identity_local.ps1 -Stop
```

停止保持进程不删除数据库文件，不主动 terminate Ubuntu 或停止其他项目。连接均使用 127.0.0.1，WSL 服务只监听 loopback，不开放公网。

复测会清空并重建专用测试库的 public schema，不触碰开发库：

```powershell
wsl -d Ubuntu -u root -- runuser -u postgres -- python3 scripts/test_identity_sql.py --reset-test-schema --report /tmp/asterway-identity-sql-test.json
```

从仓库根目录运行，WSL 会继承当前工作目录。复测依赖本地 Ubuntu 的 python3-psycopg2、python3-argon2。服务安装与版本参考 [PostgreSQL Ubuntu 官方说明](https://www.postgresql.org/download/linux/ubuntu/)。软件安装后，[本地数据库准备脚本](../../scripts/setup_identity_local.sh)只创建缺失的本项目库与开发角色，不执行业务 SQL。

[开发库初始化脚本](../../scripts/init_identity_local.py)只接受本机 asterway_dev，要求 public schema 为空，使用同一事务建立结构、角色授权及初始超管，遇到已有表或已存在的凭据输出文件会拒绝覆盖。初始超管密码不可通过 SQL、目录元数据或日志查询取得；开发数据库连接口令为仅供本机的明确默认值，保存在 app 本地 YAML，不能用于生产。
