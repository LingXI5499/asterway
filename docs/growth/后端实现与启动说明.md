# 核心成长后端实现与启动说明

## 实现顺序与职责

按 entity → Mapper/XML → DTO/VO → Service 接口/实现 → Controller 完成，最后更新 Identity 权限、菜单与初始化。没有新增业务模块之间的 Maven 依赖，版本保持不变。

| 业务主体 | 模块 | 单表链路 |
|---|---|---|
| 目标 | goal | GoalEntity / GoalMapper / GoalService / GoalServiceImpl / GoalController |
| 阶段 | stage | StageEntity / StageMapper / StageService / StageServiceImpl / StageController |
| 任务 | task | TaskEntity / TaskMapper / TaskService / TaskServiceImpl / TaskController |
| 周计划 | planning | WeeklyPlanEntity / WeeklyPlanMapper / WeeklyPlanService / WeeklyPlanServiceImpl / WeeklyPlanController |
| 日计划 | planning | DailyPlanEntity / DailyPlanMapper / DailyPlanService / DailyPlanServiceImpl / DailyPlanController |
| 任务安排 | planning | TaskAssignmentEntity / TaskAssignmentMapper / TaskAssignmentService / TaskAssignmentServiceImpl / TaskAssignmentController |

规划中的跨表只读投影由 PlanningTaskMapper 查询，仍使用 XML；不拆额外“查询 Service”。common 内的 GrowthContextUtils、GrowthSupportMapper/XML 负责用户写锁、日期、归属投影与跨模块引用处理，common 不引用任何业务工程类。Service 全部使用接口与实现类，Controller 只注入接口。

## 关键规则

- 用户来自 SecurityUtils，所有查询和写入带本人条件，普通用户只能访问自己的数据，管理员与超级管理员直接被拒绝，不能使用成长业务。
- 成长写操作全部使用 @Transactional 并先锁 identity_user 的本人行，同一用户父级归档/删除、任务更新、安排改期遵循统一事务顺序。
- 数据库唯一索引是最后防线；应用校验日计划所属周、自然周范围、有效祖先、版本与完成状态。
- 逻辑删除不破坏安排历史；改期不复制任务；过期任务只查询，不自动复制或延期。
- 时间点使用 Instant，计划日期使用 LocalDate；today 按本人已生效时区计算，已到期但尚未懒更新的待生效时区也按新时区处理。
- Goal/Stage 进度由有效任务权重聚合，暂停参与总权重，空集合返回 null。
- 更新成功后版本递增，过期版本或安排标识不一致返回 409。跨用户资源返回 404，参数错误 400，缺少动作权限 403。
- 成功业务与操作日志一起提交，异常回滚业务；公共失败审计继续独立记录。

## 手工初始化

应用仍不自动执行 SQL，没有 Flyway。全新本地环境先初始化 Identity 与本地服务，再从仓库根目录手工执行：

```powershell
./scripts/start_identity_local.ps1
./scripts/init_growth_local.ps1
```

脚本固定操作本机 asterway_dev：六表都不存在时事务内建立；六表都存在时仅补齐授权；部分表存在时拒绝执行。不会清空账户或成长数据。授予应用角色 SELECT/INSERT/UPDATE 和序列权限，撤销成长表的物理 DELETE/TRUNCATE。初始化创建 32 个成长权限与 27 个隐藏菜单节点，对新增关联推进角色版本。

现有 identity.sql 同时保留完整新库种子，手工初始化脚本提取其中的成长授权标记块；不是迁移版本链，不创建版本表。

## 编译与运行

```powershell
mvn -B -ntp -f backend/pom.xml '-Dmaven.test.skip=true' package
java -jar backend/app/target/app-0.1.0-SNAPSHOT.jar
```

保持 Java 17，本地端口 8089、PostgreSQL 5432、Redis 6379。运行中 JAR 在 Windows 下可能被锁，重新打包前应只停止本项目对应的 Java 进程。
