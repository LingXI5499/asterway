# 核心成长前端实现与验收说明

## 页面范围

按用户确认范围实现 9 个路由页面：6 个主页面和 3 个详情页，68 项页面交互。相同动作在不同页面的入口分别计数，表单提交/取消不额外拆项；共用弹窗、抽屉不计作页面。原账户体系的 15 个页面继续保留，合计 24 个逻辑页面。

| 页面 | 路由 | 交互数 | 主要操作 |
|---|---|---:|---|
|目标管理|`/growth/goals`|10|查询、重置、切换分类、新增、编辑、状态、归档、恢复、删除、详情|
|目标详情|`/growth/goals/:id`|5|编辑目标、状态、创建阶段、阶段排序、阶段详情|
|阶段管理|`/growth/stages`|9|选择目标、查询、重置、新增、编辑、状态、删除、排序、详情|
|阶段详情|`/growth/stages/:id`|5|编辑阶段、状态、创建任务、任务排序、任务详情|
|任务中心|`/growth/tasks`|11|查询、重置、新增、编辑、状态、删除、排序、安排改期、移出、详情、历史|
|任务详情|`/growth/tasks/:id`|6|编辑、状态、删除、安排改期、移出、历史|
|周计划|`/planning/weekly-plans`|9|选周、历史周、创建、加入任务、指定日、跨周改期、移出、删除、进入日计划|
|日计划|`/planning/daily-plans`|8|选日、创建、加入任务、状态、改期、移出、删除、任务详情|
|待处理任务|`/planning/pending-tasks`|5|查询、重置、改期、退回任务池、任务详情|

页面交互均已编码，编译通过不等于已经完成真实业务流程验收。

## 角色边界

- 成长业务只允许普通用户。账户只要包含 ADMIN 或 SUPER_ADMIN，即使同时持有 USER 基础角色，也视作管理身份。
- 普通用户登录后优先进入目标工作区；相关权限未授予时退回账户中心。管理员进入其获授权的管理页。
- 前端菜单过滤、路由守卫、动作按钮共同限制；后端 SecurityUtils/PermissionGuard 在超管放行前排除管理身份的成长权限。
- Identity 返回的有效权限集移除管理身份的成长能力，菜单树也排除对应目录、页面与关联权限按钮。
- RoleService 禁止向 ADMIN/SUPER_ADMIN 分配成长权限和菜单，保留 USER 的账户安全核心授权。角色管理前端同步限制选项。
- 初始化默认只授予 USER，并移除管理角色旧有直接成长授权。基础 USER 仍保留在管理账户上供个人资料、密码和设备安全使用，但不产生成长访问能力。
- 晋升管理身份不删除个人成长数据；退回普通用户身份后仍按本人归属访问。

## 公共交互与组件

- 使用既有 Vue、Element Plus、ECharts 版本，不增加 UI 框架。
- GrowthEditor 共用目标、阶段、任务资料表单，字段白名单提交，编辑使用 PUT 以支持清空可选日期与预计耗时。
- GrowthSelector 级联查询目标和阶段，支持远程关键字搜索，不一次载入全部个人数据。
- GrowthActions 协调资料、状态、归档、移出、删除与恢复，成功后只更新所在内容区。
- OrderDialog 分页装载同父资源，最多 100 条提交，每条携带原版本；只修改当前页排序，其他项目保持原值。
- TaskAssignmentDialog 加载当前安排版本，明确选择周/日，缺少计划时由用户点击创建，保存时校验所选日期与已加载对象一致。
- TaskPicker 从可安排任务池选择已有任务；AssignmentHistory 分页只读展示每条安排的建立、结束和原因。
- 列表使用服务器分页，详情使用独立路由，目标和阶段进度以服务器结果渲染进度条和环形图，无有效任务时显示空进度。
- 布局继续保留，菜单展开和收起状态不因子路由变化而重建；面包屑区分成长规划与账户入口。
- 表格、表单、卡片与日历条支持窄屏，使用平面背景、轻阴影、焦点反馈、加载、空数据和错误提示，遵循减少动画设置。

## 业务细节

- 所有 ID 使用字符串。写请求使用当前资源或当前安排的 version，409 展示服务端原因；关闭并重新打开表单可重新读取最新版本。
- 任务创建必须指定阶段；目标和阶段归属不因计划改变。
- 目标分类提供当前、未来、全部、完成、归档；归档时必须选择保留安排只读或将未完成安排退回任务池。
- 归档目标下的阶段与任务只读，TaskVO 补充 goalArchivedAt 供任务列表禁用操作，服务端继续做最终约束。
- 周一至周日使用自然周；用户日期按账户当前有效时区计算，包括已到生效时间的待生效时区。日历日期运算不依赖浏览器 UTC 日期截断。
- 周/日不存在时显示空视图，查询不会创建记录；创建周/日均有明确按钮。
- 周计划显示七天导航和真实任务来源；历史周计划分页查看，周计划可包含多个目标的任务。
- 未指定具体日期时只安排到周；改期先结束旧记录再建立新记录，完成任务不能重新安排。
- 过去计划禁用普通编辑、状态和删除按钮；允许通过明确的改期/移出操作处理未完成安排。目标归档时不能改期。
- 删除计划必须选择当前安排的处理方式；不会删除任务。包含过去日计划或受保护安排时显示后端拒绝原因，不伪装成功。
- 待处理只查询，不自动复制、延期或创建计划。任务池排除已完成任务与归档目标。
- 不实现习惯、专注计时、统计看板、通知等扩展页面。

## 初始化与菜单

手工执行 scripts/init_growth_local.ps1，从 identity.sql 的同一标记块提取初始化规则。已启用成长目录和 6 个主页面入口（7 个可见节点），20 个按钮节点继续隐藏，通过动作权限控制。重新显式执行初始化会补齐 USER 默认授权并启用本阶段入口，保留已有账户和业务数据，不作为日常开关同步工具。

角色管理与菜单管理仍由管理员执行，是配置普通用户能力，不代表管理员本人能够使用成长业务。

## 验证边界

本轮验证为前端生产构建、必要后端重新编译打包、应用启动和服务可达检查。不新增或执行单元、系统、集成测试，不创建测试账户或注入演示成长数据。真实的目标创建、改期、归档、跨角色访问等业务流程仍待用户验收。
