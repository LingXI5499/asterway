## 行为与接口

`GET /api/v1/auth/me` 使用会话中的账户 UUID 查询数据库最新资料。
客户端附带的账户 ID 不参与授权；查询投影不读取密码或密码哈希。

成功响应沿用初版的 `accountId`、`username`、`nickname`、`role`，
补充 UTC 格式的 `createdAt`、`updatedAt`，外层仍为统一响应结构。
资料查询不创建账户、不写业务数据，也不修改既有 V001/V002 迁移。

| 场景 | 返回与页面行为 |
|---|---|
| 有效账户 | 200，展示数据库最新资料 |
| 未登录或账户不存在 | 401 AUTH_REQUIRED；无效会话清理，返回登录页 |
| 账户停用 | 403 ACCOUNT_UNAVAILABLE；清理当前会话，登录页提示账户不可用 |
| 数据库连接失败 | 503 SERVICE_UNAVAILABLE；保留身份，隐藏旧资料并允许重试 |
| 其他未知异常 | 500，统一错误响应，不向页面暴露内部异常 |

页面首次打开、恢复可见和恢复联网时重新读取资料，也可点击“刷新资料”。
退出或页面卸载后不再展示该页面的账户资料。

## 开发辅助与编码约定

- 引入 springdoc-openapi 2.8.17，接口文档仅展示本次 `/auth/me`。
- 默认端口下，本地 `local` 环境文档入口为 `http://localhost:8088/swagger-ui/index.html`。
- 非 `local` 环境默认不注册 Swagger 文档端点；访问不存在资源保持 404。
- 使用现有 SLF4J / Logback，日志输出 traceId；账户业务日志只携带必要 UUID。
- 默认业务包日志等级改为 INFO，避免 MyBatis DEBUG 输出注册 SQL 的敏感参数。
- 新增 Java 和 JavaScript 注释仅使用 `//`，XML 使用简短 XML 注释。
- 新增业务方法先组装结果，再以简短 return 返回；按层分工，SQL 仍写在 Mapper XML。
- 页面沿用简单表单和按钮，本次未增加组件库依赖。

版本依据：[springdoc 官方兼容矩阵](https://springdoc.org/v2/)。
会话清理依据：[Spring Security 6.5 注销机制](https://docs.spring.io/spring-security/reference/6.5/servlet/authentication/logout.html)。

## 用户验收入口

1. 在 IDEA 启动现有后端，再在 `frontend` 目录执行 `npm.cmd run dev`。
2. 用已有账户登录，进入 `/home`，确认用户名和昵称可见。
3. 点击“刷新资料”，确认读取成功；停止后端后刷新应提示失败并提供重试。
4. 启动后端后重试，应恢复资料展示。
5. 打开本地 Swagger，检查 `/auth/me` 的资料响应。

停用与账户不存在场景已由自动化检查覆盖；不要求为手工验收改动真实账户数据。
