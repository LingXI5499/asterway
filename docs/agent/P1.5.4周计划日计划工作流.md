## 一、实现内容

| 部分 | 文件 | 说明 |
|---|---|---|
| 计划上下文 | `agent/app/services/planning_context_service.py` | WEEKLY_PLAN/DAILY_PLAN 收集现有周计划、待重新安排任务；避免重复建周与重复安排 |
| 意图规则 | `agent/app/services/planning_service.py` | 周/日计划只输出 weeklyPlans/dailyPlans/taskAssignments；不创建新目标/阶段/任务，提示改走任务规划 |
| 方案结构 | PlanSnapshot + workflow_service | weeklyPlans 按 weekStart；dailyPlans 引用 weekKey + businessDate；taskAssignments 引用 taskKey + weekKey（+ businessDate 可落到日） |
| 原子提交 | P1.5.2 `AgentPlanCommitServiceImpl` | 周计划用 `WeeklyPlanService.byWeek(date,true)` 获取或创建；日计划用 `DailyPlanService.byDate`；安排用 `TaskAssignmentService.assign`，不复制任务实体 |
| 任务安排口径 | 既有 Java 业务约束 | 安排引用已有任务与周/日计划；同一任务安排替换由业务 Service 校验；不自动开始计时 |

## 二、工作流语义

1. 周计划：根据 weekStart 定位或创建周计划；日计划必须属于本方案周计划；
2. 任务安排：引用任务池/已有任务与周计划，可指定日期落到日计划；不创建任务副本；
3. 生成阶段注入现有周计划与待重新安排任务，避免重复建周、忽略逾期任务；
4. 确认后 Java 在单一事务内创建周/日计划与安排，返回 weeklyPlanIds/dailyPlanIds/assignmentIds；
5. 不删除计划、不修改既有安排历史；删除/改期仍由业务页面按既有规则操作。
