日期：2026-11-05。状态：**SQL 与接口契约完成，未执行数据库；继续 P1.5.1。** 无 Java/Python 代码改动。

## 一、新增 SQL（agent.sql 追加段）

| 表 | 作用 | 要点 |
|---|---|---|
| `agent.workflow_run` | 一次对话内的工作流运行 | 意图（目标/阶段/任务/周计划/日计划/习惯/综合）、状态机 DRAFT→WAITING_CONFIRM→CONFIRMED→EXECUTING→SUCCEEDED/FAILED/CANCELLED/EXPIRED、过期时间、graph_state JSONB；同一会话只允许一个活动运行 |
| `agent.plan_version` | 方案不可变版本 | 版本号每运行唯一；DRAFT/WAITING_CONFIRM/CONFIRMED/SUPERSEDED/REJECTED/EXPIRED；snapshot JSONB 存结构化方案；确认后写 confirmation_token（sha256）；同一运行只允许一个 CONFIRMED |
| `agent.workflow_event` | 工作流事件流 | 只追加：运行开始、方案生成/修订、确认、提交开始/成功/失败、取消、过期；`(run_id,event_no)` 唯一，payload JSONB |
| `agent.plan_commit` | Java 幂等提交记录 | `idempotency_key`、`request_hash` 唯一；PENDING/RUNNING/SUCCEEDED/FAILED；attempts≤10；result JSONB 存创建结果；同一 plan_version 只提交一次 |

所有表含所属用户、版本号、时间约束（非有限时间、时间倒置拒绝）；`user_id` 只由 Java 验证后的身份写入；不存密码、令牌或原始资料。

约束：
- clientKey 仅在快照内关联，Java 创建后返回真实标识映射；不把内部 ID 暴露给模型作为可写入参数。
- 快照必须包含 intent、时区和版本一致的任务/阶段/目标引用；Java 二次校验引用关系与日期边界。
- 确认后快照不可修改；修订生成新 plan_version，旧版本标记 SUPERSEDED。
- 方案必须明确列出将要创建/修改的实体；不包含删除或归档动作（目标删除只允许归档，且不在 P1.5 工作流自动执行）。

## 三、Java 幂等提交接口契约

```
POST /asterway/agent/plans/commit
Authorization: 普通用户 JWT
权限: agent:workflow:manage
请求: {
  "runId": "123",
  "planVersionId": "456",
  "idempotencyKey": "<sha256 64hex>",
  "requestHash": "<sha256 64hex>",
  "snapshot": { ...方案快照... }
}
响应: {
  "commitId": "789",
  "status": "SUCCEEDED",
  "result": {
    "goalIds": ["..."], "stageIds": ["..."], "taskIds": ["..."],
    "weeklyPlanIds": ["..."], "dailyPlanIds": ["..."], "assignmentIds": ["..."],
    "habitIds": ["..."]
  },
  "warnings": []
}
```

规则：
1. Java 校验登录态、普通用户身份与 `agent:workflow:manage`；不接受客户端指定 userId。
2. 以 `idempotency_key` 唯一约束保证重复请求不重复创建：已 SUCCEEDED 直接返回既有 result；RUNNING 返回 409；FAILED 可按尝试次数重试。
3. 一次请求在同一数据库事务内完成全部业务写入；任一步失败整体回滚并写 FAILED + 错误码。
4. Java 只信任已确认方案：Python 只对 CONFIRMED 的 plan_version 发起提交，并在提交前校验 run 未过期、版本匹配、消费者为本人。
5. 提交成功/失败后 Python 写 plan_commit.result 与 workflow_event，并更新 run 状态。
6. 不自动开始执行计时、不打卡、不删除既有业务；计划工作流不复制任务。

## 四、权限准备态

- `agent:workflow:read`、`agent:workflow:manage` 两个准备态权限与隐藏按钮菜单挂在 `growth_agent` 页面，默认禁用/隐藏，仅 USER 授权，ADMIN/SUPER_ADMIN 不授权。
- 后端验收后通过 `SET LOCAL asterway.agent_workflow_backend_ready='true'` 启用；本阶段未执行任何 SQL。
