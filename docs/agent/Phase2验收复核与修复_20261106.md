## 已修复的问题

| 问题 | 修复与证据 |
|---|---|
| SQL 初始化失败 | 三处把排序值写成 `AND 20 OR 19` 等布尔运算，PostgreSQL 报 `42804`；改为 `CASE WHEN`。修复后全新隔离库顺序执行 11 份 SQL，通过并建立 12 张 Agent 表。 |
| 向量约束放过空数组或二维数组 | 改用 `cardinality` 与单维检查，三个非法数组场景已被拒绝。 |
| 记忆来源可引用他人记录 | 写入前核对来源会话、轮次和被替代记忆的归属。 |
| 重复修改记忆报 500 | 检查重复并转换唯一约束异常，返回 `409`。 |
| 记忆确认／修改缺少向量任务 | 确认后入队，修改时删除旧向量并重新入队，确认替代关系时归档旧记忆。 |
| 已删除文档仍进入 RAG | 向量、关键词及来源查询统一过滤归属、删除状态和就绪状态，不再用“未命名资料”继续注入被删除内容。 |
| 长文静默丢失后半部分 | 分块超过上限时明确拒绝，不再直接截取前若干块。 |
| 文档只向量化首批 | 一个领取处理完整批次，每次写入前复核任务代次和文档状态。 |
| 相似度错误及旧片段遗漏 | 点积改为余弦；按模型过滤，分批检索全部有效片段，取消只看最近 200 条的范围限制。 |
| Embedding 配置与协议不符 | 默认改为百炼 `text-embedding-v4`、1024 维、每批最多 10 段；按返回索引配对，检查数量、维度、有限数值和非零向量。参考[官方接口规格](https://www.alibabacloud.com/help/en/model-studio/embedding)。 |
| 解析包和 Windows 时区数据缺失 | 明确增加 `pypdf`、`python-docx`、`tzdata`；实际 PDF／DOCX 解析和时区检查通过，未整体升级既有框架。 |
| 后台任务取消／超时后状态错误 | 使用数据库时间、领取代次和实际超时控制；旧任务不能覆盖新结果，解析失败或超时不会永久停留在解析中。 |
| 空方案、无效引用、完成标准丢失 | 提取严格规划 Schema，保留完成标准，校验日期、周期、意图范围和引用关系。 |
| 计划无法引用已有任务 | 区分新建引用和已有对象 ID／版本；周／日计划不复制任务，已有安排变化需匹配版本。 |
| 确认后无法调整或确认过期版本 | 提交前修订生成新版本并使确认失效，保留旧版本确认历史，只能确认最新方案。 |
| Java 信任传入的“已确认”快照 | 核对本人、会话、运行状态、最新版本、过期和规范化内容摘要，拒绝篡改、取消及未确认方案。 |
| JSON 整数节点类型不同误报篡改 | 比较规范化 JSON 内容，真实模型方案互操作通过。 |
| `@Size` 用于 `JsonNode` | 移除不适用的注解，结构与批量范围由具体校验承担，正常 DTO 验证通过。 |
| 失败记录等待父事务锁 | 原事务完成回滚后再记录失败，保持用户锁顺序，验证中途失败无业务半成品。 |
| 重试及终态时间约束失败 | 清理旧结束与错误字段，一条 SQL 只取一次时间，统一更新相关时间。 |
| Python 重写 Java 回执、重复计数 | Java 回执为真实事务结果，Python 只同步工作流状态，不二次累计尝试或覆盖成功。 |
| 超时被当作失败、成功后重放报错 | 未知结果保持待核对，详情读取可依据晚到回执恢复；成功重放不重复创建。 |

| 健康状态虚报已部署能力 | 增加存储就绪和向量密钥配置状态；没有后台任务表时不启动反复报错的任务循环。 |

## 接口和配置变化

- 规划快照增加 `goalId/goalVersion`、`stageId/stageVersion`、`taskId/taskVersion`；与新建对象的 `clientKey` 引用互斥。
- 同周未定日任务安排到某天时携带 `assignmentId/assignmentVersion`；其他安排冲突返回 `409`，不暗中覆盖。
- 内部规划详情增加 `commit`，用于刷新后核对真实提交结果。
- `/health` 增加 `storageReady` 和 `embeddingConfigured`。`phase` 表示实现阶段，不能替代验收结论。
- 聊天与 Embedding 独立配置，示例密钥保持为空。
- 本次保留数组向量存储兼容既有实现，没有将其称为已完成 pgvector。
