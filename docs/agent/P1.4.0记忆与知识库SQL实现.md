## 二、表设计要点

### agent.memory（长期记忆）
- `kind`：PREFERENCE 偏好、FACT 事实、CONSTRAINT 约束、GOAL_CONTEXT 目标背景；仅作为对话上下文，不作为授权依据。
- `status`：CANDIDATE 候选 → CONFIRMED 已确认 / REJECTED 已拒绝 / ARCHIVED 已归档；确认后才跨会话使用。
- 记录来源会话/轮次（逻辑引用）、置信度 0～1、替代关系 `supersedes_id`（逻辑引用，不级联）。
- 约束：正文非空白且 ≤4000 字；状态与时间成对（确认时间、拒绝时间、归档时间）；逻辑删除保留审计；已确认内容同一用户去重索引（`md5(content)`）。
- 用户不接受客户端或模型指定 `user_id`；该列由 Java 验证后的身份写入。

### agent.memory_embedding（记忆向量）
- 一条记忆当前一条向量；`dimension` 与数组长度强一致；模型更换时更新该行。
- 使用 `double precision[]` 存储，避免依赖 pgvector；检索在 Python 内计算余弦相似度。

### agent.knowledge_document（知识文档元数据）
- 文件本体不入库，只存受控 `storage_key`、sha256 `checksum`、大小（≤25MB）与状态机 UPLOADED→PARSING→READY/FAILED、DELETED。
- 同一用户未删除文档按 checksum 去重；删除为逻辑删除。

### agent.knowledge_chunk（文档分块）
- 每文档按 `chunk_no` 唯一；正文 ≤8000 字、token 数 1～8192；向量三件套（embedding/模型/维度）同空或同有且维度一致。
- 文档删除不物理丢弃分块，保留历史用于审计与恢复。

### agent.background_task（后台任务）
- 类型：DOCUMENT_PARSE、DOCUMENT_EMBEDDING、MEMORY_EMBEDDING；引用类型与类型强匹配。
- 状态机 PENDING→RUNNING→SUCCEEDED/FAILED/CANCELLED，带尝试次数（≤20）、调度/开始/结束时间与错误码。
- 同一引用同一类型只允许一个 PENDING/RUNNING 活动任务（部分唯一索引）。

## 三、授权准备态

- 4 个权限与 4 个隐藏按钮菜单挂在既有 `growth_agent` 页面下，默认 `is_enabled=false`、`is_visible=false`。
- 仅 USER 角色授权；ADMIN/SUPER_ADMIN 保持无授权（管理身份优先限制）。
- 后端验收后通过维护事务设置 `SET LOCAL asterway.agent_memory_backend_ready='true'` 启用；本阶段未执行任何 SQL，开发库未改动。
