## 二、幂等与事务规则

1. 幂等键 = sha256(runId:planVersionId:snapshotHash)；`agent.plan_commit.idempotency_key` 唯一，同一方案版本只产生一条记录。
2. 请求已 SUCCEEDED：直接返回既有 result，不再执行业务创建。
3. 状态 RUNNING：返回 409，不并发重复提交。
4. FAILED 且 attempts<10：允许重试，先标记 RUNNING 再执行。
5. 业务创建在单一数据库事务内完成，任一步失败整体回滚；失败记录在独立事务写入 FAILED + 错误码，保证可审计与可重试。
6. Java 校验登录态与 `agent:workflow:manage`；不接受客户端指定 userId；快照结构二次校验（intent、阶段必须有目标、任务必须属于阶段、日计划/安排引用关系）。
7. 创建结果返回真实 goalIds/stageIds/taskIds/weeklyPlanIds/dailyPlanIds/assignmentIds/habitIds，Python 写回 plan_commit.result 并更新 run 为 SUCCEEDED/FAILED；重复请求返回同一结果。
8. 只创建/安排，不删除、不归档、不开始计时、不打卡。

## 四、部署注意事项

- Java 提交记录使用业务数据源访问 `agent.plan_commit`；本地开发库需确保 Java 使用的数据库角色对 `agent.plan_commit` 有 SELECT/INSERT/UPDATE 权限（生产部署时按最小权限单独授权）。本阶段未执行任何授权 SQL。
- 提交接口要求目标用户已具备 `agent:workflow:manage`；该权限在 SQL 中为准备态，P1.5 后端验收后才启用。
- 快照中 `clientKey` 只用于本次提交内部映射；响应中的真实标识不会被模型当作可写参数。
