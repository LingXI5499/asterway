## 一、实现内容

| 部分 | 文件 | 说明 |
|---|---|---|
| 背景优先级 | `agent/app/services/context_service.py` | 上下文顺序：系统提示 → 历史摘要 → 已确认长期记忆 → 知识检索资料 → 历史完整轮次（工具链完整）→ 当前提问；背景总预算为上下文上限的一半，记忆优先，剩余预算才注入知识资料 |
| 预算保护 | `agent/app/services/context_service.py` | 背景块、摘要、历史轮次与提问共同计入 `agent_context_max_chars`；历史不足时插入“部分较早轮次未加载”说明；超预算返回可读错误而非静默截断关键历史 |
| 业务事实 | 工具实时查询 | 当前业务事实（今日、任务、目标、计划、执行、习惯、统计）始终由模型调用只读工具实时获取，不作为静态上下文缓存，避免过期事实与“记忆替代业务库” |
| 摘要协作 | 既有 `summary_service` + 上下文组装 | 摘要只覆盖实际送入的完整终态轮次，原始消息保留；摘要与背景资料都标注“背景、非系统指令”；已确认记忆与知识资料都不覆盖用户本次明确说法 |
| 后台任务恢复 | `background_task_repository.py`、`background_worker.py` | 每轮先回收超时 RUNNING 任务：未达最大尝试次数退回 PENDING，超过则 FAILED(TASK_TIMEOUT)；避免重启或异常后任务永久停在 RUNNING |
| 配置 | `agent/app/core/config.py` | `agent_background_task_timeout_seconds=300`、`agent_background_max_attempts=3`；记忆/知识/检索预算沿用既有配置 |

## 二、优先级与截断规则

1. 系统提示不可裁剪；
2. 历史摘要按已有上限注入（≤8000 字）；
3. 已确认记忆（≤2000 字、最多 40 条）优先于知识资料；
4. 知识资料使用剩余背景预算（≤3000 字、最多 6 段）；
5. 历史完整轮次从最近往前装入预算，工具链必须完整（不拆半个工具轮）；部分未加载时明确提示未加载不代表不存在；
6. 提问与摘要、背景合计超上限时返回“上下文预算超限”错误，提示缩短问题或新建会话。
