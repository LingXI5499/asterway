# 多知识库、批量导入与格式说明改造

本轮已完成本地实现、隔离验证和开发环境启用。开发库已执行增量迁移并配置服务角色权限，Java、Python 与前端均已更新并重启。已有账号、资料、会话与业务数据保留，未提交、推送或合并。

## 已实现的行为

- 知识资料按个人知识库管理，桌面展示左侧知识库和右侧文档，手机使用知识库选择器。创建、编辑和移动使用居中弹窗。
- 同一知识库中的相同文件返回“已存在”；相同内容可分别导入不同知识库。单篇或批量移动保留文档、版本、原文、索引和引用编号，遇到目标库内容冲突时整批不移动。
- 非空库不能删除。文档查询、搜索、解析状态筛选、分页、版本、原文定位及处理记录继续可用；处理记录显示文档名称和中文处理状态。
- 每批最多选择 20 个文件，同时上传 2 个。文件入队时固定目标知识库。上传、解析和索引分别展示状态，只有索引就绪才显示“可检索”。
- 单文件失败不阻断其他文件。未上传项可以移除；上传失败重新上传原文件，后台处理失败只重试处理。收起进度弹窗不会停止上传；离开页面或刷新时会提示尚未上传的文件，已上传文件在服务端继续处理。
- 上传能力接口统一提供格式和有效大小上限，当前最高 25 MB。新文档与新版本使用相同规则：TXT 支持 UTF-8 BOM，Markdown 保留标题，文字 PDF 保留页码，DOCX 读取正文和表格。
- 空文件、超限、格式不支持、编码错误、加密、损坏以及没有可提取文字均返回原因。扫描 PDF 提示先完成 OCR，本轮没有加入 OCR、文件夹或压缩包导入。
- 每个会话可选择多个知识库，新会话默认不引用。会话保存选择，每轮保存发送时的范围；切换选择只影响后续消息。向量检索与关键词回退均受同一范围限制，空范围直接跳过文档检索。
- 引用增加知识库名称，继续保存文档、版本、片段、页码及摘录。失效或越权选择返回提示，请求重放复用原轮次或拒绝不一致的请求，不扩大检索范围。

## 数据与兼容

新增 `knowledge_base`、`conversation_knowledge_base`；文档增加知识库归属，消息轮次增加范围快照。归属使用复合外键限制，重复文件约束改为用户、知识库和摘要共同唯一。

增量 SQL 位于现有 `agent.sql` 末尾，用 `ASTERWAY_KNOWLEDGE_BASES_BEGIN` 与 `ASTERWAY_KNOWLEDGE_BASES_END` 标记，外层有独立事务。应用不会自动执行迁移。

旧文档归入各用户的“默认知识库”，首次迁移为旧会话保留原检索范围。再次执行不会恢复用户主动清空的范围，也不会给后来创建的会话补选知识库。迁移不重建原文件、文档编号、版本、索引或历史引用。

旧上传请求没有 `knowledgeBaseId` 时仍归入默认库；旧消息请求没有 `knowledgeBaseIds` 时读取会话保存的范围；显式空数组表示不检索。

开发库已手工执行增量 SQL，并为现有 Agent 服务角色配置新增表及序列的必要权限。Java 与 Python 已加载本轮实现，应用仍不会在启动时自动迁移。
