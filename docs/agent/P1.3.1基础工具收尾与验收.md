## 本轮完成

### 工具事实与回复保存

- 调用 Java 前，先把模型的工具请求保存为助手消息，并为每条工具结果、下一条助手回复预留有序序号。
- 查询成功或普通失败都保存对应的工具结果；同一事务内复核用户、会话和运行轮次，避免停止后继续追加有效结果。
- 使用既有三表和工具字段，不新增工具 CRUD 链路。工具仍只读 Java 业务数据。
- 公开聊天分页只展示用户提问和最终回复；刷新不把内部工具消息当作聊天正文。不新增历史工具审计页面。
- 各次模型调用分别保存自身用量；最终回复和重放结果按轮次汇总，避免累计用量被重复累计。

### 上下文与压缩

- 普通响应和 SSE 共用同一生成流程，都会按权限选择工具。
- 按完整终态轮次取历史，完成轮次保留成对的助手工具请求与工具结果，不从中间裁断。
- 取消、失败或未完整结束的轮次只把用户原问题带入后续上下文，避免复用缺失结果的工具链或半截回答。
- 摘要覆盖序号只推进到真正装入摘要输入的完整轮次；因预算未送入的消息不会被标成已摘要。
- 同会话摘要任务合并调度、共享模型并发额度，保留摘要版本和旧边界的比较更新；失败、过长或截断摘要不替换旧摘要。
- 摘要作为历史背景资料使用，原文保留；字符预算不足时明确提示历史未全部加载，不假装已经读取。

本轮未重新生成旧摘要，也未修复历史会话已经保存的错误摘要边界。特别长的完整轮次无法装入摘要预算时不推进边界；这会保留原文，但不保证该轮次一定能自动压缩。摘要的语义保真度仍需人工验收。

### 工具边界与停止恢复

- 严格校验工具参数、增量调用 ID／名称／参数长度和批次大小；超长结果转换为有明确截断标记的合法 JSON。
- 只向模型提供当前用户有权使用的工具。每次模型调用及实际业务查询前复核身份；登录失效或管理身份限制终止生成，普通查询失败转换为工具结果。
- 保持单工具 8 秒、最多 3 个工具轮和 6 次执行的默认限制；达到上限后要求模型基于已有结果作答。
- 停止或断连时尽力保存当前回复片段；停止事件、查询状态和页面断连清理配套处理，避免无人消费的事件队列继续等待。
- 读取会话／轮次和发起新问题前，先用短事务处理已过期运行轮次，避免进程重启后页面一直显示生成中。
- Python 关闭服务时先停止生成和摘要任务，再关闭数据库及 HTTP 客户端。

入口：<http://localhost:5175/agent>。Vite 绑定 `localhost`；Java 使用 8089，Python 使用 8001。

| 操作 | 预期 |
|---|---|
| 普通用户问“我今天应该做什么” | 出现今日看板查询状态，回答基于本人任务、习惯及执行数据；空数据按实际情况说明。 |

| 查询或回答中停止，再刷新并继续提问 | 已停止状态可恢复，不一直显示查询中；新问题可正常开始。 |

| 工具无结果、超时或缺少业务查询权限 | 显示实际失败或空结果，不伪造业务信息；登录失效按认证失败处理。 |
