# Asterway V2.1

在 V2.0 的成长助手、规划与执行反馈闭环基础上，完善计划页面、多知识库、批量导入及配置启动说明。接口继续使用 `/asterway`，保留既有工程与依赖版本。

## 本次变化

- 计划整合周／月日期选择和当天任务卡片，任务池、本周任务、全部任务和逾期待处理集中在任务管理弹窗；任务详情、编辑、状态与安排操作保留在当前页面。
- 聊天支持 Enter 发送、Ctrl+Enter 换行，继续兼容 Shift+Enter 和输入法确认。
- 用户可创建多个私有知识库，维护名称和简介，单篇或批量移动文档；同库去重、跨库独立版本、非空库删除保护均已接入。
- 批量导入最多 20 个文件、并发 2 个，区分上传成功、解析与索引就绪；单项失败可重试。上传区域明确展示格式、25 MB 最高上限、扫描件及错误原因。
- 会话可选择一个或多个知识库，新会话默认不引用。消息固定发送时的范围，向量和关键词回退都按库隔离，引用保留知识库、文档、版本、页码和原文定位。
- 增加可复制的 Java 外部配置模板，重写 Agent 配置示例，在 README 中逐项说明聊天 API、向量 API、数据库、服务间密钥及 JWT 的填写位置和启动顺序。

## 升级与数据

已有 V2.0 数据库先备份，再人工执行 `agent.sql` 中 `ASTERWAY_KNOWLEDGE_BASES_BEGIN` 对应的增量事务，并为现有 Agent 数据库角色配置新增表及序列权限。应用不会自动建表或迁移。

旧资料迁移到各用户的默认知识库，原文、文档编号、版本、索引及历史引用保留。旧会话延续原有范围；新会话不自动选择知识库。前端、Java、Python 必须一起更新，SQL 与配置准备完成后重启服务。

## 验证范围

发布前在独立源码快照完成 `npm ci`、36 项前端检查、57 项 Python 检查、7 项隔离 SQL 检查、前端构建和完整 Maven 打包；配置模板字段、空白凭据及手工迁移开关检查通过。隔离测试 schema 与临时权限已清理，当前开发服务保持运行。

本次计划及知识库改造已完成前端检查、Java 打包、Python 检查、隔离数据库迁移与检索范围验证，并复核桌面和手机布局。开发环境已完成增量迁移、角色权限配置和三个服务重启；迁移前后 45 张原有表的原有字段摘要一致，实际登录页面正常显示原有 16 篇资料及格式说明，没有原先的资源不支持错误。

知识库专项写入使用隔离数据；本次开发环境启用后的页面复核只读，没有创建、移动或删除用户资料。真实模型生成期间切换范围及实际向量服务调用未在本次启用中重新执行，具体边界见 [多知识库改造与验证](../agent/多知识库改造_20261109.md)。

配置模板保持密钥和密码为空；真实配置、知识文件、数据库备份、依赖、缓存、IDE 文件和运行日志不进入发布。GitHub 发布表示源码及说明可获取，不代表已部署到其他服务器。
