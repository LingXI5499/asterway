> 版本：V1.2；日期：2026-10-18。

## 1. 文档目标

Asterway 是面向个人成长管理的 MVP。本设计包为实现者提供每项功能的需求、字段、请求、业务步骤、数据操作、页面状态和验收方法。

当前版本覆盖12个功能模块、132项现行功能需求、36张表、95个HTTP接口、7类系统处理、20个页面、19批开发工作和72项综合验证。逐接口功能测试与综合验证互为补充。

日常查阅从[index.html阅读页](index.html)进入，通过目录或搜索定位功能。阅读页一次展示一项内容，接口定义、业务流程、数据实现和测试分开查阅，长示例与细则默认折叠。Markdown是可编辑正文；文档变更后应同步更新阅读页。

## 4. 不可突破的核心约束

| 编号 | 要求 | 手写时的具体含义 |
|---|---|---|
| RULE-001 | 不允许物理外键 | 项目表、Spring Session 表均不建 FOREIGN KEY；不做数据库级联，不用触发器查父表模拟外键。父子存在性、同一用户归属和删除引用由事务内检查 |
| RULE-002 | 只做 MVP | 不增加 AI 接入、向量库、社区、聊天、提醒推送、质量评分、任意周期、补打卡、任务恢复等功能 |
| RULE-003 | Java 全栈方向不变 | JDK 21、Spring Boot、MyBatis XML、PostgreSQL；前端 Vue 3 + TypeScript。Mapper 不写 SQL 注解和结果映射注解 |
| RULE-004 | 一个运行应用 | Maven 工程拆分不等于拆微服务；保持一个后端进程、一个数据库，模块间使用进程内调用和同库事务 |
| RULE-005 | 数据归属以服务端身份为准 | 不从请求 userId 决定个人数据归属；管理员不能读其他用户的成长正文 |
| RULE-006 | 一人同时只计一个任务 | 可保留多个暂停执行；切换要先关闭旧计时段，再开新段。暂停不计时；预计耗时不决定实际时长 |
| RULE-007 | 不制造历史 | 迁移只改当前安排，真实执行留在原日期；过去日计划只读；习惯不能补记、撤销完成或重算过去 |
| RULE-008 | 完成需要明确区分 | 结束一次执行不等于任务完成；任务完成不可恢复。目标满进度发确认通知，由用户决定结束，也允许提前主动结束 |
| RULE-009 | 以实际生效日期为准 | 周一至周日；时区按有效区间确定；自动启动、延期、周期处理都复用同一业务用例 |
| RULE-010 | 失败不伪装成功 | 响应丢失保留原意图核实；数据库不可用不能本地假完成；文档完成不能写成测试通过 |

## 5. 编号和书写方式

| 编号类型 | 含义 | 示例 |
|---|---|---|
| FR / BL / AC / NFR / NFA | 原需求、业务与质量编号 | 沿用旧文档，不因拆接口而重编需求 |
| DB | 表和字段 | DB-18、DB-18.last_confirmed_at |
| API | 一个 HTTP 接口 | API-FOCUS-001；编号与路径分别查，不能只凭名字猜 |
| PAGE | 页面或重要全局交互 | 在 07 定义 |
| DEV | 一批可以手写并验证的实现工作 | 在 06 定义 |
| TEST | 一个有输入、步骤、预期与证据的验证场景 | 在 08 定义 |

字段说明写清必填、可空、单位和来源。正文中的类名、目录、SQL 功能名称只用于设计说明，不表示实现文件已经存在。一个成功结果以数据库已提交为准；一个验收结论以实际证据为准。

## 6. 使用边界和完成口径

1. 从[项目文档入口](README.md)进入，先读10需求分析，再按01～05及11理解业务链路；按06的DEV批次实现后端，达到该批验收条件后再继续。
2. 07定义页面原型与前端实现依据，用于校验交互和接口是否完整；实际实现按06的开发顺序推进。
3. 08 中所有未实际运行的测试均为 NOT_VERIFIED。性能、兼容性、备份和恢复依赖真实环境，不能由设计证明已经达标。
4. 框架具体补丁、依赖锁文件、Argon2id 成本、实际索引计划等在工程准备和验证时记录；不改变已确认技术路线，也不假造实测值。
5. 每次改变契约，先更新对应设计并登记09，再修改实现和测试；通过版本历史保留决策依据。
