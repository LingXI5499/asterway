# Execution 后端业务与接口约定

本文件是 SQL 验收后的接口合同。Execution 接口及跨模块后端联动已编码，实际构建、启动和未执行的业务验收边界见[后端实现与启动说明](后端实现与启动说明.md)。

## 1. 业务和实现顺序

后续顺序：Execution（含现有任务／计划／归档联动）→ Habit → 必要站内提醒 → 今日看板 → 历史统计。Habit 分类、数量限制、完成率与生命周期历史轮到该模块时单独设计。

Execution 只支持已加入有效周计划的任务。普通用户拥有任务、阶段、目标和安排，父链未删除／未完成且目标未归档，目标和任务开始日期已到达。当前周未安排具体日期的任务可执行；有具体日期的任务只在当天执行；阶段日期只作参考。过期／未来安排先调整，执行结束不等于完成任务。

暂停和结束保留任务状态，开始或恢复将任务置为 IN_PROGRESS。运行中不允许通过手动任务状态修改使任务表现为未开始、暂停或完成。不同任务可以保留多个暂停会话，同一个任务只能有一个未结束会话。另一任务正在运行时先暂停，不能隐式切换。

全部控制时间由服务端生成，不支持自由专注、补录、计时修正、倒计时或番茄钟。

## 2. 接口合同

前缀 `/asterway`，统一返回 ResultVO，分页数据使用 PageResultVO。BIGINT 标识沿用现有字符串序列化约定，客户端不能提交 owner、控制 SID、实际耗时或操作时间。

| 方法 | 路径 | 请求或筛选 | 权限 |
|---|---|---|---|
| POST | /executions | taskId、taskVersion | start；实际恢复同时检查 resume |
| GET | /executions/current | 无 | read |
| POST | /executions/{id}/pause | version | pause |
| POST | /executions/{id}/resume | version | resume |
| POST | /executions/{id}/finish | version | finish |
| POST | /executions/{id}/heartbeat | segmentId | heartbeat |
| GET | /executions | taskId、goalId、stageId、status、dateFrom、dateTo、page、size | list |
| GET | /executions/{id} | 无；包含首屏 20 个时间段 | read |
| GET | /executions/{id}/segments | page、size | read |
| GET | /tasks/{id}/executions | status、dateFrom、dateTo、page、size | list |
| GET | /tasks/{id}/execution-summary | dateFrom、dateTo | read |
| GET | /stages/{id}/execution-summary | dateFrom、dateTo | read |
| GET | /goals/{id}/execution-summary | dateFrom、dateTo | read |
| GET | /executions/summary | dateFrom、dateTo | read |

权限均以 `execution:session:` 开头。管理身份先行拒绝，之后再判断具体动作，不能让 SUPER_ADMIN 通行逻辑开放个人执行接口。

- 创建新会话返回 201，返回原会话／恢复／控制和心跳成功返回 200。current 无运行会话时返回成功、data=null。
- page 默认 1，size 默认 20、最大 100，越界返回 400；会话按首次开始时间、主键倒序，时间段按段序号升序。
- 日期参数成对提供，起止日期均包含；缺一或逆序返回 400。列表不传日期则查全部历史，汇总不传日期则统计今天，同时返回累计实际耗时。
- 列表日期筛选按任一实际时间段是否与区间相交，不能只筛会话首次开始日期；会话不因有多个匹配时间段重复出现在列表中。
- 参数错误 400，未登录 401，管理身份或缺动作权限 403，不属于本人或不存在的资源 404；版本、当前状态、资格、并发互斥和过期心跳冲突 409。
- 不提供执行删除、时间段独立增删改查或手工补时接口。

### 结果内容

ExecutionSessionVO 包含 id、taskId、taskName、status、startedAt、finishedAt、finishReason、version、taskVersion、actualSeconds、rangeActualSeconds（提供日期时）、lastHeartbeatAt、activeSegmentId、activeSegmentStartedAt、serverNow、heartbeatDeadline、eligibleUntil、canHeartbeat、heartbeatIntervalSeconds。

ExecutionSegmentVO 包含 id、segmentNo、assignmentId、startedAt、endedAt、endReason、effectiveEndedAt、actualSeconds、timeZone。开放段的 endedAt 保持空值，展示截止单独使用 effectiveEndedAt，不能伪造已落库的暂停时间。

详情使用 ExecutionDetailVO，包含 execution 和首屏 segments 分页对象，可由 segments 接口继续获取。控制端 SID 不序列化。汇总包含 totalActualSeconds、rangeActualSeconds、totalSessions、rangeSessions、finishedSessions、runningSessions、pausedSessions、latestExecutionAt；rangeSessions 按区间参与会话去重，latestExecutionAt 取最近一段的开始时间，不取心跳更新时间。

## 3. 控制、心跳和事务

1. 鉴权并限制普通用户，先用短事务归一化该用户已超时／到边界的状态，保证这部分不会被随后失败的业务命令回滚。
2. 命令事务重新锁 identity_user，重新读取任务、父链、有效安排和会话；取得锁后再读取服务端时间。
3. 开始同任务已运行时返回原会话，不转移控制端；其他任务运行则冲突。同任务存在暂停会话则恢复，否则创建会话和首段。
4. 真正新建／恢复时校验相应版本，任务置 IN_PROGRESS 并推进任务版本，新增段、设置认证上下文 SID，初始化心跳。开始请求携带旧 taskVersion 的延迟重放不能在旧会话结束后新建会话。
5. 暂停关闭当前段，清空控制端，推进会话版本。恢复只对 PAUSED 生效，重验资格、创建下一段并绑定恢复端。重复恢复已运行会话只返回状态，不转移 SID。
6. 结束 RUNNING 先关段；结束 PAUSED 不增段。重复暂停／结束不重写已有时间；FINISHED 不允许恢复。
7. 心跳同时匹配 owner、RUNNING、当前段 ID 和控制 SID；先判断截止，再刷新。心跳只更新最近心跳及更新时间，不递增控制版本，旧段请求不能刷新新段。
8. 过期心跳返回 409，不能复活已经暂停的段；网络结果不明时用 current／详情对账，不盲目重试创建。

控制端是登录会话，不是设备标签或浏览器标签页。同账户其他登录端可以查看、暂停和结束；需要接管时先暂停再恢复，同一登录下多标签页共享 SID。

心跳 20 秒、超时 90 秒、扫描 15 秒；定时扫描每批最多 100 个候选，候选查询不先锁会话，再逐用户加锁、重读和处理，繁忙用户可跳过留待下批。调度使用明确的目标用户身份，不伪装登录用户。状态变更按现有审计规则记录，心跳不逐条写操作日志。

已有用户锁的任务／归档／账户联动直接参加父业务事务，禁止持锁再开新事务等待自己的用户锁。任一步失败则父业务及执行变更一起回滚。

## 4. 日期边界和认证

日安排的边界为当地次日零点；未定日的周安排为下周一零点。用户存在待生效时区时与时区生效时间取较早者；修改待生效时区时同步更新开放段截止，不延长已经确认的截止。段开始时的时区和超时阈值作为快照保留。

开放段只计到 `min(serverNow,lastHeartbeatAt+timeout,eligibleUntil)`，读取也必须封顶。已经越界的暂停会话再次恢复，重新检查当前周、日期及父链，不沿用旧资格。

将 heartbeat 和全局计时器自动 GET current 请求加入现有 JWT 不续期清单。有效交互仍按现有策略滑动续期。前端后续使用认证请求发送心跳，不在 URL 或 query 中携带 JWT；页面关闭不能保证精确回调，异常退出按服务端心跳截止处理。

## 5. 与现有模块同批修改

| 模块 | 后端阶段必须修改 |
|---|---|
| task | 完成前要求没有未结束会话；确认删除时同事务结束全部未结束会话、结束安排并逻辑删除任务 |
| planning | RUNNING 阻止涉及该任务的改期、移出或计划删除；PAUSED 允许调整，旧安排留历史 |
| goal／stage | 会让 RUNNING 失去资格的状态或开始日期修改要求先暂停；恢复时重新检查 |
| goal | 新归档同事务结束全部未结束会话、结束全部有效安排（含已完成任务位置）；恢复不自动安排／计时 |
| identity | 注销／踢下线只暂停对应 SID 控制的运行记录；全部撤销、停用或升为管理身份时暂停相应运行记录；数据库联动先于提交后的 Redis 撤销 |
| common | 中立联动接口、配置／枚举、有效权限过滤、管理身份限制、心跳不续期和错误处理 |

目标旧 DELETE 接口已改为 410、提示使用归档；新归档请求为 `{version, confirmed:true}`，取消旧 KEEP/RETURN_TO_POOL 选择。原目标页面同步移除删除入口并修改归档请求和确认说明；本轮不新增 Execution 前端页面。

实现仍为一条会话 Controller／Service 接口及实现链。时间段使用独立 Entity、Mapper/XML、VO，参加会话事务，不增加独立时间段 Service／Controller。调度在 execution 专属目录，其他公共内容在 common，app 不承载协调器或 Controller。

## 6. 后端完成后的人工验收项

编码阶段仅做编译和启动检查，不建立严格测试体系。人工验收项目另行记录执行结果：首次开始与重复开始、恢复原会话、任务版本重放、另一任务互斥、多暂停会话、跨设备接管、旧段心跳、七天会话不被轮询续期、超时／日期／时区边界、暂停后结束、跨日实际耗时、任务完成／删除、计划调整、目标归档与恢复、账号撤销、管理身份和跨用户限制。

SQL 通过不替代这些未执行的业务验收；前端页数与交互数量仍在后端完成后确认。
