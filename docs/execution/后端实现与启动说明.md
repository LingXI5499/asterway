# Execution 后端实现与启动说明

实现入口：

公共常量、配置、范围枚举和 ExecutionLifecycleProvider 在 common；Identity、任务、计划、目标和阶段通过公共契约接入，业务工程之间没有增加 Maven 依赖。app 仍只有一个启动类、本地 YAML 和 SQL。

编译打包及 Java 17 启动已经通过；具体机器校验结果见 [backend-build-results.json](backend-build-results.json)。这不代表业务流程已经验收，本轮没有新增或运行单元、系统、集成测试，也没有调用计时业务接口创建测试记录。

## 2. 已编码行为

### 会话与计时

- 开始任务时检查本人、普通用户身份、目标／阶段／任务状态、目标及任务开始日期、本周有效安排及今日日期。
- 同用户最多一条运行，同任务最多一条未结束；再次开始优先恢复暂停会话，同任务已经运行时返回当前会话，不转移控制端。
- 新建或实际恢复将任务置为 IN_PROGRESS 并推进任务版本；结束执行不完成任务。
- 开始、恢复新增连续时间段；暂停关闭段；暂停后结束不增段。所有时间由服务端在取得用户锁后生成。
- 暂停／结束重复请求不重写历史时间。FINISHED 不能恢复，过期开始请求不能用旧任务版本新建会话。
- 开放段按服务端时间、最后心跳加阈值、计划／时区边界中的最早值计时；查询同样封顶。实际耗时先累加毫秒再取整为秒，跨日期按时间区间交集计算。
- 执行记录、详情时间线、任务／阶段／目标和个人区间汇总均已编码；历史查询包含逻辑删除或归档对象的执行事实。

### 控制端和认证

- SID 直接取认证上下文，不接受客户端提交，也不返回到接口。其他设备可以查看、暂停和结束；接管通过先暂停再恢复，同一登录下的标签页共享控制身份。
- 心跳校验 owner、运行状态、SID 和当前段 ID，不递增会话版本，不写逐条成功／失败操作日志。
- 心跳和自动 GET current 不续签七天登录有效期。控制动作在用户锁内再次读取账户状态、权限和登录会话，避免使用等待锁前的失效身份。
- 注销／踢下线只暂停所撤销 SID 控制的记录，全部退出、停用、重置密码、本人改密和角色变更会同步暂停相应运行记录。
- 单端撤销在数据库联动提交后执行 Redis 撤销；Redis 失败返回 503，不能静默宣称已退出。全端撤销沿用数据库 auth_version 失效及提交后清理策略。
- 管理身份限制先于超级管理员通行，USER+ADMIN、USER+SUPER_ADMIN 也不能访问个人计时；权限有效集、菜单过滤和角色分配白名单同时更新。

### 跨模块事务

| 操作 | 已接入的处理 |
|---|---|
| 完成任务 | 有运行／暂停会话时拒绝，要求先结束 |
| 删除任务 | 同事务结束未结束会话、结束安排，再逻辑删除任务 |
| 改期／移出计划 | 相关任务运行时拒绝；暂停后可以调整，恢复重验；同位置仅排序不重建安排 |
| 删除日／周计划 | 范围内存在运行执行时拒绝，原有显式处理安排规则继续生效 |
| 目标／任务开始日期、父链状态变更 | 会使运行任务不再可执行时回滚，提示先暂停 |
| 目标归档 | 同事务结束全部未结束会话、全部有效安排，再归档；包含暂停及已完成任务位置 |
| 目标恢复 | 不自动重新安排或恢复执行 |
| 时区更新和延后生效 | 同步缩短开放段截止；新段按有效时区重新取得资格 |

命令前到期维护使用独立短事务；命令失败后再处理等待期间的到期状态。已有父业务锁的联动加入原事务，不持锁另开事务等待自己。读取分页和统计使用一致快照，扫描按批逐用户处理并跳过忙锁，不引入分布式控制租约或额外事件表。

## 3. 目标接口兼容变更

目标不再提供成功删除操作。`DELETE /asterway/goals/{id}` 对本人可访问目标返回 410、`GOAL_DELETE_RETIRED`，保留旧入口用于明确提示；目标删除 Mapper 写语句已移除，历史 deleted_at 数据仍保留。

归档固定请求：

```json
{"version":0,"confirmed":true}
```

旧 `unfinishedHandling=KEEP/RETURN_TO_POOL` 请求不再接受。归档会结束全部未结束执行并移出计划；重复归档仍按确认和版本处理旧策略遗留的有效安排，不覆盖历史。

**仅同步了原有页面的接口兼容，没有新增前端页面。** 目标归档改为复选确认和新请求体，移除目标删除按钮，任务删除及目标恢复提示补充执行联动语义，个人权限分类补充 execution；其他页面和交互保留。Execution 新页面的数量和交互仍须先确认，执行入口保持隐藏。

## 4. 本地初始化和启动

本轮已手工运行：

```powershell
./scripts/init_execution_local.ps1
```

脚本只对已有本地开发库增加验收后的两张执行表、应用角色权限及 Execution 授权标记块，不重跑 Identity 建表或旧成长初始化，不覆盖账号、任务或计划数据。已有部分表或缺少验收列／索引时中止，不自动 ALTER 或删除。重复执行保留已有执行数据。

当前数据库状态：两表已建立，七项执行后端权限启用且默认授予 USER，六个菜单节点已登记；执行页面启用但隐藏，旧目标删除权限与按钮停用且授权移除。没有新增实际执行数据。

对旧目标归档安排做了只读数量预览，结果为 **0**，没有执行历史数据修正。应用仍不自动运行 SQL，历史数据没有清理。

编译打包命令：

```powershell
mvn -f backend/pom.xml -pl app -am -Dmaven.test.skip=true package
```

使用 Java 17 运行 `backend/app/target/app-0.1.0-SNAPSHOT.jar`，端口为 8089。当前本地进程已启动，开发接口文档地址：`http://127.0.0.1:8089/swagger-ui/index.html`。

唯一 application.yml 新增以下本地参数，没有环境变量、profile 或配置导入：

```yaml
asterway:
  execution:
    heartbeat-interval-seconds: 20
    heartbeat-timeout-seconds: 90
    scan-delay-ms: 15000
    scan-batch-size: 100
```
