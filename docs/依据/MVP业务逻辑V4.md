# Asterway V1.0 业务逻辑与业务事件流分析（V4）

> 文档类型：业务规则、业务流程及验收依据  
> 修订日期：2026-10-17  
> 依据：当前需求决策、业务规则及一致性审查。  
> 适用范围：个人账户、目标、阶段、任务、周计划、日计划、专注执行、习惯、今日看板、通知、历史统计及基础管理后台。  
> 使用方式：本文为当前业务逻辑基线。本文不定义数据库表、API 路径或代码实现。

### 当前版本要点

1. 删除任务后，任务退出当前任务进度和阶段完成判断；已发生的投入、完成事实及历史归属继续保留。
2. 当天习惯已有有效完成记录时，该日同时计入完成率的分子、分母，不因之后暂停、结束、删除或修改周期而撤销。
3. 明确系统配置仅包含站点显示名称和是否开放注册，避免将固定业务规则做成任意可改的配置。
4. 功能性需求清单与本文同步维护，后续设计以本文为业务基线。

“补充约定”表示为明确边界而采用的设计默认值；调整时应记录变更及影响范围。自动延期公式按BL-GOAL-008执行。

## 1. 统一口径

### 1.1 规则来源与编号

- **需求基线**：已确定的产品行为与业务约束。
- **补充约定**：在产品方向内补齐业务边界的默认规则，变更时须说明依据。
- `BL-模块-序号`：业务流程的稳定编号；新增流程继续编号。
- `DEC-序号`：需求决定的追溯编号。
- `AC-序号`：业务验收场景。

所有流程均适用第 2 章的身份、归属、校验、重复提交及失败处理规则。各流程另外描述自己的触发时机、前置条件和特殊分支。

### 1.2 规则冲突的处理

| 涉及内容 | 本文采用的最终规则 | 采用原因 |
|---|---|---|
| 任务进度 100% 是否自动结束目标 | 系统自动发起完成确认并通知用户，用户确认后目标才正式完成 | 满进度仅发通知，结束必须取得用户确认 |
| 已完成任务是否可以重新打开 | 不可以；需要继续做时新建任务 | 第 22 条针对任务完成后的规则更明确；第 28 条的重新打开适用于阶段，并补充适用于目标 |
| 未来开始的目标默认归档 | 开始前隐藏在“待开始”范围，到期自动显示；主动归档单独记录 | 必须区分自动等待与主动归档，防止系统擅自恢复主动归档目标 |
| 多任务执行 | 多个任务可以处于未完成、已暂停状态；同一用户同一时刻只有一个任务计时 | 开始另一个任务时，自动暂停当前任务 |
| 过去日计划只读与任务改期 | 历史页面不提供编辑；通过当前任务的改期操作迁移原安排，原日期不保留重复条目 | 不改写真实执行事实，也不为迁移制造重复历史 |
| 结束时间补录与禁止习惯补记 | 可以补齐已有执行记录的结束时间；不可以补记过去日期的习惯完成 | 两者对应不同业务对象 |

### 1.3 主要业务边界

以下均为**补充约定**，具体规则见对应章节：

1. 自动延期使用“基准计划时长 × 30% × 剩余任务比例”，至少延长 1 天；自动延期不扩大后续计算基数。
2. 用户删除的任务退出当前有效任务总数；有执行或完成历史时仅保留历史身份与贡献，不再阻塞阶段完成。
3. 昵称选填，未填写时默认取注册时的用户名；昵称后续独立修改，可重复。
4. 同一任务同时只保留一个有效周计划归属，以及至多一个有效日计划日期。
5. 异常退出时以最后可确认的执行时刻暂停，不能把离线时间持续算为专注时间。
6. 习惯当天修改立即生效，已发生的完成事实保留；当天尚未完成的应执行状态按最新规则判断。
7. 普通用户、管理员、超级管理员按固定角色控制权限；管理员不能操作同级或更高权限账户。
8. 阶段排序不构成前置依赖，允许推进多个阶段。

## 2. 全局业务规则

### 2.1 个人使用与账户隔离

1. 系统可以存在多个注册账户；每个普通用户只管理自己的个人成长数据。
2. 不提供用户之间的交流、私信、社区、关注、共享任务或协作计划。
3. 目标、阶段、任务、计划、执行记录、习惯、通知和历史查询，均按当前账户隔离。
4. 创建子对象时，同时校验父对象归属及关联关系；不能通过更换对象标识操作其他用户的数据。
5. 管理员的管理权限仅用于管理后台；不能因此取得普通用户的个人执行操作权限。

### 2.2 通用操作顺序及失败处理

每次写操作按以下顺序处理：

1. **E1：接收操作。** 确认登录状态、操作角色及请求对应的对象。
2. **E2：校验。** 检查归属、当前状态、字段格式、关联关系及业务限制。
3. **E3：确认影响。** 对不可恢复的任务完成、删除、目标结束等操作展示必要的影响说明；用户取消则结束流程。
4. **E4：保存。** 保存业务结果及必须同时变化的关联数据。
5. **E5：刷新。** 更新相关列表、计划、看板、通知和统计。

| 场景 | 处理结果 |
|---|---|
| 未登录、登录失效 | 拒绝受保护操作，提示重新登录；未结束执行按中断规则处理 |
| 对象不存在或不属于当前用户 | 拒绝操作，不泄露他人数据 |
| 必填项缺失、格式错误、日期关系错误 | 拒绝保存，明确指出需修改的内容 |
| 状态不允许 | 保持原状态，提示当前允许的处理方式 |
| 重复创建计划、重复完成、重复结束或重复计时 | 返回现有结果，不产生重复记录或重复贡献 |
| 保存失败 | 保留上一次有效结果，允许重试；不得出现只迁移一半、只归档一半的结果 |
| 保存成功但页面刷新失败 | 告知结果已保存、展示暂未更新；重新查询实际结果，不把成功写入当作失败再次执行 |
| 查询没有记录 | 展示空状态 |
| 查询失败 | 展示加载失败及重试入口，不伪装成“无任务”或统计值 0 |

### 2.3 时间、时区与日期边界

**需求基线：** 自动匹配用户所在地区的时区；一天以当地午夜为界；一周固定周一至周日。

1. 自动识别设备提供的有效时区，并作为当前账户的业务时区。浏览器可以读取运行环境的默认时区，参见 [MDN：获取用户时区](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat/resolvedOptions#examples)。地区名称或界面语言不能单独替代时区。
2. 一天为当地日期 `00:00:00` 至次日 `00:00:00`，采用前闭后开区间。
3. 一周为当地周一 `00:00:00` 至下周一 `00:00:00`；周日全天属于本周。
4. 目标开始、目标预计结束、日计划、周计划和习惯判断，使用同一业务时区。
5. 实际耗时按真实经过时间计算；跨日统计按当地午夜拆分，不能把“日历上相隔一天”直接等同于固定 24 小时。
6. **补充约定：** 首次识别失败时保留最近一次有效时区；从未取得有效时区时，要求选择时区后再进行日期相关写操作，不能静默套用服务器地区。
7. **补充约定：** 设备时区变化时，自动匹配并在当前日周期结束后启用新时区；进行中的执行先暂停。已有计划日期、习惯完成归属日期和历史统计分桶不整体重排，后续记录使用新时区。这样避免同一天被重复结算。
8. 定时处理未能准点运行时，恢复服务或用户访问时补做应发生的状态检查；同一日期、同一周期的处理只能生效一次。

### 2.4 四类信息必须分别保存和展示

| 类型 | 表示什么 | 不能替代什么 |
|---|---|---|
| 业务状态 | 目标是否完成、阶段是否暂停、任务是否完成 | 不能由是否加入计划直接推断 |
| 计划安排 | 哪一周、哪一天准备完成任务 | 不代表已经执行 |
| 执行状态 | 计时中、暂停、已结束 | 结束一次执行不代表完成任务 |
| 归档状态 | 是否退出日常管理范围并保留历史 | 不代表目标或任务已经完成 |

除明确描述历史查询的流程外，任务的恢复、加入计划、执行及当前进度均只针对未被用户删除的有效任务。恢复目标或计划不能恢复已经删除的历史任务。因任务删除而保留的历史身份，不等同于可以重新加入任务池的普通归档对象。

## 3. 核心对象生命周期

### 3.1 目标

| 状态或标记 | 展示与可用能力 | 后续处理 |
|---|---|---|
| 待开始 | 不进入活跃目标和今日看板；可从待开始范围查看、拆解和规划 | 到达开始日自动进入进行中 |
| 进行中 | 进入活跃目标和看板；可拆解、安排和执行 | 用户结束，或进度 100% 后等待确认 |
| 待确认完成标记 | 目标仍未正式完成；显示确认通知 | 用户确认结束，或继续管理 |
| 已完成 | 保留目标结束时的进度和历史；退出待执行范围 | 可归档；可主动重新打开 |
| 主动归档标记 | 从活跃管理中移出；保留原业务状态 | 由用户恢复，不由到期任务自动恢复 |

未来目标的自动隐藏在界面可归入“待开始／归档”区域，但必须显示“待开始，将于某日显示”。“已完成”和“已归档”可以同时成立，不能相互覆盖。

### 3.2 阶段、任务与执行

| 对象 | 状态及规则 |
|---|---|
| 阶段 | 创建后未开始；首次执行其任务后进入进行中；可暂停、恢复、完成、重新打开；仅空阶段可删除 |
| 任务 | 创建后未开始、未执行；首次执行后进行中；可暂停、恢复；完成后不可恢复为未完成；符合删除条件时可删除或归档保留 |
| 一次执行 | 从 0 正向计时；计时中可暂停，暂停后可继续；结束后记录本次有效专注时间 |
| 任务计划归属 | 任务池、有效周计划、可选日计划是安排关系；加入计划不会把任务标记为进行中 |

任务暂停包括主动暂停和切换任务引起的暂停。任务累计时间、已发生的执行记录不因暂停、恢复、改期或归档归零。

### 3.3 习惯

| 状态 | 列表位置 | 是否触发当天应执行 | 是否允许恢复 |
|---|---|---|---|
| 启用 | 习惯清单；当天应执行项进入今日清单 | 按周期判断 | 无需恢复 |
| 暂停 | 暂停队列中继续显示 | 不触发 | 允许 |
| 结束 | 自动进入归档范围 | 不触发 | 允许，恢复同一习惯 |
| 删除 | 从清单、暂停队列及可恢复对象列表中消失 | 不触发 | 不提供恢复；实际历史贡献保留 |

## 4. 账户管理

### 4.1 字段、改名与密码规则

| 字段 | 业务规则 |
|---|---|
| 用户名 | 必填；登录依据；全系统唯一；1–30 个字符；仅英文字母、汉字和数字；不允许空格、下划线和其他符号 |
| 昵称 | 可重复；不作为登录依据；可随时修改；**补充约定：** 选填，填写时为 1–30 个字符且不能全为空白，未填写时默认取注册时用户名 |
| 密码 | 必填；长度 8–50 个字符，包含端点；不要求必须包含几类字符；弱密码在长度合格时也允许提交 |
| 确认密码 | 注册及修改密码时使用，必须与对应的新密码一致；不作为个人资料保存 |

1. 取消用户名修改冷静期；首次修改及后续修改均可立即生效。
2. **补充约定：** 用户名中的英文字母按不区分大小写判断唯一性和登录匹配；展示保留用户保存的形式。改名后旧用户名不再作为该账户的登录名。
3. 个人资料只提供昵称、用户名及密码管理，不增加头像、签名、手机号或邮箱绑定。
4. **密码强度分类补充约定：** 数字、大写英文字母、小写英文字母，以及其他允许字符。中文等其他可见字符归入第四类，避免非空密码出现“命中 0 类”的矛盾。
5. 命中 1、2、3、4 类时分别显示“弱、低、高、强”；为空时提示“密码不能为空”，不显示强度；长度不合格时另行提示长度规则。
6. 全为空白的密码按未填写处理；不自动删改有效密码首尾字符。强度提示不代替长度校验。
7. 密码不得保存明文或直接使用 MD5；采用专用密码哈希。此项延续 V2，依据为 [OWASP 密码存储说明](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。
8. 普通用户不提供基于邮件、短信的找回或重置密码流程。

### BL-AUTH-001 用户注册账户

**触发：** 未登录用户提交注册。**输入：** 用户名、密码、确认密码、可选昵称及滑动验证结果。

1. **E1：** 先检查当前是否开放公开注册，再检查必填项、用户名格式、密码 8–50 字符及两次密码是否一致；注册关闭时不创建账户。
2. **E2：** 验证本次滑动验证；失败、过期或结果无效时拒绝本次注册。
3. **E3：** 检查用户名唯一性；昵称可重复。重复用户名须提示更换。
4. **E4：** 创建账户前再次确认注册仍开放；创建普通用户，保存密码哈希，初始化昵称及有效时区。
5. **E5：** 提示注册成功并引导登录；失败不生成半成品账户，重复请求不创建多个账户。

公开注册不能选择管理员或超级管理员身份。

### BL-AUTH-002 用户登录账户

**触发：** 用户提交用户名、密码及滑动验证结果。

1. **E1：** 检查当前登录尝试是否处于临时锁定期间；未到期则拒绝并展示剩余等待时间。
2. **E2：** 验证滑动结果；失败只拒绝本次请求，不增加用户名或密码错误次数。
3. **E3：** 滑动验证通过后检查凭据；用户名不存在和密码错误都算一次认证失败，统一提示“用户名或密码错误”。
4. **E4：** 连续失败达到 5 次时锁定 5 分钟；锁定期内不能凭正确密码绕过。
5. **E5：** 到期自动解除临时锁定并清零连续计数；成功登录也清零计数。
6. **E6：** 凭据正确且账户可用时建立会话；读取异常中断执行，先按暂停状态展示。

**补充约定：** 不存在用户名也按规范化后的提交用户名形成失败计数，不能因查不到账户而跳过计数。该计数不等于限制所有随机用户名请求的额外风控机制。管理员禁用账户与 5 分钟临时锁定分别处理，禁用不会到期自动恢复。

### BL-AUTH-003 用户退出账户

**触发：** 用户使用系统内的退出登录或正常退出入口。

1. **E1：** 查询该用户所有尚未结束的执行，包括暂停中的执行。
2. **E2：** 若存在，要求先结束并补齐必要结束时间；允许取消退出返回系统。
3. **E3：** 所有执行已结束后，注销当前会话，展示未登录状态。
4. **E4：** 结束或注销失败时提示重试；不删除个人业务数据。

直接关闭进程、断电、连接丢失和会话被撤销按 `BL-FOCUS-005` 自动暂停处理，不能依赖正常退出流程拦住这些情况。

### BL-AUTH-004 用户修改密码

**触发：** 已登录用户提交原密码、新密码和确认新密码。

1. **E1：** 校验字段、原密码、新密码长度，以及两次新密码一致且与原密码不同。
2. **E2：** 如当前仍有未结束执行，先要求用户结束；取消则不提交密码修改。
3. **E3：** 保存新密码哈希；失败保留原密码与会话。
4. **E4：** 成功后注销该用户全部既有会话，包括当前会话，要求重新登录。

### BL-AUTH-005 查看及修改个人资料

1. **E1：** 用户查看个人资料，系统展示用户名、昵称及密码修改入口，不返回密码原文或哈希。
2. **E2：** 用户提交新用户名或昵称；系统分别校验格式和用户名唯一性，不校验冷静期。
3. **E3：** 校验通过后立即保存；与当前值相同时按无实际变更处理。
4. **E4：** 改名后使用新用户名登录；现有会话关联同一账户，不创建新账户、不迁移成长数据。
5. **E5：** 修改失败保留原值；昵称不随后续用户名修改自动变化。

### BL-AUTH-006 个人数据访问控制

每次个人业务查询和修改都校验登录、账户归属与父子关联；无权访问时不返回数据。管理后台另按第 12 章权限执行。

### BL-AUTH-007 密码找回与重置的范围

本版不提供普通用户自助找回或重置密码入口，也不增加邮箱、手机号或短信验证。正常修改密码必须验证原密码；管理后台不提供密码查询。

## 5. 目标管理

### BL-GOAL-001 创建目标及自动开始

**触发：** 用户创建目标。**输入：** 名称、描述、开始日期、预计结束日期及完成条件。

1. **E1：** 校验必填信息和有效日期；预计结束日期不能早于开始日期。
2. **E2：** 创建属于当前用户的目标，记录基准计划时长。
3. **E3：** 开始日期在未来时，设为待开始并自动隐藏；在待开始范围可查看、编辑和拆解。
4. **E4：** 开始日期为今天或过去时，进入进行中并显示在活跃目标范围。
5. **E5：** 到开始日当地零点，系统自动使待开始目标进入进行中并出现在看板目标队列。
6. **E6：** 启动检查时若目标被主动归档或已完成，不自动恢复。重复检查不重复创建目标或通知。

**补充约定：** 待开始目标可预先安排开始日及之后的未来计划，但不得提前执行；自动开始只显示目标，不自动创建任务、周计划或日计划。

### BL-GOAL-002 查看目标列表、详情、进度和累计时间

1. **E1：** 用户选择活跃、待开始、已完成或归档范围，系统只展示本人对应目标。
2. **E2：** 展示目标日期、状态、阶段、任务数量、已完成数量及实际投入时间。
3. **E3：** 详情展示描述、完成条件、阶段和任务；无任务时显示“暂无任务，可先规划任务”。
4. **E4：** 对有任务的目标计算进度；查询失败展示加载失败，不展示虚构的 0%。

**任务数量与进度口径：**

- `N` 为用户在该目标所有阶段中创建、未被用户删除的当前有效任务数量。
- `C` 为这些当前有效任务中已完成的数量；因删除而归档保留的历史任务不进入当前 `C` 或 `N`，但仍参与实际投入和历史完成贡献统计。
- 任务池、周计划、日计划只是同一任务的不同入口；同一任务只计 1 次。
- 暂停任务仍计入；用户删除任务时，无论是否保留执行历史，都从当前 `N` 中移出，原来已完成的还须从当前 `C` 中移出。
- 当 `N > 0` 时：`P = C / N`，显示为百分比。
- 当 `N = 0` 时：显示无任务状态；不以除零结果显示进度，也不触发自动完成确认。
- 显示值可以四舍五入，但自动确认判断使用 `C = N 且 N > 0`，不能因 99.6% 显示为 100% 就触发。
- 当前任务总数会随用户增删任务变化；已结束目标的历史保留结束当时的数量和进度快照。

“因删除而归档的任务”与“所属目标主动归档”分别处理：前者退出当前考核范围；后者仅改变管理可见性，不自动删除任务或改变该目标的任务数。

例如，目标原有 3 项有效任务，完成 2 项，另一项已投入 20 分钟但不再需要。删除这项后，当前进度为 `2 / 2`，该项的 20 分钟仍计入真实投入；系统可以通知确认结束目标，但不能把被删除任务补记为已完成。若全部有效任务都被删除，`N = 0`，只显示无任务，不自动判定完成。

### BL-GOAL-003 修改目标信息与日期

1. **E1：** 用户修改目标名称、描述、完成条件、开始日期或预计结束日期。
2. **E2：** 校验目标归属、非归档状态及日期先后关系；已完成目标须先重新打开再继续调整规划。
3. **E3：** 对尚无执行历史的目标，开始日期改到未来时重新隐藏等待；改到今天或过去时立即进入进行中。
4. **E4：** 已有实际执行时，不允许把开始日期改到首段真实执行日期之后；不改写实际开始和结束记录。
5. **E5：** 手动修改日期后更新目标自身日期及基准计划时长，不自动修改任务截止日期、周计划或日计划。
6. **E6：** 若修改结果与已安排的未来任务冲突，提示用户先调整冲突计划，不静默批量改期。
7. **E7：** 用户把预计结束日期设为已经过去的有效日期时，保存后立即执行自动延期规则，展示最终生效日期。

### BL-GOAL-004 归档及恢复目标

**归档触发：** 用户主动归档目标。

1. **E1：** 检查目标归属与当前状态。
2. **E2：** 检查目标下是否存在未结束执行，包括暂停中的执行；存在则拒绝归档，要求先结束执行。
3. **E3：** 展示影响并由用户确认：目标退出活跃范围，关联任务退出当前及未来的有效计划。
4. **E4：** 保存主动归档标记，撤出有效安排，保留目标、阶段、任务、真实执行及已形成的历史贡献。
5. **E5：** 刷新目标、周计划、日计划及看板；归档不等于任务完成，也不产生计划延期。

**恢复触发：** 用户从归档范围恢复目标。

1. **E1：** 解除主动归档标记，保留原完成状态、任务状态及累计时间。
2. **E2：** 原目标已完成时，仍作为已完成目标；需要继续推进时另执行重新打开。
3. **E3：** 未完成目标按开始日期显示为待开始或进行中；已经超过预计结束日期时补做一次延期。
4. **E4：** 未完成任务回到任务池，不自动恢复旧周计划或日计划。

归档和恢复均不能创建目标副本；保存失败保留原状态。

### BL-GOAL-005 完成、主动结束及重新打开目标

**系统发起确认：**

1. **E1：** 任务创建、删除或完成导致目标进度更新后，检查是否 `N > 0 且 C = N`。
2. **E2：** 满足条件且目标仍进行中时，添加待确认完成标记，并向本人发送一条站内通知。
3. **E3：** 用户点击通知或目标中的确认入口；系统重新校验最新任务状态。
4. **E4：** 用户确认后，检查不存在未结束执行，正式完成目标并记录结束时间及当时进度。
5. **E5：** 用户选择继续推进时，保持进行中；同一轮 100% 条件不因刷新反复提醒。

**用户主动结束：**

1. **E1：** 用户可在进度不足 100% 或无任务时主动结束目标。
2. **E2：** 系统展示未完成任务数量，要求先结束所有未结束执行。
3. **E3：** 用户确认后记录目标完成／结束状态及结束时间，撤出未完成任务的有效计划。
4. **E4：** 未完成任务保持未完成；不自动补完成阶段或任务，不伪造 100% 进度。

**重新打开：补充约定。** 用户可以主动重新打开已完成目标；系统保留上次结束历史，开启新的推进区间。原已完成任务不撤销完成；尚有效的未完成任务回到任务池，已删除的历史任务不恢复，原计划不自动恢复。仅恢复归档显示不等于重新打开。

**异常与通知边界：** 确认前又新增未完成任务时，旧的“全部任务完成”通知标为条件已变化，不能直接沿用自动确认结果；用户仍可选择主动结束。目标归档后不再推送完成确认。重复确认只产生一次完成结果。

### BL-GOAL-006 禁止删除目标

不提供目标删除功能。用户不再推进时可以主动结束或归档；任何目标删除请求都不能删除目标及其历史。

### BL-GOAL-007 更新目标统计

任务创建、完成、彻底删除或归档后重算当前 `C、N、P`；执行区间变化后重算实际时间。阶段排序、计划迁移及普通信息修改不增加任务数或实际耗时。

### BL-GOAL-008 预计结束日期自动延期

**需求基线：** 目标结束日期是预计完成日期；超过后自动延长，也允许手动修改；目标不因预计日期经过自动结束或消失。

**公式为本次补充约定：**

```text
B = 最近一次用户设定的开始日期至预计结束日期的日历天数，包含首尾，至少为 1
P = 当前目标任务完成比例；无任务时仅为计算延期取 0
延长天数 Δ = max(1, ceil(B × 30% × (1 - P)))
新预计结束日期 = max(原预计结束日期, 今天 - 1 天) + Δ 天
```

| 基准时长 B | 当前任务进度 | 本次延长 |
|---:|---:|---:|
| 30 天 | 无任务或 0% | 9 天 |
| 30 天 | 50% | 5 天 |
| 30 天 | 90% | 1 天 |
| 30 天 | 100%，尚未确认结束 | 1 天 |

1. **E1：** 当地日期切换或用户访问目标时，检查目标已经开始、尚未完成、未主动归档且今天晚于预计结束日期。
2. **E2：** 读取基准时长和最新任务比例，按公式计算新日期；补偿长期未访问时也确保新日期不早于今天。
3. **E3：** 保存旧日期、新日期、延长天数、当时进度及自动延期原因，供目标时间线查看。
4. **E4：** 刷新目标日期，目标保持进行中，不挂一个永久的“已逾期”状态。
5. **E5：** 同一过期日期重复处理不叠加延期；目标已完成或主动归档时停止自动延期。

自动延期不更新 `B`，避免基数不断膨胀；用户手动调整开始或预计结束日期后才更新 `B`。自动延期只改目标预计日期，不改任务截止日期或计划安排，也不代表自动提高目标进度。

## 6. 阶段管理

### BL-STAGE-001 创建阶段

**触发：** 用户在待开始或进行中的目标下创建阶段。

1. **E1：** 输入阶段名称、描述；完成条件、开始日期、结束日期可选。
2. **E2：** 校验名称和描述非空；日期填写时必须有效，起止都填写时开始不晚于结束。
3. **E3：** 检查目标属于本人、未主动归档且未完成。
4. **E4：** 创建未开始阶段，默认追加到当前阶段列表末尾；失败不保存无效阶段。

阶段日期用于规划，不自动构成前置阶段依赖；多个阶段可以同时推进。

### BL-STAGE-002 查看阶段及手动排序

1. **E1：** 用户查看阶段，系统展示名称、描述、状态、任务数量、已完成数量和实际投入。
2. **E2：** 用户拖动或上下移动阶段顺序；系统校验涉及阶段都属于同一目标及当前用户。
3. **E3：** 保存完整有效顺序；所有相关视图使用相同顺序。
4. **E4：** 排序失败保留原顺序；排序不改变任务优先级、完成情况、日期或历史时间。

### BL-STAGE-003 修改阶段

1. **E1：** 用户提交阶段信息修改，系统校验归属、必填信息、日期及父目标状态。
2. **E2：** 未开始、进行中及暂停阶段可以调整信息；已完成阶段要继续新增任务，须先重新打开。
3. **E3：** 保存后刷新列表和详情；不改写已有任务的真实执行历史。

### BL-STAGE-004 完成、暂停、恢复及重新打开阶段

1. **E1：** 完成阶段前，只检查阶段下当前有效任务；只要其中存在未完成任务，即拒绝完成。因删除而归档保留的历史任务不参与此判断。
2. **E2：** 同时检查不存在未结束执行；用户确认后记录阶段完成时间。
3. **E3：** 空阶段可由用户确认完成，但不会把无任务目标自动判为 100%。
4. **E4：** 暂停阶段时，自动暂停其当前计时任务，保留未结束执行、计划和实际进度；暂停期间不能开始或完成其任务。
5. **E5：** 恢复阶段后重新允许有效计划中的任务执行，不自动开始计时。
6. **E6：** 用户可重新打开已完成阶段，保留历史完成节点；原已完成任务继续完成，可创建新任务。

所属目标已归档或已完成时，阶段的推进操作须先恢复目标或重新打开目标。阶段完成不直接完成目标。

### BL-STAGE-005 删除阶段

1. **E1：** 用户发起删除，系统确认阶段归属并统计其关联任务。
2. **E2：** 只有当前有效任务数量为 0 时允许删除；仍有效的未开始、已暂停或已完成任务都不算空阶段。已经删除、仅保留历史的任务不再占据阶段当前清单。
3. **E3：** 用户确认后将空阶段移出当前列表并更新排序；失败保留阶段。
4. **E4：** 阶段存在历史任务或投入时，保留历史身份、所属目标和必要摘要，供历史及时间统计使用；无历史时可直接删除。不允许通过阶段删除级联清除任务或执行历史。

## 7. 任务管理

### BL-TASK-001 创建任务

**触发：** 用户在目标的阶段下创建任务。

1. **E1：** 输入名称、描述、完成条件、优先级，以及可选的任务开始日期、最终截止日期和预计耗时。
2. **E2：** 名称、描述、完成条件、优先级必填；优先级仅高、中、低；预计耗时填写时必须为正数。
3. **E3：** 校验阶段及目标归属、非归档状态；已完成目标或阶段须先重新打开；暂停阶段可编辑规划但不能执行。
4. **E4：** 日期填写时格式必须正确；开始和截止都填写时开始不晚于截止。
5. **E5：** 创建未开始、未执行任务，进入任务池；不自动加入周计划或日计划。
6. **E6：** 更新所属阶段和目标任务数量；无效输入或保存失败不产生任务。

任务开始日期及最终截止日期不等于日计划的具体安排日期；任务不设置这些字段也可以加入周计划。

### BL-TASK-002 查看任务及执行进度

展示任务身份、所属目标和阶段、优先级、完成条件、安排关系、预计耗时、业务及执行状态、累计实际耗时和执行历史。任务池、周计划和日计划展示的是同一任务；不能把它们各算为一个任务。

“迁移时保留进度”指保留未开始／进行中／暂停状态、已有执行区间和累计专注时间；本版不额外引入完成质量评分，也不要求用户填写主观任务进度百分比。

### BL-TASK-003 修改任务

1. **E1：** 用户提交任务修改，系统检查归属、必填信息、优先级、日期和当前状态。
2. **E2：** 未完成任务可调整规划信息；计时中不允许修改预计耗时，暂停或结束本次执行后可修改。
3. **E3：** 任务已完成时保留只读完成结果，不提供撤销完成或再次开始入口；需要新工作时创建新任务。
4. **E4：** 修改日期与已有计划冲突时提示处理，不静默移动已有计划，不改写真实执行日期。
5. **E5：** 保存成功后更新任务、计划及看板展示；修改失败保留原数据。

### BL-TASK-004 设置优先级与预计耗时

优先级为高、中、低；预计耗时可不填，填写时为有效正时长。预计耗时用于规划，实际专注时间可以超过预计耗时，系统不因此自动暂停或完成任务。修改优先级不改变手动排序；修改预计耗时不修改实际耗时。

### BL-TASK-005 判断任务截止日期逾期

仅当任务有最终截止日期、尚未完成且该日期已过时显示任务“截止日期已逾期”。无截止日期的任务不因日计划或周计划结束被赋予虚构截止日期。任务逾期不自动延期截止日期，仍可重新安排。

目标自动延期、日计划未完成、周计划未完成及任务截止日期逾期是分别判断的业务事件。

### BL-TASK-006 完成任务

**前置：** 任务属于本人、未完成、未归档，父目标和阶段允许推进，且处于当前可执行的计划范围。

1. **E1：** 用户主动选择完成；不要求必须先积累专注时间。
2. **E2：** 如任务存在未结束执行，先结束并保存必要时间；可用一次“结束并完成”操作顺序处理。
3. **E3：** 提醒“完成后不能恢复为未完成”，用户确认后保存完成状态和时间。
4. **E4：** 更新计划、看板、阶段和目标统计；达到全部任务完成条件时发起目标完成确认。
5. **E5：** 保留所有真实耗时；没有计时记录的完成任务实际耗时为 0，不使用预计耗时代填。

不记录任务完成质量；重复完成不生成多条完成记录。结束一次执行不能自动代替本流程。

### BL-TASK-007 删除任务

| 情况 | 删除结果 |
|---|---|
| 未发生执行，也没有完成事实 | 允许彻底删除任务及未执行的计划关联 |
| 已经开始过执行、已有实际时间或已经完成 | 从活跃范围移除，归档保留任务、实际记录及历史贡献 |
| 仍有未结束执行，包括暂停执行 | 先结束执行，不能直接删除或归档 |

1. **E1：** 用户发起删除，系统校验归属并判断上表情况。
2. **E2：** 显示实际结果是“删除”还是“移出并保留历史”，用户取消则不变更。
3. **E3：** 彻底删除时清除未执行安排；保留历史时撤出当前和未来有效计划，不删除真实记录。
4. **E4：** 将任务从当前有效任务范围移出，重算阶段和目标任务数量、进度及阶段完成条件；历史耗时和已发生完成贡献继续保留。
5. **E5：** 不因删除创建任务副本、补完成记录或计划延期事件。

**补充约定：** 因删除而归档保留的任务只保留历史身份，不进入当前目标进度、阶段待完成数量、任务池或有效计划，也不提供恢复删除入口。已有历史任务不能因此被补记完成；所属阶段的历史引用不阻塞其空阶段删除。删除导致剩余有效任务全部完成时，只触发目标完成确认，仍由用户决定是否结束；没有剩余有效任务时不触发。

### BL-TASK-008 重新安排未完成任务

**触发：** 用户主动改期，或从未完成计划的处理入口选择新的安排。

1. **E1：** 校验任务属于本人、尚未完成、未归档；新日期不能在过去。
2. **E2：** 若当前计时中，先暂停并保存当前执行区间；暂停中的执行和累计进度随任务保留。
3. **E3：** 用户选择今天、未来某日、仅某周不指定日期，或返回任务池。
4. **E4：** 同周改期只迁移日计划；跨周改期同时迁移周计划及日计划，目标周计划不存在时按唯一性规则创建。
5. **E5：** 同一操作中撤销原有效安排并建立新安排；原日期不保留“原计划未完成”“已改期”的独立条目。
6. **E6：** 执行记录保留真实时间；已经投入的时间不能整体改记到新日期。
7. **E7：** 返回任务池时取消全部有效计划；下次执行前须重新加入计划。

改期不创建任务副本，不改变任务完成状态或最终截止日期。历史页面本身不能编辑过去日计划；从当前任务或待处理列表迁移是本流程，迁移后历史安排查询不再列出被撤销的原条目。必要的内部操作追踪不作为额外计划历史展示。

### BL-TASK-009 暂停及恢复任务

1. **E1：** 用户暂停未完成任务；若正在计时，同时关闭当前专注区间，停止累计时间。
2. **E2：** 任务进入暂停状态；保留计划、已累计时间及尚未结束的本次执行。
3. **E3：** 用户恢复时，先校验当前日期及计划、目标和阶段是否允许执行。
4. **E4：** 如存在有效的暂停执行，继续该次执行；上一执行已经结束时新建一次执行，从 0 计时。
5. **E5：** 另一任务正在计时时，按任务切换规则先暂停另一任务。

任务暂停不会免除日计划或周计划到期时的未完成判断；计划过期时须先重新安排，才能恢复执行。已完成任务不能使用恢复入口撤销完成。

## 8. 周计划与日计划

### 8.1 安排与执行范围

```text
目标 → 阶段 → 任务池
                ↓ 用户选择
             某周周计划
                ├─ 不指定日期：本周找时间完成，可从周计划直接执行
                └─ 指定某日：进入该日日计划，在该日执行
```

1. 周计划固定为周一至周日；同一用户同一周最多一个周计划，与有多少个目标无关。
2. 日计划从该日所在周的周计划中选择任务；不能绕过周计划直接接收任务池任务。
3. **补充约定：** 同一用户同一日期最多一个日计划；没有安排时展示空计划，不强制生成空业务数据。
4. 同一任务只保留一个有效周计划归属；同时至多指定一个具体日期。改期使用迁移，不复制为多个日期的任务。
5. 不指定具体日期的任务，在对应周任一天均可执行，不要求为了计时而创建一个今日计划项。
6. 指定日期的任务，只有在该日可以开始、继续执行或完成；要提前或延后做，先由用户修改安排。
7. 今天和未来的计划可规划；未来任务不能提前计时。过去日计划和已结束周计划作为历史查看，不提供内容编辑。
8. 已完成结果保留在其完成时对应的计划中；不会因日历进入下一天而复制一份。

### BL-WEEK-001 创建及查看周计划

1. **E1：** 用户选择某一周，系统按本人业务时区确定周一及周日。
2. **E2：** 已有计划时打开同一计划；没有时显示空状态，允许为本周或未来周创建。
3. **E3：** 创建时再次检查唯一性；多次请求仍只有一个该周计划。
4. **E4：** 展示选入任务、日期安排、状态及有效耗时；过去周以只读结果展示。

### BL-WEEK-002 将任务加入或移出周计划

**加入：**

1. **E1：** 用户选择本周或未来周，从任务池选择本人未完成、未归档任务。
2. **E2：** 校验目标未完成、未主动归档；待开始目标只能预先安排与开始日期相容的未来范围。
3. **E3：** 检查是否已有其他有效周计划；已有时提示按迁移流程处理，不能再创建第二份有效安排。
4. **E4：** 加入所选周，默认不指定日期；不改变任务未开始状态。

**移出：** 用户将未完成任务移出周计划时，同时取消该周的有效日安排；正在计时则先暂停。任务及已发生执行保留，返回任务池，不形成延期事件。已完成结果不从历史计划中随意抹除。

### BL-WEEK-003 指定或取消具体日期

1. **E1：** 用户为周计划中的未完成任务选择该周内的今天或未来某日。
2. **E2：** 检查日期属于所选周，且不早于目标开始日期及已设置的任务开始日期。
3. **E3：** 原来没有日期时创建唯一日安排；原来已有日期时按 `BL-TASK-008` 迁移。
4. **E4：** 用户取消具体日期时，撤销原日安排，任务仍留在该周，可在本周其他时间执行。
5. **E5：** 设置失败不改变原安排；不能把另一周日期硬塞进当前周计划。

跨周日期调整调用完整迁移流程，先变更周归属，再确定日安排。

### BL-WEEK-004 更新周计划任务推进情况

任务开始、暂停、继续、结束、完成、移出或改期成功后，周计划展示同一任务的最新有效状态。结束一次执行仍显示未完成任务；任务完成才显示已完成结果。计划进度仅统计该计划实际关联的不同任务，不把该目标全部任务误算为本周任务。

### BL-WEEK-005 周周期结束与未完成处理

**触发：** 下周一当地零点。

1. **E1：** 查询周结束时仍在本周的任务，排除已完成、已主动移出和因目标归档退出的任务。
2. **E2：** 对其余任务生成一次本周未完成的待处理结果；无日期任务同样参加判断。
3. **E3：** 当前仍在计时的任务先暂停，保留进度；不能因为旧周已结束而继续无限执行。
4. **E4：** 用户可选择加入当前或未来周，或者返回任务池；系统不自动安排下一周。
5. **E5：** 迁移时撤销原有效安排，不为原周或原日期留一份重复任务；真实执行历史按实际日期保留。

同一周期不能重复生成待处理项。过去周已经结束，不允许在旧周直接继续执行。待处理任务不是另一份任务，也不属于当前可执行计划，须先完成重新安排。

### BL-WEEK-006 删除周计划

1. **E1：** 用户发起删除，系统检查该周及其日计划关联的未结束执行；存在则先要求结束。
2. **E2：** 展示影响：撤销该周尚未执行的安排，未完成任务回到任务池，不能级联删除任务。
3. **E3：** 无执行或完成事实的计划可删除；有执行或完成事实的部分归档保留，未执行的多余安排清除。
4. **E4：** 保留真实执行与历史统计；不因删除计划产生延期。
5. **E5：** 用户重新规划同一周时仍遵守周唯一性；有归档历史的周复用同一周的计划身份，不形成两份周计划。

### BL-DAY-001 创建及查看日计划

1. **E1：** 用户打开某日，系统定位该日所属周及本人周计划。
2. **E2：** 展示当天任务及顺序；无任务显示“暂无任务，可从周计划中安排”。
3. **E3：** 今天及未来允许规划；过去日期提供只读历史，不允许新增、调整顺序或修改当日完成结果。
4. **E4：** 通过当前任务入口迁移过去未完成安排时，只按迁移规则更新安排关系，不提供过去计划编辑表单。

### BL-DAY-002 将周计划任务加入日计划

用户选择该周尚未完成任务及具体日期，系统校验归属、周范围、目标及任务日期，再建立唯一日安排。已有其他日期时调用迁移，不重复安排。添加计划本身不创建执行或完成记录。

### BL-DAY-003 调整日计划顺序

用户调整今天或未来的任务顺序；系统检查所有任务都属于本人该日计划后保存。失败保留旧顺序。顺序与优先级分别管理；不能借排序移动到其他日期，也不能编辑过去顺序。

### BL-DAY-004 重新安排日计划任务

统一调用 `BL-TASK-008`；支持移至今天或未来日期、只保留在某周、返回任务池。未开始和已做一部分的任务都可迁移，计时中先暂停。跨周时同步移动周归属；原日期不保留独立迁移条目。

### BL-DAY-005 更新日计划状态

加入后未执行、计时中、暂停、结束本次但未完成、任务已完成分别展示。任务迁移后原日不再显示其计划项；真实执行历史仍可在实际发生日期查询。目标归档、任务归档或计划删除导致的撤出不冒充完成。

### BL-DAY-006 日周期结束与未完成处理

**触发：** 次日当地零点。

1. **E1：** 仅检查当日日计划中仍有效且未完成的任务；无日期周任务不参加日计划未完成判断。
2. **E2：** 排除已完成、已迁移、已移出和因归档撤出的任务。
3. **E3：** 形成唯一的当日未完成待处理项；指定日期的计时任务先暂停。
4. **E4：** 用户可迁移到今天或未来某日、保留为本周无日期任务，或返回任务池。
5. **E5：** 不自动推迟到次日，不自动创建任务副本；实际执行区间继续保留。

任务尚未处理而本周也结束时，转由周未完成处理统筹展示，避免同一任务同时出现多个待处理操作卡片。原周期的未完成事实可用于处理依据；迁移后不在原日期额外展示“未完成／已改期”副本。

### BL-DAY-007 删除日计划

沿用计划删除规则：先结束关联未结束执行；清除未执行安排；已经执行或完成的部分归档保留。删除日安排不删除任务，也不必移出其有效周计划；没有具体日期的任务仍可在该周完成。过去计划只允许按历史保留规则归档，不提供修改已发生事实的编辑能力。

## 9. 任务执行与专注时间

### 9.1 计时的统一含义

1. 专注计时从 `00:00:00` 开始正向累计，不能用预计耗时做倒计时。
2. 本次执行可包含多个实际专注区间；暂停时间不计入。
3. 暂停后继续同一次执行，显示此前累计值并继续增加；结束后再开始是新一次执行，新一次从 0 开始。
4. 任务累计时间等于各次有效专注区间之和；界面分别展示“本次专注”和“任务累计”。
5. 多个任务可以保留暂停中的执行，但同一账户同一时刻只有一个计时区间；限制覆盖多个页面、设备和会话。
6. **补充约定：** 任务已设置开始日期时，不可早于该日执行；最终截止日期已过不禁止重新安排，但仍显示任务逾期事实。

### BL-FOCUS-001 开始任务执行

**前置：** 本人未完成、未归档任务；目标已开始且未完成、未主动归档；阶段未暂停、未完成；任务在当前可执行计划范围。

1. **E1：** 用户从当前周无日期任务、今日日计划、看板或符合相同条件的任务详情发起开始。
2. **E2：** 检查有效计划：无日期任务须属于本周；有日期任务须安排在今天；只有任务池或未来计划的任务拒绝开始。
3. **E3：** 检查任务是否已有暂停的未结束执行；存在则转继续执行，不重复创建。
4. **E4：** 若另一任务正在计时，在同一切换时刻先关闭其当前区间并暂停，再开始本任务。
5. **E5：** 创建本次执行和第一个区间，记录真实开始时刻，从 0 计时；任务首次开始时进入进行中。
6. **E6：** 刷新两项任务、计划及看板。切换保存失败时保留操作前有效状态，不能出现两个同时计时任务。

### BL-FOCUS-002 暂停、继续及结束本次执行

**暂停：** 关闭当前专注区间，保存区间结束时刻及有效耗时，本次执行仍未结束。

**继续：** 重新校验计划和父对象状态，暂停其他正在计时的任务，为本次执行追加新专注区间；不把暂停间隔计入。

**结束：**

1. **E1：** 用户选择结束当前或某个暂停中的执行。
2. **E2：** 计时中则关闭当前区间；已暂停则直接使用已保存区间，不能把暂停至点击结束之间的时间算入。
3. **E3：** 记录本次执行结束时间，并确认所有专注区间时间有效。
4. **E4：** 汇总区间，标记本次执行已结束，更新任务、阶段、目标及每日投入。
5. **E5：** 保留任务未完成状态；用户另选择完成任务时才进入完成流程。

重复暂停、继续或结束不重复增时；时间不能为负；保存失败不能提示已成功结束。

### BL-FOCUS-003 继续执行未完成任务

任务仍有暂停中的本次执行时，继续原执行；本次已经结束时，再执行会新建一次记录。无论哪种情况，都必须先符合当前计划范围。改期不删除已有执行，也不把历史累计时间当作新一次计时起点。

### BL-FOCUS-004 计算实际耗时与跨日汇总

```text
单个专注区间耗时 = 区间结束时刻 - 区间开始时刻
本次执行耗时 = 本次所有有效专注区间耗时之和
任务累计耗时 = 该任务所有有效专注区间耗时之和
阶段／目标累计耗时 = 各自所属任务的有效区间耗时之和
```

例如：10:00–10:20 专注，10:20–10:30 暂停，10:30–10:45 继续。本次实际专注为 35 分钟，不能按开始到结束算成 45 分钟。

1. 已保存的暂停区间即为确定耗时，不必等整次执行结束才显示。
2. 当前仍在进行的区间可展示实时值；历史统计必须区分实时值与已确认结果，不能在结束后重复累加。
3. 本周无日期任务跨午夜持续执行时，可继续同一次执行；投入按午夜拆分，次日计入次日。
4. 指定日期任务到该日结束、无日期任务到所属周结束时自动暂停，重新安排后才能继续。
5. 预计耗时、暂停时间和无法确认的离线时间都不直接计入实际专注时间。
6. 任务迁移、归档或删除保留历史时，不改变区间真实发生日期，也不减少已发生的时间贡献。

### BL-FOCUS-005 异常中断、补录结束时间及任务切换

**异常中断触发：** 进程被关闭、浏览器崩溃、断网、设备休眠、会话被撤销，或执行连接丢失。

1. **E1：** 系统检测到执行连接中断后，关闭可确认的最后专注区间，将本次执行置为暂停。
2. **E2：** **补充约定：** 暂停时刻取最后可确认仍在执行的时刻，不取数小时后重新登录的时刻，也不凭空推断整个离线期间都在专注。
3. **E3：** 再次进入系统时展示暂停及已保存的累计值，允许继续、结束或补齐已有记录的结束时间。
4. **E4：** 不把异常中断当作任务完成，不自动注销或删除已有时间贡献。

**补录或修正已有结束时间：**

1. 用户可以为异常中断、遗漏结束的既有执行补录真实结束时间；不通过此入口创建完全不存在的过去执行。
2. 时间不得早于相关区间开始，不得晚于当前时刻；涉及恢复或其他任务执行时不得形成重叠区间。
3. 自动暂停截断得过早而用户能确认真实结束时刻时，可以修正末段结束；不能覆盖随后已经确认的其他任务时间或指定日期／周期限制。
4. 主动暂停至主动恢复之间仍是暂停，不能因填写较晚的执行结束时间整体变成专注。
5. 修正时保存原值、新值及修正时间，重新计算实际发生日期的投入，只做差量结果更新，不重复累加。
6. 已经正常结束且时间完整的历史记录，不开放任意批量回填；本入口仅处理既有中断记录的时间完整性。

**正常退出与强制退出的边界：** 系统内退出入口必须先结束所有未结束执行；操作系统强制结束进程无法保证被页面阻止，必须通过自动暂停及恢复处理兜底。浏览器的关闭前事件并不可靠，参见 [MDN：beforeunload 的使用限制](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event#usage_notes)。

**任务切换：** 自动暂停当前任务，然后开始或恢复新任务；切换不要求把旧任务标为完成。多设备同时开始时，也必须以同一账户仅一个有效计时任务为准。

## 10. 习惯管理

### 10.1 基础规则

1. 习惯独立于目标任务，不作为任务加入周计划或日计划；在今日看板以独立清单展示。
2. 周期严格只有“每天”及“每周指定星期”；每周至少选择一个星期，不提供每隔若干天、每月或自定义复杂周期。
3. 用户通过勾选完成当天应执行习惯；不记录质量分数，不要求专注计时。
4. 不允许提前勾选未来日期，也不允许补记过去日期；历史只读。
5. 执行时间为可选描述；填写该时间不自动引入习惯定时提醒功能。

### BL-HABIT-001 创建习惯

1. **E1：** 用户输入名称、类别、具体完成条件和周期；描述、执行时间可选。
2. **E2：** 校验必填信息；类别限睡眠与作息、饮食与饮水、运动与身体健康、学习与认知成长、生活秩序与自我管理、心理与情绪健康、人际关系、其他。
3. **E3：** 校验每天或每周指定星期；非法周期、未选星期、无效时间拒绝保存。
4. **E4：** 创建启用习惯及首段规则；创建当天按新规则判断是否需要执行，不追记创建前的未完成。
5. **E5：** 更新习惯列表和今日清单；失败不生成半成品习惯。

### BL-HABIT-002 查看及筛选习惯

按启用清单、暂停队列和归档范围展示本人习惯，支持类别和状态筛选。当天应执行的启用习惯显示完成勾选；非执行日仍可在完整习惯列表查看，但不作为今日待完成项。无记录展示空状态，加载失败单独提示。

### BL-HABIT-003 修改习惯及规则时间线

**需求基线：** 新规则从修改当天生效，旧规则按时间顺序展示节点。

1. **E1：** 用户修改名称、类别、条件、周期或执行时间，系统按创建时相同口径校验。
2. **E2：** 影响执行判断的修改成功时，记录旧规则结束节点和新规则生效节点，立即刷新今天尚未完成的应执行判断。
3. **E3：** 修改前日期仍按当时规则解释，不把所有历史日期套用新周期。
4. **E4：** **补充约定：** 当天已经勾选完成的记录保留其完成事实和当时条件；修改后不要求重复完成，也不把原完成记录改成未完成。
5. **E5：** 当天尚未完成，新周期包含今天则进入待完成；不包含今天则移出今日待完成，不制造一次未完成。
6. **E6：** 同一天多次修改保留先后时间节点；午夜结算时，未完成项按当天最后生效的规则与状态判断。

**时间线展示示例：**

```text
10-01 09:00  创建：每天，完成条件为阅读 20 分钟
10-17 14:00  修改：每周一、三、五，完成条件为阅读 30 分钟
10-20 08:00  暂停：暂停期间不触发应执行
10-23 08:00  恢复：重新按当前规则进入清单
```

界面展示日期、节点动作、变更前后内容及生效区间，不要求用户理解内部版本号。未改变规则的普通保存不生成虚假变更节点。

### BL-HABIT-004 暂停、恢复、结束及恢复已结束习惯

| 操作 | 校验及结果 |
|---|---|
| 暂停 | 启用习惯进入暂停队列；今日未完成项不再触发；暂停前已完成事实保留 |
| 恢复暂停 | 同一习惯回到启用清单；今天是否应做按当前规则判断；暂停期间不补算未完成 |
| 结束 | 用户确认后记录结束节点并自动归档；结束后不触发，原历史保留 |
| 恢复已结束 | 从归档中恢复同一习惯，开启新的有效区间；结束期间不补算未完成 |

所有操作记录实际发生时间，重复操作不重复生成贡献。结束与暂停不会删除过去完成；恢复不会自动补记空档日期。

### BL-HABIT-005 勾选当天完成

1. **E1：** 用户从习惯列表或今日清单勾选完成。
2. **E2：** 校验归属、当前启用状态、当地日期为今天，以及今天属于当前应执行周期。
3. **E3：** 检查今天是否已有完成记录；已有则保持已完成，不重复增加次数。
4. **E4：** 保存完成时间、日期及当时规则依据，更新清单和历史。
5. **E5：** 暂停、结束、删除、非执行日及过去／未来日期提交均拒绝。

本版不新增任意撤销历史完成或过去日期补记入口。

### BL-HABIT-006 计算每日状态

| 指定日期的情况 | 展示及统计 |
|---|---|
| 已有真实完成记录 | 已完成；即使之后修改规则、暂停或结束也保留该贡献 |
| 今天应执行、启用且未完成 | 待完成 |
| 已结束日期，当时应执行且未完成 | 未完成 |
| 非执行日、未创建、暂停或结束期间 | 不要求执行，不算未完成 |
| 今天修改后不再应执行且没有完成 | 非执行日，不制造未完成 |

**补充约定：** 当天在结束前被暂停或结束且尚未完成时，不再计为当天未完成；此前已经结束的日期不被今天的操作反向豁免。

#### 习惯完成率的唯一计算口径

每个习惯的每个当地日期最多形成一项日结果，按下列优先级决定是否进入统计：

1. **已有有效完成记录：** 该日完成数为 1、应执行数为 1；之后暂停、结束、删除或修改周期均不撤销这一结果。
2. **没有完成记录且日期已经结束：** 采用该日结束边界前最后有效的周期及状态结算。应执行且启用则完成数为 0、应执行数为 1；否则两者均为 0。结算结果随后只读。
3. **没有完成记录且日期尚未结束：** 按当天当前有效规则及状态判断；应执行则分母暂计 1，非执行、暂停、结束或已删除则暂计 0。界面标明“含今日进行中数据”，到日结束再固定结果。
4. **范围汇总：** 完成率等于上述完成数之和除以应执行数之和；分母为 0 显示“无应执行记录”。同一习惯同一日期不因多次状态变化重复计数。

| 发生情形 | 当日完成数／应执行数 | 历史处理 |
|---|---|---|
| 今天完成后暂停、结束或删除 | 1／1 | 完成事实及统计均保留 |
| 今天完成后修改周期，新周期不含今天 | 1／1 | 保留当时有效完成，不要求重做 |
| 今天未完成即暂停、结束或删除 | 0／0 | 当天不再形成未完成；此前已结束日期不变 |
| 今天启用且应执行，到日结束仍未完成 | 0／1 | 结算为未完成，之后不可补记 |
| 过去应执行但未完成，今天删除习惯 | 过去仍为 0／1 | 今天操作不反向取消历史应执行日 |

该顺序保证完成数不大于应执行数，也不会出现存在有效完成记录却显示“无应执行记录”的结果。

### BL-HABIT-007 查看历史与规则节点

用户按日期范围查看完成、未完成及非执行状态，并查看创建、规则变更、暂停、恢复、结束及删除节点。旧规则对应的日期按旧规则解释，不开放补记编辑。没有历史显示空状态，不强迫用户逐日回看。

### BL-HABIT-008 删除习惯

1. **E1：** 用户可从启用、暂停或归档范围删除习惯，系统展示“将从列表移除，历史贡献保留”。
2. **E2：** 用户确认后，习惯从清单、暂停队列和可恢复归档对象列表中消失，不再触发。
3. **E3：** 保留已经发生的完成记录、规则节点和删除摘要，只能从历史查询，不提供恢复删除入口。
4. **E4：** 没有历史贡献的多余习惯可直接移除；不因删除回写过去的完成或未完成。

“删除后消失”指不再作为可管理习惯出现；“保留历史”指已经发生的贡献仍可查，两者使用不同入口。

## 11. 今日看板、历史与统计

### BL-DASH-001 汇总今日内容

1. **E1：** 用户进入看板，系统确认本人业务日期，并补做目标开始、延期及计划周期结束检查。
2. **E2：** 展示今日有具体日期的任务，以及独立的“本周未指定日期”任务清单；后者可以直接执行，不伪装成已加入今日日计划。
3. **E3：** 展示唯一计时任务及暂停中的任务，显示本次专注与任务累计时间。
4. **E4：** 展示今天应执行习惯，支持勾选完成；暂停习惯可从暂停队列管理。
5. **E5：** 展示已经开始、未完成、未主动归档的目标概览；待开始目标到期后自动进入队列。
6. **E6：** 独立展示待处理计划和目标完成确认通知。

没有任务时展示无任务状态，并提供规划入口；不能用“加载失败”代替无任务，也不能用无任务遮住仍可完成的习惯。

### BL-DASH-002 筛选任务

用户按目标或状态筛选今日任务及本周无日期任务，系统只筛选本人当前有效范围，不改变任务状态、安排或时间。筛选无结果时显示“暂无符合条件的任务”。

### BL-DASH-003 从看板重新安排

调用统一迁移流程：先暂停计时、迁移周及日归属、保留真实执行、原日期不留重复条目。用户取消或保存失败时保持原有效安排。

### BL-HISTORY-001 按时间范围查询历史

用户可选择今天、昨天、本周、本月或自定义范围。系统校验起始不晚于结束，按该记录所属日期及业务时间规则展示本人数据。空结果与查询失败分开；不能因当前对象已归档就查不到它的历史贡献。

### BL-HISTORY-002 查看目标、阶段、任务与计划历史

1. 目标历史展示开始、手动改期、自动延期、主动结束、归档、恢复和重新打开节点，以及结束时统计快照。
2. 阶段历史展示原归属、完成及重新打开节点；归档任务仍可追溯原阶段。
3. 任务历史展示真实执行区间、暂停、继续、结束、完成和归档结果；不显示完成质量。
4. 过去计划只读；用户迁移后撤销的原安排不再作为独立原日任务条目展示。
5. 过去日期实际发生过的专注时间仍归属过去日期，即使当前任务已经迁移到未来。
6. 删除有历史的计划时，可从历史查看已归档执行部分；未执行的多余内容不会被制造成历史贡献。

### BL-HISTORY-003 查看习惯历史

展示对应日期状态、完成记录及规则时间线；暂停、结束及非执行日不计为未完成。已删除习惯以历史摘要展示，不能从历史入口恢复或补记。

### BL-HISTORY-004 统计完成情况及真实投入

| 指标 | 统计口径 |
|---|---|
| 当前目标任务进度 | 当前有效任务的 `C / N`；用户已删除、仅保留历史的任务不参与，按第 5 章定义 |
| 日期范围任务完成数 | 在范围内实际完成的不同任务数；删除或归档保留的已完成任务继续贡献 |
| 日期范围投入时间 | 有效专注区间按实际发生日期分配后的时间之和 |
| 阶段、目标累计投入 | 包括已归档保留任务的实际时间，不因计划移动而变化 |
| 习惯完成次数 | 范围内真实完成记录数；删除、结束或暂停不抹除已有贡献 |
| 习惯完成比例 | 按 BL-HABIT-006 的日结果汇总；已有完成记录的日期必定同时进入分子、分母，其余日期按当日有效规则及状态判断；分母为 0 显示无应执行记录 |

同一任务、专注区间和习惯当日完成只统计一次；预计时间不参与实际投入求和。当前目标进度与历史完成贡献可不同，不能用当前任务数量回算全部历史快照。

### BL-HISTORY-005 删除对象后的历史访问

| 对象及条件 | 当前管理范围 | 历史与贡献 |
|---|---|---|
| 目标 | 不能删除；只能结束或归档 | 全部保留 |
| 当前有效任务为空的阶段 | 可以移出当前列表；有历史时保留历史身份 | 必要历史节点及原归属保留；不能带走任务历史 |
| 从未执行也未完成的任务 | 彻底删除 | 不产生执行贡献；清除未执行安排 |
| 已执行或已完成后被删除的任务 | 退出当前任务范围，仅归档保留历史身份 | 原状态、真实耗时、完成贡献及归属保留，不阻塞阶段完成或空阶段删除 |
| 无执行事实的计划 | 可以删除 | 不制造历史贡献；任务本身保留 |
| 有执行事实的计划 | 已执行部分归档，未执行安排清除 | 执行及完成贡献继续保留 |
| 已删除习惯 | 从可管理列表消失 | 原完成记录、规则及删除摘要保留 |

历史访问仍需校验本人归属；归档不允许绕过归属权限。

## 12. 管理员与超级管理员

### 12.1 固定角色权限

| 能力 | 普通用户 | 管理员 | 超级管理员 |
|---|---|---|---|
| 管理自己的目标、计划及习惯 | 允许 | 如使用个人功能，仍仅本人 | 如使用个人功能，仍仅本人 |
| 查看用户数量及普通用户账户列表 | 不允许 | 允许 | 允许 |
| 新增、查询、修改、删除普通用户账户 | 不允许 | 允许 | 允许 |
| 新增、查询、修改、删除管理员账户 | 不允许 | 不允许 | 允许 |
| 修改账户角色 | 不允许 | 不允许 | 仅在普通用户与管理员范围内允许 |
| 查看及修改系统配置 | 不允许 | 不允许 | 允许 |
| 查看密码原文／哈希或代替用户执行任务 | 不允许 | 不允许 | 不允许 |

本版采用少量固定角色，不引入复杂自定义权限体系。超级管理员不通过公开注册产生；普通管理员不能将自己提升为超级管理员。

### BL-ADMIN-001 查看用户数量及账户

1. **E1：** 管理员打开后台，系统校验其管理角色。
2. **E2：** 管理员只查询普通用户；超级管理员可查询普通用户及管理员。
3. **E3：** 展示用户名、昵称、角色、账户状态和账户数量，不返回密码材料或个人成长内容。
4. **E4：** **补充约定：** 普通用户数量、管理员数量及已删除数量分别显示；默认用户数为未删除的普通用户，包含被禁用账户，避免把禁用误认为已不存在。

### BL-ADMIN-002 新增、修改及删除账户

1. **E1：** 检查操作者是否有权管理目标账户；管理员不能修改或删除同级管理员、超级管理员。
2. **E2：** 新增账户沿用用户名、昵称和初始密码规则；编辑可修改用户名、昵称、账户状态，超级管理员还可调整允许范围内的角色。
3. **E3：** 用户名修改继续满足全系统唯一；所有后台写操作记录操作者及发生时间。
4. **E4：** **补充约定：** 删除账户采用停用登录及逻辑删除，保留其已发生业务历史；不级联物理删除任务和执行数据。被删除账户不能继续登录。
5. **E5：** 禁用、删除或撤销会话时，先保存当前可确认专注区间并暂停执行，再使会话失效；不等待被管理用户主动退出。
6. **E6：** 不允许删除、禁用或降权至系统不存在可用超级管理员的结果；不提供任意创建超级管理员入口。

普通用户没有后台管理入口。后台修改信息不会让管理员取得其他用户的个人执行会话。

### BL-ADMIN-003 管理系统配置

**本版配置清单为补充约定，仅包含以下两项：**

| 配置编号 | 配置名称 | 默认值 | 输入规则 | 生效及影响 |
|---|---|---|---|---|
| CFG-001 | 站点显示名称 | Asterway | 1–30 个可见字符，不能全为空白 | 保存后用于后续页面展示，不改写历史对象名称 |
| CFG-002 | 是否开放注册 | 开放 | 仅开放／关闭 | 关闭后拒绝新的公开注册；不影响已有账户登录及管理员按权限新增账户 |

1. **E1：** 超级管理员进入配置页，系统校验角色并展示当前值及默认值；普通用户和管理员无权读取或修改后台配置。
2. **E2：** 提交时校验配置项在上表范围内、值符合规则；不允许自行添加配置键、删除配置项或提交未知项目。
3. **E3：** 保存配置及操作者、实际生效时间、变更前后值；失败保留原值。
4. **E4：** 新值保存成功即生效；已打开但尚未完成提交的注册，也须在创建账户前检查最新开放状态。用户取消或注册被关闭时不创建半成品账户。
5. **E5：** 刷新配置页及相关展示；重复提交相同值按无实际变更处理。

目标延期系数、密码长度、用户名唯一性、周一至周日、习惯周期、单任务计时、历史保留及账户角色边界均为本版固定规则，不出现在系统配置表单中；调整这些规则须通过需求变更及影响评估。

## 13. 系统通知

### BL-NOTICE-001 目标完成确认通知

1. **触发：** 进行中目标满足 `N > 0 且 C = N`，系统自动创建本人可见的站内通知。
2. **内容：** 指明目标名称、任务已全部完成，并提供“确认结束目标”“继续推进”。
3. **确认：** 重新校验条件和未结束执行，再记录正式结束；仅阅读通知不等于确认。
4. **去重：** 同一目标同一轮满足条件只发一次；任务比例先下降再重新达到全部完成时，可以产生新一轮确认。
5. **失效：** 目标已结束、已归档或任务条件变化时，旧通知不再直接执行过期动作。
6. **送达：** **补充约定：** MVP 使用站内通知，支持未读标记；用户离线期间保留，登录后可见。不增加用户私信、短信或邮件能力。

通知创建或展示暂时失败，不回滚已经成功的任务完成；补偿重试须去重。通知不能因每次页面刷新重复发送。

## 14. 跨模块联动与事件顺序

| 触发事件 | 必须依次生效的结果 |
|---|---|
| 到达目标开始日期 | 检查非主动归档及未完成 → 目标进入进行中 → 显示目标队列；不自动安排任务 |
| 任务开始或切换 | 校验当前计划 → 暂停原计时任务 → 开始新计时 → 更新两个任务及看板 |
| 暂停、结束或修正时间 | 保存有效区间 → 计算实际耗时 → 汇总任务、阶段、目标及日期统计 |
| 完成任务 | 结束未结束执行 → 确认不可恢复 → 保存完成 → 更新进度 → 必要时通知确认目标 |
| 任务迁移 | 必要时暂停 → 校验目标周日 → 原安排撤销与新安排建立同时生效 → 保留真实进度 |
| 目标归档 | 拒绝尚有未结束执行 → 用户确认 → 记录主动归档 → 撤出有效安排 → 保留历史 |
| 主动结束目标 | 结束执行 → 用户确认 → 保存结束状态及快照 → 撤出未完成任务安排；不补完成任务 |
| 删除任务或计划 | 检查执行已结束 → 区分未执行和已有历史 → 清除多余安排／归档真实部分 → 更新统计 |
| 修改习惯规则 | 校验 → 保存生效节点 → 立即重算今天未完成项 → 保留过去记录 → 刷新清单 |
| 习惯勾选完成 | 校验今天应执行 → 保存唯一完成记录 → 刷新清单及历史；不改变目标进度 |
| 计划周期结束 | 按周期边界检查有效安排 → 暂停超出范围执行 → 汇总待处理 → 等待用户迁移 |

### BL-COMMON-001 任务状态变化后的联动

任务创建、修改、暂停、恢复、完成或归档成功后，任务详情、任务池、所属周日计划和看板必须查询同一有效结果。只有任务数量或完成情况变化才重算进度；不因多个页面展示同一任务而重复计数。

### BL-COMMON-002 执行记录变化后的时间联动

开始、暂停、继续、结束或补齐时间后，按专注区间更新任务、阶段、目标和实际发生日期的统计。不修改预计耗时，不因执行结束自动完成任务。时间修正必须替换原贡献，不能在原贡献上再累加整段时间。

### BL-COMMON-003 习惯状态变化后的联动

创建、改规则、暂停、恢复、结束、删除及当日完成，均更新习惯列表、今日清单和相关历史。过去完成事实保留；非执行日及暂停、结束区间不算未完成；不联动改变任务或目标进度。

### BL-COMMON-004 计划变化后的联动

计划加入、移出、迁移、删除以及目标归档后，重新校验日计划必须属于同一周计划，且任务有效归属唯一。迁移撤销旧安排并保留真实执行；目标恢复后未完成任务回任务池，不自动重建旧安排。

### BL-COMMON-005 日计划与周计划的统一未完成处理

日结束仅检查该日具体日期任务；周结束检查该周全部未完成任务。系统产生待处理结果，由用户决定新安排，不自动决定新日期，不创建任务副本。已经完成、主动移出、迁移或归档撤出的任务不参加原安排的周期检查。

日计划和周计划在周日结束时使用同一个当地边界时刻；按边界前最后有效安排进行判断。同一任务的待处理入口合并，日、周事实不能各创建一份可执行任务。目标或任务在边界前已归档、移出或完成时，不再生成该安排的未完成待处理项。
